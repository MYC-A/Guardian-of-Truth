Работай с проектом Guardian-of-Truth.

## 1. Доступ к удалённому GPU-серверу

У тебя есть SSH-доступ к ModelScope через настроенный на моём компьютере алиас:

`guardian-modelscope`

Сначала самостоятельно проверь подключение:

```bash
ssh guardian-modelscope "hostname && nvidia-smi"
```

На удалённом сервере установлена NVIDIA A10 с 22 ГБ доступной VRAM.

SSH-туннель через VPS уже настроен и работает. Не изменяй его конфигурацию, SSH-ключи и сетевые настройки.

## 5. Запусти проверки

Самостоятельно настрой переменные окружения для Hugging Face cache.

Проверь наличие `MISTRAL_API_KEY`, не выводя и не сохраняя значение ключа в логах.

Если ключ отсутствует, сообщи об этом и продолжи проверки, не требующие Mistral.

Последовательно выполни:

1. Проверку импорта необходимых библиотек и CUDA.
2. Unit tests Semantic Pipeline V1.
3. Dry-run на одном случае.
4. При успешном прохождении предыдущих проверок — настоящий A5 smoke-test на одном случае.

Для настоящего запуска используй уже скачанные локальные модели, включив `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`.

Сохраняй результаты и логи в `/mnt/data/guardian/results`.

Если smoke-test выявит ошибку в коде, исследуй её причину, внеси минимальное необходимое исправление и повтори соответствующую проверку.

Не скрывай неуспешные проверки и не выдавай частичный запуск за полноценный успех.

**Не запускай полный benchmark и массовые платные запросы Mistral без моего отдельного разрешения.**

## 6. Проверь результаты

После smoke-test самостоятельно прочитай сформированные артефакты:

* `component_status.json`

Не считай `UNRESOLVED` технической ошибкой без анализа причины: это может быть корректный результат консервативного решателя.

### Mistral API на ModelScope

На удалённом сервере ModelScope уже настроен Mistral API.

Ключ и название модели находятся в защищённом файле:

`/mnt/data/guardian/secrets/mistral.env`

Используемая модель: `ministral-14b-latest`.

**Перед запуском Guardian**

Загружай переменные окружения в том же удалённом Bash-процессе, в котором будет выполняться Guardian:

```bash
source /mnt/data/guardian/secrets/mistral.env
```

При выполнении команд через SSH учитывай, что каждая новая SSH-сессия создаёт отдельное окружение и не наследует переменные предыдущих сессий.

Для запуска через локальный Codex используй следующую схему:

```bash
ssh guardian-modelscope 'bash -c "
  source /mnt/data/guardian/secrets/mistral.env
  cd /mnt/data/guardian/Guardian-of-Truth
  /mnt/data/guardian/venv/bin/python scripts/run_semantic_pipeline_v1.py ...
"'
```

**Проверка конфигурации**

Перед запуском убедись, что:

* файл `mistral.env` существует;
* переменная `MISTRAL_API_KEY` непустая;
* `MISTRAL_MODEL` соответствует `ministral-14b-latest`;
* Guardian действительно использует указанную модель, а не жёстко заданную модель по умолчанию.

Если CLI или `SemanticPipelineConfig` не подхватывает `MISTRAL_MODEL` автоматически, передавай название модели через предусмотренный конфигурационный параметр. При необходимости исправь чтение переменной в коде.

Не изменяй саму модель без согласования.

**Безопасность**

Не запрашивай API-ключ повторно, если файл существует и переменная успешно загружается.

Не выводи значение ключа в терминал, логи, отчёты, артефакты или ответы. Не добавляй файл с ключом в Git и не копируй его на локальный компьютер.

Не передавай ключ непосредственно в аргументах командной строки.

Не изменяй настройки SSH-туннеля и существующие Python-окружения.

**Использование API**

Mistral API уже настроен пользователем. Не выполняй дополнительные тестовые API-запросы без необходимости.

При первом реальном A5 smoke-test используй сохранённый ключ и модель `ministral-14b-latest`.

Не запускай полный benchmark и массовые API-запросы без отдельного разрешения пользователя.
