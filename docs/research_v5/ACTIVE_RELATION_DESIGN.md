# Implemented relation boundary

The active diagnostic uses `process_grounding.py`, `native_role_grounding.py` and
`paired_pilot.py`. The earlier `contracts.py`, `atomic_relations.py` and
`compile_relations.py` remain the **untested pre-steering atomic prototype** saved
at `cef9d89`; they were not used for a model prediction, oracle result or adoption
claim. They are preserved rather than deleted or silently relabeled as validated.

## Code-owned structure

The original SourceStore retains every prompt/response character. EvidenceGraph
owns native target IDs, event roles/positions, policy windows and declaration IDs.
Code enumerates scalar field IDs and declared argument IDs, builds RFC6901 pointers
and relation hashes, and compiles finite OR-of-AND constraints into the existing
three-valued requirement evaluator. Models never emit recursive Formula children,
witness paths, JSON pointers or local relation IDs.

Both model arms receive the same full originals and address index. Index entries
omit redundant quotations/scalar values; those values remain in originals and
are read by code. Selecting a valid source ID proves provenance only. Semantic
norm scope, relevance, modality and role/alias selection are hypotheses.

## Separate absence contracts

Process queries select a prerequisite declaration, attempt or qualified Boolean
result mode, target-to-call/result joins, and scoped exemption opinion. Code
searches only events before the regulated native target. It validates assistant
actor, typed identities, record lineage and original unique receipts. A recorded
attempt is not success; a Boolean must be actually Boolean. AND/OR keeps the
provided grouping. All success/outcome conditions must be supplied explicitly;
the code does not infer operational success or business authority from a name.

A missing bound successful check is FALSE **only** for an explicitly complete
recorded mandatory process. Under an incomplete log it is UNKNOWN. Neither says
the world-state authorization or safety is false. Ambiguous receipts, multiple
checks needing revocation scope and unsupported effects/state stay UNKNOWN.
Satisfied process rules alone do not certify whole-move NO_ERROR.

## Positive evidence and role validity

A native role query supplies a current target field, read-declaration argument,
result identity field and fact field. The research view verifies unique receipts
in the original unfiltered stream first. Only an explicit differing call-argument
identity on such a receipt may be excluded from that entity's validity stream.
This prevents a bill receipt from shadowing a line receipt from a polymorphic tool.
It never rescues ambiguous parallel calls, discards later same-entity observations,
changes originals or disables the source-integrity signature.

The active native state operator supports an ISO calendar date before an explicit
system date, with REQUIRE/FORBID/PERMIT and scoped exemption uncertainty. Positive
source evidence works without closed-world absence. Other arithmetic, prose
credentials, missing world state and future immutable observations are not silently
coerced into this operator. This is a narrow tested mechanism, not a general solver.

## Observed unresolved boundary

The model still selects target/field/argument candidates. Validated free strings
allow wrong namespaces to reach admission, where they become UNKNOWN. The pilot
used business/user IDs and reversed field roles; it also omitted a prohibition.
Code-owned trees/paths therefore removed one technical failure class but did not
solve addressing or normative interpretation. No automatic field repair was added.
Future per-target code binding or constrained candidate selectors would be a new
pre-sealed version, and must still be checked for semantic mistakes.
