# Как передать решение организаторам

Код и результаты опубликованы отдельно от весов:
https://github.com/MYC-A/Guardian-of-Truth/tree/submission/qwen-offline-20261008

Ветка GitHub нужна для воспроизводимости. Она не заменяет архив решения:
по проверенным условиям Guardian модельные веса должны лежать внутри загружаемого
ZIP. В репозитории веса и ZIP не коммитятся.

## Артефакт

**Готовый проверенный архив, 2026-10-09:**

```text
A:\Guardian-submissions\guardian-qwen-b2-rebuilt.zip
bytes: 30395847624 (30.395847624 GB)
SHA256: 912fd1cd11121797efa433d459e67907c041b6200ea420d82d2b4a5418b27311
receipt: A:\Guardian-submissions\guardian-qwen-b2-rebuilt.verification.json
```

Это полный ZIP с кодом, настоящими весами и Linux runtime. Все member CRC/hashes,
известный GGUF SHA, manifest inventory, root layout, Unix permissions и native ELF
проверены;4669 vendor files совпали с официальными pinned wheel bytes.
Status: `READY_VERIFIED_PACKAGING`. Именно этот файл загружать в форму решения.
GPU inference новой сборки и hidden30min limit остаются непроверенными.
Receipt также опубликован в `receipts/final_packaging_20261009.json`.

Ниже — история восстановления; её старый server ZIP SHA не относится к готовому
архиву выше.

Исторически на сервере был собран полный архив:

```text
/dev/shm/guardian-qwen-b2-20261008.zip
bytes: 30447402247
SHA256: 46317b9570c76833771f14468e045e642f9802c7b516fba8234fefa23a493835
```

Это30.447402247GB по десятичной шкале, меньше лимита40GB. Сейчас сервер остановлен;
его не запускаем для проверки этого документа. Stop сохраняет постоянный диск с
проверенным stage, но ZIP в `/dev/shm` хранится в RAM и после остановки не считается
сохранённым. При последующем запуске архив потребуется заново построить из stage
и проверить по SHA256. Delete инстанса или диска — другое действие; сохранность
при Delete этим планом не обещается. Выгрузка runtime отложена по указанию пользователя.

Путь завершения без сервера выполнен — `RUNTIME_REBUILD.md`: Linux CUDA SM80 runtime
собран в GitHub Actions, точные прежние веса получены из pinned публичного
источника. Helper соединил их на дискеA и проверил новый ZIP. Исторический
SHA выше **не является SHA новой сборки**.

Локальная цель нового артефакта:

```text
A:\Guardian-submissions\guardian-qwen-b2-rebuilt.zip
A:\Guardian-submissions\guardian-qwen-b2-rebuilt.verification.json
```

Файл с окончанием `.partial` не готов. Для новой сборки
`VERIFIED_OFFLINE_PACKAGING` в receipt означает проверку известного размера/SHA
исходной модели, полного ZIP SHA, каждого файла по manifest/CRC, Unix permissions,
корневой структуры, ELF и отсутствия host driver/известных secret paths.
Наличие заранее выделенных30GB само по себе не доказывает скачивание.
Перед загрузкой проверяется именно окончательный файл:

```powershell
python -X utf8 scripts/verify_qwen_submission.py `
  --archive A:\Guardian-submissions\guardian-qwen-b2-rebuilt.zip `
  --receipt A:\Guardian-submissions\guardian-qwen-b2-rebuilt.verification.json
```

На 2026-10-09 **веса** полностью проверены: файл браузера
`A:/GIS_Загрузки/Не подтвержден 625998.crdownload` имеет точные28595763648bytes,
GGUF magic и совпавший полный SHA256. Его расширение не означает, что данные
неполные; повторное скачивание не требуется. Receipt:
`receipts/browser_model_20261009.json`. Полный ZIP теперь готов и указан выше.
Первый CI run завершился на link без host CUDA driver; это отдельная ошибка
сборки runtime, а не недокачанные веса. Исправления сохраняют исходные веса/VMM.

Старые
`DOWNLOADING`/`ALLOCATING_LOCAL_FILE` могут оставаться после остановки процесса;
они не доказывают активную передачу или готовый файл. Указанный путь — цель, а не
наличие готового ZIP. Старый `r3.zip.partial` не участвует в новой сборке.
Не загружать в конкурс ни один `.partial` или weight-free CI artifact. Packaging
receipt не доказывает GPU inference новой сборки, её качество или30min hidden run;
эти границы явно записаны отдельно.

## Загрузка

1. Войти своим аккаунтом на https://dsworks.ru/champ/aij26-guardian и вступить
   в соревнование, если это ещё не сделано.
2. Открыть форму отправки решения в личном кабинете соревнования. В публичной
   неавторизованной странице форма не видна; точное название кнопки не проверено.
3. Загрузить готовый ZIP целиком. Не загружать `.partial`, GitHub source ZIP без
   весов или отдельный файл предсказаний.
4. Дождаться результата платформы и сохранить submission ID, статус, время,
   score и доступные логи. Это первая проверка реального hidden input и его
   лимита; локальный valid46 не позволяет обещать тот же расход времени.
5. До 20.10.2026 включительно выбрать три итоговых решения галочками на платформе.
   Если их не выбрать самостоятельно, правила предусматривают автоматический
   выбор трёх решений с максимальной метрикой.

По условиям платформа распаковывает source archive, выполняет `pip install .`,
затем `python scripts/predict.py --input INPUT --output OUTPUT`. Архив содержит
корневые `pyproject.toml`, `scripts/predict.py`, `src/`, `model/`, offline runtime
и Dockerfile. Docker registry reference для этой задачи не подтверждён.

Если форма требует иной формат, сохранить её точные требования до изменения
пакета. Нельзя применять Docker registry инструкции второй задачи к Guardian.
Полные проверенные источники и ограничения: REQUIREMENTS.md.
Разбор типичных ошибок загрузки/распаковки/скоринга и различия между официальными
ответами и советами участников: PLATFORM_UPLOAD_REVIEW.md. Зелёное уведомление
«запущено» само по себе не подтверждает запуск: проверять запись submission и стадии.
Не утверждаем, что сторонний uploader из комментариев безопасен: вложение не
получено и его код не проверен.

Лимит — десять успешных решений за весь конкурс, а не десять в сутки. Определение
«упавшего» в сноске14 правил относится к отсутствию любого предсказания из-за
критической ошибки. Расход попытки при частичном output/таймауте не установлен;
совет «все неуспешные запуски бесплатны» шире проверенного текста правил.

Автоматическая отправка в аккаунт не выполнялась. Один submission не доказывает
универсальность, но даст фактическое свидетельство о среде, времени и качестве.
