# Guardian of Truth — каскад Granite Guardian 4.1 FP8 → Qwen3.8-27B AWQ (B2)

`python scripts/predict.py --input <test.csv|parquet> --output <predictions.csv|parquet>`

Вывод: `id,label` (CSV, либо Parquet если путь оканчивается на `.parquet`).
Читаются только `id, prompt, response`. Без сети, всё из архива (свой рантайм vLLM 0.19.1).

## Как работает
1. Granite Guardian 4.1 8B (FP8 block-128) — groundedness-судья на всех строках
   (`scripts/granite_stage.py`, отдельная группа процессов). После него файл ответа уже записан.
2. Группа процессов Granite убивается и проверяется, что её нет.
3. Qwen3.8-27B AWQ INT4, конвейер B2 legacy — только на строках, где Granite сказал 0,
   в порядке убывания P(yes) Granite. Итог = Granite OR Qwen. Положительный ответ Qwen
   учитывается, только если все вызовы модели по строке завершились чисто до жёсткого стопа.
   Файл ответа перезаписывается атомарно каждые ~15 с.

## Время (от запуска predict.py; лимит платформы 30 мин)
- Granite: до 14 мин (иначе частичный результат, Qwen не запускается);
- Qwen стартует не позже 14 мин; новые строки до 21 мин; жёсткий стоп вызовов 25 мин;
- затем остановка сервера и финальная запись; выход 0.
- Если Granite не дал ни одного ответа — выход ≠ 0 без файла (платформа возвращает попытку).
- Если Qwen не стартовал/упал — остаётся ответ Granite (+ уже найденные Qwen-позитивы), выход 0.

Код: `scripts/cascade_submission.py`; сборка ZIP: `scripts/build_cascade_submission.py`.

## Проверка на A100 (vast.ai, бандл-рантайм, холодные кэши, 11.10.2026)
| Тест | Результат |
|---|---|
| valid46 | Granite 16/2/7 (F1 0.780) → каскад **20/2/3, F1 0.889**; всего 698 с (Granite 108 с, старт Qwen 320 с) |
| 920 синтетических строк (CSV) | Granite 920 строк за 344 с; Qwen 266 строк, приём остановлен на 21 мин; выход 0 на 21.9 мин |
| Qwen не стартует | остаётся ответ Granite, выход 0 |
| сервер Qwen убит (kill -9) посреди | незавершённые строки = Granite, запись файла, выход 0, VRAM освобождена |

Найдено: `read_rows` на CSV падал на промптах > 128 КиБ (`_csv.Error: field larger than field limit`) —
исправлено в каскаде (`csv.field_size_limit`). Старый B2-архив на CSV-входе с длинными промптами упал бы.

## Варианты архива
- **Каскад** (Granite + Qwen AWQ): ~35–36 ГБ, `--qwen-dir` указан.
- **Только Granite** (страховочный): ~14 ГБ, без `--qwen-dir`; рантайм пропускает Qwen (`QWEN_NOT_BUNDLED`).
  Проверено: 920 строк CSV за 333 с, выход 0. На valid46 F1 0.780.

## Вход
Свой ридер `read_input`: Parquet по сигнатуре или CSV (BOM, CRLF, многострочные поля в кавычках,
поля > 128 КиБ, лишние колонки, регистр/пробелы в заголовках, битые байты UTF-8 → замена,
пустые/NULL → ''). Дубликаты id не роняют прогон (получают одну метку, все строки в выходе).

## Веса
- Qwen: `cyankiwi/Qwen3.8-27B-AWQ-INT4` @ `6e134bae811fb5adac50ee042ae5f029ac6779aa` (HF, байт-в-байт).
- Granite FP8: сделан `scripts/fp8_block_quantize.py` из `ibm-granite/granite-guardian-4.1-8b` @ `ab01ccca…`
  **на GPU**. Повтор на CPU даёт другие байты (округление в fp8 отличается), поэтому для сборки
  брать именно файлы с сервера (`GRANITE_MANIFEST.json` это проверит).
