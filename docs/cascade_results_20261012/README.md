# Guardian: текущие результаты и следующий эксперимент — 12.10.2026

Каскад Granite → Qwen B2 показал F1 **0.8889 на valid46**, но получил **0.32448 на платформе**. Повторный запуск после исправления сопоставления строк дал, по сообщению пользователя, тот же балл. Причина расхождения не установлена: журнала и предсказаний именно платформенного запуска нет. Новый standalone Qwen3.8 B2 также, по сообщению пользователя, «не прошёл»; ошибка выполнения и низкая оценка пока не различены.

Этот каталог фиксирует накопленные результаты, анализ сохранённых прогонов и проект следующего эксперимента. Нового GPU-инференса 12.10 в рамках этого аудита не было. valid46 — многократно использованная разработочная выборка из 46 строк, 23 положительных; её результаты не являются независимой оценкой переноса на платформу.

Времена отдельных контролей нельзя складывать в оценку нового каскада: у них различаются старт, кэши и число вариантов. Исходный Granite воспроизвёл прежние метки. В прогоне на 920 синтетических строках каскад завершился за 21.9 мин, но строки повторялись, поэтому это проверка исполнения и дедлайна, а не доказательство скорости на уникальном полном тесте.

Исторический standalone Qwen3.8 FP8 B2 давал F1 около 0.821 и 5–6 строк/мин на valid46. Это другой профиль, чем AWQ внутри каскада. Прежние сравнения MoE давали Qwen3.5-35B-A3B F1 0.619, Qwen3.6-35B-A3B 0.541, Gemma 4 26B-A4B 0.545 и GLM-4.7-Flash 0.143; эти цифры взяты из ранее сообщённой истории экспериментов, в текущем аудите не воспроизводились. Замена модели сама по себе пока не показала нужного сочетания качества и скорости.

## Что проверено в реализации и сборке

- `5bee205d`: позиционная адресация строк каскада. Повторяющиеся id больше не перезаписывают метки; исходные id и порядок сохраняются. Это реальное исправление, но его роль в старом платформенном результате не доказана.
- `4aa7e1a5`: актуальная на момент публикации база ветки `cascade/granite-awq-20261011`. Добавлена проверка количества и соответствия возвращённых vLLM prompt каждому входному prompt в чанке Granite (`GRANITE_OUTPUT_ORDER_MISMATCH`) и тесты обработки нескольких чанков. Это защитная проверка; новый платформенный балл после неё в этом отчёте не зафиксирован. Проверка поля prompt не может обнаружить перестановку, если это поле отсутствует или равно None.
- Отдельный standalone ZIP `guardian-qwen38-b2-fp8-graphs16-rowfix-20261012.zip` собран из исходного FP8-архива с исправленным I/O и логированием; код сборки — локальный коммит `fc5dd8ce`. Он не является вариантом `--keep-source-qwen` из каскадного сборщика. Сохранены полный B2, 16 workers / 16 slots, контекст 32768, GPU memory utilization 0.88, prefix caching, chunked prefill и CUDA graphs. KV dtype — auto, вычисления BF16.
- Для standalone зафиксировано **188 passed, 2 skipped** (POSIX signal tests на Windows), CPU-проверка entrypoint непосредственно из ZIP и SHA256/CRC/mode-проверка всех **52673 файлов**. Размер **36575995616 байт**, ниже лимита 40000000000. SHA256: `8a0c6af86313a96cdd45026c30cfacc3c7b80aa35e1144817e28e329ba9fe149`.
- GPU-проверка именно этого standalone ZIP не выполнена: SSH возвращал Connection refused. CPU-тесты и проверка архива не подтверждают качество модели и время полного платформенного запуска.
- В standalone внутренний `duration=1800` не оставляет отдельного резерва на pip install и внешние операции. У каскада другой режим: жёсткий стоп 25 мин от predict.py с предусмотренным резервом. Причина последней неудачи по одному этому различию не установлена.

## Что удалось установить при аудите

**Расхождение с платформой остаётся необъяснённым.** Сохранённый каскад имеет F1 1.000 / 0.833 / 0.800 / 0.909 в airline / banking / retail / telecom. Простое перевзвешивание этих четырёх сохранённых профилей не даёт 0.324. Изменение трудности и состава внутри домена, малая выборка и неполное техническое покрытие этим не исключаются. Precision 0.26316 не является долей положительного класса платформы.

**Granite часто ошибается уверенно.** Шесть из семи FN имеют P(yes)<0.05, обе FP — P(yes)>0.995. Интервал 0.1–0.9 выбирает 12 строк, но охватывает только одну из девяти ошибок и одно из четырёх известных исправлений Qwen. Снижение порога до 0.02 даёт TP20/FP13/FN3 и F1 0.7143: полнота растёт ценой качества. Простой отбор «сомнительных» строк не обоснован этими данными.

**Сократить B2 можно, но ×5 не показано.** На 28 сохранённых Qwen-строках основной допущенный ответ совпал с окончательным. Поздние ветки плюс доказуемо бесполезный blind-проход можно исключить в исследовательском варианте: 50 вызовов вместо 100, на 28.8% меньше входных и 30.4% меньше выходных токенов. Это сохранённая проекция ответов, а не новый GPU-прогон и не универсальная гарантия ненужности поздних веток.

**Найдены технические пути потери полноты.** Контролируемые тесты воспроизвели: отказ supervisor принять положительное основное решение после сбоя вспомогательного вызова; неразобранный Granite score, превращающийся в 0; непосчитанные строки Granite, получающие 0 при пропуске Qwen. Эти сценарии не наблюдались в доступном платформенном логе — такого лога нет. Узкий модуль повторного допуска основного решения подготовлен отдельно, но в боевой ZIP не включён.

**Другие проверки пока дают ограниченный выигрыш.** Прототип закрытого списка инструментов нашёл на valid46 четыре положительных примера без FP и добавил один TP к Granite: F1 0.8095. Прирост полного каскада не показан. JEV имеет сигнал ранжирования (AUC около 0.779); исследовательская LOO-калибровка дала F1 0.750, ниже Granite 0.7805. Эти результаты не подтверждают перенос выбранного порога на платформу.

## Следующий эксперимент

Подробный протокол: [NEXT_METHOD.md](NEXT_METHOD.md).

С независимым участием Astra выбран кандидат: **повторно используемый индекс политики и короткая совместная проверка конкретного хода**. В valid46 ровно четыре различных полных блока policy, повторяющихся 12/11/11/12 раз. Статический разбор можно исследовать отдельно от переменной истории. Ключ переиспользования учитывает все инструкции и каталоги, влияющие на смысл; судья получает оригинальные правила с исключениями, а не только пересказ.

Для отказа проверяется существование конкретного ещё доступного разрешённого шага; для действия — его предусловия, объект и состояние на текущий момент. Три общих FN каскада: преждевременная банковская эскалация, отказ от доступного обмена товара и восстановление линии при истёкшем контракте. Это мотивирует проверку, но не доказывает её будущий F1.

Один короткий вызов на строку и ограниченный повтор при конкретном конфликте должны уменьшить повторное чтение и генерацию. В B2 уже есть условия и исключения: новое здесь — организация работы. Сначала сравниваются одинаковые модель и веса, представление входа с индексом и без него, контрастные пары и полное время на уникальных входах. Если Qwen3.8 не укладывается, тот же протокол проверяется на Qwen3.5. Ускорение и улучшение качества пока не измерены.
