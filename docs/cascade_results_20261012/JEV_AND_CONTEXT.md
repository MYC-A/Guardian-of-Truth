# Проверка JEV и структурного контекста, 11.10.2026

Эксперименты проведены отдельно от боевого ZIP. Промпты и правила отбора зафиксированы до инференса. Инференс читает только id/prompt/response; оценка использует метки после получения ответов. Порог JEV заранее задан 0.5, подбор порога по valid46 не делается. 46 строк — прежняя разработочная выборка, не новый независимый тест.

## Структурный контекст Granite

В исходном варианте сохраняются начало и конец промпта, всего 4800 символов. Новый алгоритм отбирает целые фрагменты с адресами источника: политику SYSTEM, список имён инструментов, полные схемы текущих вызовов, недавнюю историю и фрагменты с точными значениями из текущего ответа. Семантическая поддержка из одного совпадения строки не выводится. Вариант с обычной обрезкой ограничен примерно тем же числом токенов, что структурный; токенизация обёрток даёт небольшое различие.

Критерий, модель и обработка ответа Granite одинаковы. Prefix caching отключён для всех трёх вариантов, поэтому следующий прогон не получает выгоды от общих префиксов предыдущего. Отдельный холодный старт Granite: 87.07 с; подготовка промптов: 16.38 с; весь процесс трёх вариантов: 195.28 с. В таблице указано только время инференса, не полное время каскада.

| original4800 | 16 / 2 / 7 / 21 | 0.7805 | 13.40 с | 2084 токенов |
| structured10000 | 13 / 1 / 10 / 22 | 0.7027 | 38.31 с | 6030 токенов |
| headtail_matched | 10 / 1 / 13 / 22 | 0.5882 | 38.11 с | 6056 токенов |

Политика и обязательные разделы сохранены во всех 46 строках. Полная история сохранилась только в 7; это отбор, а не без потерь сжатый полный диалог. Некорректных ответов Granite нет. Новый отбор лучше обрезки того же объёма, но хуже исходного режима: переносить его в боевой каскад как улучшение нельзя.

Восемь тестов проверяют ограничения бюджета, цельность отрывков, точные адреса источников, сохранение политики и схем текущих вызовов, явную неполноту при неподдержанном формате. Они не доказывают смысловую достаточность выбранных фрагментов.

## JEV-9B

Модель autotrust/JEV-9B, ревизия 7ac669b8fb476ba926491e3d1c39f9330d68dbed. Скачаны только основные веса/токенизатор и adapter_vllm, около 18.10 ГБ. Каждый LFS-файл проверяется по опубликованному SHA256; остальные файлы также получают сохранённый SHA256. Исходный рантайм не заменяется и библиотеки не обновляются.

Для нашего vLLM 0.19.1 нужна регистрация уже существующего текстового класса Qwen3_5ForCausalLM в отдельном процессе. Решение читается из обученного decision-LoRA с поправкой bias и температуры по официальному протоколу. Перед оценкой выполняются два простых контрольных вопроса и сравнение с выключенным адаптером. Обход несовместимости рантайма не является доказательством правильности качества: результаты допустимы только после прохождения контролей.

Запланированы два варианта одного заранее заданного вопроса о новой ошибке: исходная обрезка контекста и структурный отбор. Это проверка специализированной обученной модели, не обычного Qwen с сокращённой генерацией. Старт модели, подготовка и инференс учитываются отдельно; скачивание весов не входит в моделируемый офлайн-запуск готового архива.



### Фактические запуски JEV

- `jev_eval`: код 1, весь процесс 197.33 с.
- `jev_eval_hybrid`: код 1, весь процесс 60.55 с.
- `jev_eval_plugin`: код 1, весь процесс 202.95 с.
- `jev_eval_text_positions`: код 1, весь процесс 203.98 с.
- `jev_eval_head`: код 0, весь процесс 138.48 с.

Первый запуск штатного текстового класса завершился до инференса: `Cannot unify by adjusting block_size`. Текстовый класс не объявлял гибридную архитектуру и методы расчёта состояния. В изолированной обёртке добавлены эти объявления и вызовы тех же расчётов, которые использует мультимодальная обёртка vLLM. Второй запуск выявил потерю регистрации в дочернем процессе: он выбрал мультимодальный класс и упал с `mm_encoder_tp_mode` на пустой multimodal_config. Для третьего запуска регистрация оформлена как ленивый `vllm.general_plugins` плагин. Веса, forward и установленные библиотеки не изменены. Эти сбои относятся к новой JEV, не доказывают причину низкого балла прежнего каскада.

Третий запуск дошёл до первого запроса и выявил отсутствие интерфейса SupportsMRoPE. Добавлен текстовый путь: одинаковые позиции по трём координатам, delta=0, отказ для multimodal inputs. Четвёртый запуск выявил отсутствие объявления embedding_modules для lm_head LoRA. Добавлена та же декларация, что у установленного Qwen3ForCausalLM; обученная голова не исключалась из адаптера. В итоговом запуске SSM state задан float32, как в HF config; основной dtype модели bf16. Для экономии времени повторно использован Triton cache четвёртого запуска, поэтому старт пятого нельзя называть полностью холодным. Prefix caching отключён, валидные запросы не получали выгоды от предыдущего инференса valid.

Контрольные вопросы и сравнение с выключенным адаптером пройдены. Результаты JEV включены в таблицу выше. Это качество на разработочном valid46, без подбора порога; точность на полном тесте платформы не измерена.

- `jev-context-experiment-evidence.json`: метрики, полнота выбранных источников и SHA256 исследовательских файлов.

- `result-jev_eval_head-*.json`: протокол и результаты завершённого JEV; остальные result-jev_eval* сохраняют технические попытки.
- `research-results.log`, `jev-status.log`: полученные с сервера результаты и состояние.

Боевой ZIP 5bee205d не изменялся. Скорость на этих 46 строках не гарантирует прохождение неизвестного полного платформенного теста.


Подробные расхождения с исходным Granite: `research-disagreements.json`; это разбор после оценки, не независимая проверка. Для Granite структурный отбор исправил 2 прежние ошибки и внёс 4 новые; увеличение объёма контекста само по себе улучшения не дало.


## Вероятности и калибровка

У JEV с коротким контекстом ROC-AUC 0.7788 и AP 0.7651; у исходного Granite — 0.7940 и 0.7827. Поэтому F1 0.296 при пороге 0.5 нельзя трактовать как отсутствие сигнала. Вероятности JEV, откалиброванные авторами для своей смеси задач, не откалиброваны для этого определения нарушения.

Дополнительный разбор: для каждой из 46 строк порог выбирался на остальных 45 по F1 из заранее указанной в скрипте сетки [0.05, 0.1, 0.15, 0.2, 0.25, 0.3, 0.4, 0.5, 0.6, 0.7, 0.8, 0.9, 0.95]; при равенстве выбирался больший порог. Затем проверяемая строка оценивалась с этим порогом. Её метка не участвовала в её собственном выборе порога. Это исследовательская проверка калибровки на разработочном наборе после просмотра первоначальных результатов, не независимая валидация моделей/промптов.

| Вариант | F1 после LOO-калибровки | TP / FP / FN / TN |
|---|---|---|
| Исходный Granite | 0.7805 | 16 / 2 / 7 / 21 |
| Granite, структурный контекст | 0.6522 | 15 / 8 / 8 / 15 |
| Granite, обычная обрезка такой же длины | 0.7619 | 16 / 3 / 7 / 20 |
| JEV, короткий контекст | 0.7500 | 18 / 7 / 5 / 16 |
| JEV, структурный контекст | 0.6383 | 15 / 9 / 8 / 14 |

Для короткого JEV во всех 46 LOO-разбиениях выбран порог 0.05 — нижняя граница этой сетки. Дальнейший поиск лучшего порога на тех же метках не делался. Доля положительных ответов платформы не использовалась и не считается известной. Эти результаты не доказывают перенос порога на другой набор или улучшение полного каскада. Боевой порог не менялся.

Итог: JEV запущен корректно, быстро и с обученной головой, но проверенная конфигурация не показала преимущества над имеющимся Granite. Структурный контекст в текущем виде также не готов для замены. Самые важные дальнейшие проверки — перенос калибровки на независимые размеченные данные и отдельные короткие вопросы по типам ошибки с подходящим для каждого источником контекста; это пока гипотезы, не измеренные улучшения.

Позиции текстового M-RoPE проверены против установленного upstream Qwen3VL на длинах 1, 7, 272, 1000, 12000: полное совпадение, delta=0. Запрос с multimodal feature отвергается. Лог: `jev-runtime-validation.log`. Восемь тестов отбора контекста пройдены. Библиотеки не обновлялись.

Финальная проверка: исследовательские supervisor jobs завершены, итоговый процесс JEV вернул код 0 за 138.48 с. GPU: 148 MiB, 0 %. Боевой checkout остаётся на 5bee205d без изменений.
