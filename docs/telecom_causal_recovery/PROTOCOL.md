# PRE_REGISTERED: independent targeted causal recovery v1

Base `ba2484218ff6597b3ff426762d22e582ff0ee13b`, branch
`research/telecom-causal-recovery-20261004`. Production, existing research phases,
valid.parquet and all historical labels/predictions remain unchanged.

Question: can an independent review recover the real current-action cause where
the earlier direct judge matched the label with a wrong cause? This is one known
Telecom development trajectory, not a valid46 F1 trial or an independent holdout.
The source-clear expiry prohibition is a researcher/scorer expectation; the model
gets only original normative text and evidence, never that expectation, gold,
official explanation or previous D0/P3 response.

## Arms and execution order

| Job | Normative/source packet | Additional information |
|---|---|---|
| A | Complete original main policy, complete technical Line Suspension section, factual call/result sequence, explicit identity/consent/latest intent, relevant original declarations, code-bound current target | None |
| B | Same as A | Raw typed equalities, every selected top-level ISO-date comparison with explicit system date, actor and original unique receipt checks |
| C | Same as B | Minimal factual source/actor/currentness conflicts for historical h27/h30; no previous text/verdict or contract hint |
| control_read | B on synthetic current read | No current resume action |
| control_future | B on synthetic h10 contract date 2026-12-31 | No established expired-contract condition |
| control_payment | B on synthetic h34 bill status Overdue | Expiry still applies independently; contradictory historical payment claims are disclosed |

A/B/C and controls are **ORACLE_RETRIEVAL_ASSISTED**. Selection is an explicit
researcher intervention, not automatic relevance discovery. No code computes a
normative verdict. Equalities/dates prove raw relationships; aliases, applicability,
ownership and freshness remain semantic hypotheses/unresolved. All calls/results
retain their original actors, including the USER payment.

After independent post-hoc confirmation of A's cause recovery, and only with
remaining budget, AUTO gets a complete catalog of normative fragments/history
and original declarations, but no oracle evidence set. One structured read-only
plan selects <=8 SourceStore READ_SOURCE/SEARCH_SOURCES operations, then one final
review uses only retrieved evidence. Read windows are explicitly paginated to
complete selected sources. Search coverage remains bounded and disclosed. This is
a single-round retrieval diagnostic, not a recursive controller.

## Model, budget, freeze

Pinned `ministral-14b-2512`, temperature 0, max output 1,400, timeout 120 seconds,
same small output schema and generic review prompt for all review arms. Source
IDs are constrained by per-packet enums and checked again locally. The model is
not asked for pointers, recursive Formula or witness paths. Source-valid IDs are
not a semantic correctness certificate.

Provider metadata was checked with one read-only GET; the existing public
tokenizer was reused. No weights/server deployment. Hard global ceilings:
**10 inference HTTP attempts / 60,000 known-or-reserved tokens**, one attempt per
request, no retries or fallback. Before HTTP the ledger durably reserves twice
the public tokenization of the entire serialized request + output cap + 1,024
template slack. Valid total usage replaces the reservation; malformed/missing
usage keeps the reservation and stops further calls. Transport/429/402 errors
also break subsequent calls. BUDGET_STOP records no semantic decision.

The largest core reservation is 21,132, AUTO selection 12,058. Reservations are
sequential and refunds depend on actual usage: not all prepared requests are
guaranteed to fit. No silent source trimming or cheaper fallback repairs a stop.
The protocol JSON seals code, original input, every core packet/body, parameters,
tokenizer, adaptive retrieval code/templates and budget before first inference.
Raw answers and request snapshots are immutable. Source verification, lock and
raw/request/ledger consistency prevent concurrent/repeated HTTP and cache drift.

## Pre-registered assessment

Separately record binary_correct, target_correct, policy_correct,
modality_correct, entity_binding_correct, temporal_relation_correct,
exception_scope_correct, source_grounding_correct, cause_correct and
fully_admitted. The first nine are a post-hoc source-based causal audit;
fully_admitted is mechanical shape/namespace admission. Each requires a rationale
and original-source references. A matched ERROR with a historical/payment cause
is binary_correct=true, cause_correct=false.

Original cause success requires current assistant t0, contract-end/resume norm,
FORBID interpretation, relevant line identity and original contract date, explicit
2025-02-25 system time, and recognition that payment does not waive the prohibition.
No machine clock, suspension-date substitution, USER action accusation or business
ID used as target source qualifies. Missing facts must be stated as gaps.

Control read must avoid claiming current resume execution. Control future must
avoid the expiry cause; NO_ERROR is not required if other problems remain. Control
payment must preserve the independent expiry cause even if a separate payment
condition is disputed. Controls are author-controlled diagnostics, not new official
competition rows or independent generalization. Original labels are never edited.

AUTO source discovery, oracle-assisted semantic interpretation and source admission
are reported separately. If A fails, no AUTO run. A positive local mechanism signal
still proves neither global F1 improvement nor architecture/domain transfer.
Stop after source-based audit, reports, commit and push; do not build Hybrid.
