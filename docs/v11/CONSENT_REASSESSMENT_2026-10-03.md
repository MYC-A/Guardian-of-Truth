# Возврат к задаче детектора: что доказано и где исследование ушло в сторону

Дата: 2026-10-03. Работа ведётся в изолированной
`research/consent-enhanced-audit-20261003`, основной checkout другого агента не меняется.
После команды пользователя «Пока только исправления без новых API» модельных запросов нет.

## Конкретная проблема

Мы стали оптимизировать число подтверждений согласия среди 19 применимых вызовов,
включая историю. Это вспомогательная задача, а не число найденных ошибок в 46 ответах.
Получение TRUE для корректной отмены брони само по себе не возвращает пропущенную
ошибку. Польза нового consent-канала для конкурсного детектора не измерена.
Наращивание этого канала как главного направления сейчас не оправдано.

Есть три различных препятствия:

1. **Ошибки кода.** В V4 смешанные ссылки на контейнер и его листья превращались
   в бизнес-поля; boolean внутри полного JSON не принимался. Их исправляет V5.
2. **Пропуск предложения моделью.** В fresh V4 GPT-OSS дал `plans:[]` для retail27
   с явными «Вы подтверждаете обе эти операции?» / «Да, подтверждаю обе операции».
   Gemma извлекла операции, но consensus не разрешил их. Парсер кода не может
   восстановить отсутствующую модельную гипотезу без нового семантического метода.
3. **Контракт слишком узкий для части реальной прозы.** Требуются все аргументы
   native call, а короткое предложение может описывать только изменение. Мы не
   добавляем непроговорённый год, старую часть маршрута или технический аргумент из
   будущего вызова: это было бы неподтверждённое достраивание. Чтобы проверять именно
   смысл согласованного изменения, нужны проверенные effect/argument contracts.

6 TRUE из кэша были ответами V3, пропущенными через admission V4. 3 TRUE свежего
прогона получены уже с изменённым промптом V4. Эти результаты показывают отсутствие
воспроизведённого выигрыша, но не изолируют случайность на абсолютно одинаковом запросе.

## Что реально получилось в последнем исправлении

V5 заморожен в `b3256b9c` до единственного offline replay; источники V3/V4 неизменны.
Исправления сделаны после просмотра V4 и независимого аудита кода. Это development,
не независимая проверка переноса. 0 новых HTTP и 0 новых API-токенов.

| Набор, те же сохранённые ответы | V4 TRUE/FALSE/UNKNOWN | V5 TRUE/FALSE/UNKNOWN |
|---|---|---|
| 19 реальных применимых вызовов |3/0/16|3/0/16|
| 12 новых для V4 контрастов, теперь просмотренных |1/0/11|3/2/7|
| 53 прежних контраста |10/3/40|8/3/42|
| 19 M1 с удалёнными ответами |0/0/19|0/0/19|

Восстановлены nested sequence, old/new mappings и два явных отказа. Потеряны
`v2_complete_two_call_batch` и `v3_exact_batch_with_audience_array`: строгая проверка
целого JSON не умеет разграничивать другие контейнеры на той же цитируемой строке.
Неверных разрешённых consensus на этих контрастах нет; низкое покрытие остаётся.
**V5 не повышается в detector.** На текущих реальных данных выигрыша нет.

32 теста V5 проверяют типы, сущность, порядок, вложенные источники, дубликаты ключей,
невалидный JSON, конфликтующие объекты и рамку источника. Предыдущий общий запуск
V11: 349 passed; после него добавлены ещё два regression tests и узкий V5 suite
повторно дал 32 passed. Отдельный аудит прежнего enhanced на 10 исходных диагностических
входах не обнаружил оставшихся неправильных кодовых сертификатов.

Это не доказательство понимания прозы: модель может пропустить исправление во второй
строке и процитировать только первую. Даже exact source check проверяет выбранные
источники, но не гарантирует полноту модели. `SHADOW_MODEL_SEMANTICS`, `code_proof=false`.
Ещё одно ограничение V5 — бизнес-объект с полями `value/span_ids` неоднозначен в
нетегированном evidence-формате и остаётся UNKNOWN. Оно не скрыто успешными тестами.

## Что полезного взято из существующих решений

| Источник | Реальный механизм | Применение и граница |
|---|---|---|
| [LangChain HITL, исходный код](https://github.com/langchain-ai/langchain/blob/master/libs/langchain_v1/langchain/agents/middleware/human_in_the_loop.py) | Действие содержит name+args; approve/edit/reject/respond различаются; решения в пачке сопоставляются отдельным действиям | Подтверждение относится к полному действию. Framework получает структурированное решение человека и не решает наше извлечение из истории свободной прозы. |
| [Schema-Guided Dialogue, Google](https://github.com/google-research-datasets/dstc8-schema-guided-dialogue) | Frames по сервисам, intent/slots и source spans; AFFIRM, AFFIRM_INTENT, INFORM_INTENT различаются | Полезная постановка следующего семантического опыта: сначала тип реплики и конкретное предложенное намерение. Это датасет/метод, а не готовый русский consent verifier. Обучение/скачивание датасета не проводились. |
| [Invariant: dataflow rules](https://invariantlabs-ai.github.io/docs/mcp-scan/guardrails-reference/) | Правила над Message/ToolCall/ToolOutput и порядком событий | Подходит для проверки уже привязанных событий. Применимость правила и смысл свободного согласия всё ещё нужно получить отдельно; автоматически формализованная политика не появляется от установки DSL. |
| [Instructor: validation](https://python.useinstructor.com/concepts/validation/) | Pydantic validation и возможный reask на ошибке | Полезен для формата. Валидная схема не доказывает правильный actor/scope; исправлять семантику неограниченными повторами нельзя. Новая зависимость и retries здесь не добавлялись. |
| [Python JSONDecoder](https://docs.python.org/3/library/json.html) | typed decoding, позиции конца JSON, hooks | Уже перенесён в V5: целые JSON-объекты и контейнеры-предки binding path сверяются кодом; duplicate keys/nonfinite числа отклоняются. Нет словарей доменов или названий инструментов. |

Таблица — оценка применимости, не сравнительный benchmark библиотек. Изучены официальные
документы и код; сами frameworks здесь не установлены и не запускались. Часть принципов
операционной привязки уже существовала в V2, поэтому не представляется новым выигрышем V5.

## Приоритет дальнейшей работы

Сохранённый audit `prod/phase1-admissibility-20261003@1183409c` воспроизвёл
TP19/FP0/FN4 против TP15/FP0/FN8 у прежнего рукава. Выигрыш относится к известному
public46 и не доказывает перенос. Он не вызван новым consent witness: таблицы правил
в этом прогоне пусты. Актуальность другой ветки после этого commit здесь не проверялась.

Следующий критерий полезности — восстановленные ошибки **всего ответа** при сохранении
прежних TP и отсутствии добавленных FP, с проверкой новых контрастных траекторий.
Сначала нужно сверить четыре остаточных FN и дефекты готового gate в отдельном аудите,
а не улучшать 3/19 как цель. Сейчас новые consent-архитектуры и API-прогоны не запускаются.
Подготовленные source-only fixtures V6 не использованы и не выдаются за результаты.

Артефакты: `consent_pair_v5_offline/{freeze,result,score}.json`; полные V4 raw replies
сохранены в `consent_pair_v4_83c29366_complete.zip`, V3 — в собственном неизменном архиве.
`scripts/predict.py` не изменён.
