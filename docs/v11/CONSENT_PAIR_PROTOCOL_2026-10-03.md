# Узкий разбор согласия: протокол до API

**Подготовлено:** 84 реальных вызова, 14 исторических контрастов согласия,
11 дополнительных контрастов. Модельное покрытие ещё не измерено.

Ветка `research/v11-universal-rescue-20261003`. Новая версия отдельно от
завершённого `v11-rescue-probe/1`; его код и ответы не переписываются.

## Постановка

Проверяем согласие на конкретную операцию и параметры, а не правильность всего
ответа. UNKNOWN не изменяет baseline direct и не является отрицательной меткой.
Список FN, gold и результаты model pair-probe при разработке не читаются.
Доля consent-ошибок в gold, сообщённая пользователем, не является нашим новым
независимым замером и не используется для выбора вызовов.
Пользователь также раскрыл consent-причину `airline__21::t7`: её считаем известной
диагностикой, а не слепым тестом. Код не содержит условий по ID строки или названию
домена; добавлен общий контраст «одобрено A, новая просьба B для той же сущности».

84 — точный прежний инвентарь native assistant вызовов объявленных инструментов
с ролью WRITE_OR_EFFECT либо UNKNOWN, включая историю и текущие ответы.
Сохраняем два вызова с невалидными arguments=null. В инвентарь не включались
необъявленные инструменты; эта граница явно показывается в отчёте.
Среди 84 есть 14 unlock, 30 банковских wrapper calls и 6 log_verification:
наличие такого вызова не доказывает применимость правила согласия.
Source-only аннотация политики выделяет 19 вызовов с требованием explicit yes:
15 airline, 4 retail. Это ручная область исследовательского замера, не
автоматически доказанный compiler scope. Только по этим 19 вызываются модели;
другие 65 сохраняются как NOT_CALLED_OUTSIDE_EXPLICIT_CONFIRMATION_SCOPE,
никогда не получают NO_ERROR по этому признаку. Согласование цены в telecom
является другим условием. Два malformed вызова входят в19 и не требуют HTTP.

## Метод

Модель видит до четырёх последних сообщений агента, полные следующие реплики
пользователя, декларацию целевой операции и краткие декларации остальных.
Аргументы текущего вызова от модели скрыты. Результаты инструментов представлены
метаданными событий: большие документы KB не участвуют в вопросе о согласии.
Полные native calls остаются в хронологическом инвентаре; их порядок и совпадение
с утверждённым планом проверяет код. Старые значения берутся только из явно
показанных реплик с источниками. Ссылка на непоказанный источник отклоняется.

Модель извлекает предложение и классифицирует полный ответ пользователя
относительно него. Она должна различить факт, действие агента, действие
пользователя, условное обещание, подтверждение, отказ и изменение параметров.
Каждый план имеет операцию, JSON arguments, дословную action-цитату, типизированные
листья параметров с цитатами и источниками, а также привязанный пользовательский блок.
Списки разрешено описывать обычной прозой; порядок и структура параметров сохраняются.
Пропущенные параметры не считаются служебными по догадке модели.

Код проверяет цитаты, роли, хронологию, полный набор листьев, точное типизированное
совпадение с текущими аргументами, повтор вызова и границы утверждённого плана.
Повторное описание того же действия сохраняет согласие; изменённое описание — UNKNOWN.
Другой вызов допускается только как связанный подтверждённый член того же плана
либо инструмент, описательно классифицированный READ. Эта классификация READ не
является доказательством отсутствия эффектов. Одинаковый retry никогда не разрешается
на основании старого согласия без отдельного контракта идемпотентности.

Смысловая связь между цитатой и параметром, а также интерпретация намерения
пользователя остаются модельными гипотезами. Все результаты:
`SHADOW_MODEL_SEMANTICS`, `code_proof:false`. В predictor не подключаются.
Отсутствие ответа после модельного ACTION_REQUEST имеет scope LOCAL_PROPOSAL_ONLY;
если более ранние предложения не попали в окно, оно остаётся UNKNOWN.

## Независимая проверка до freeze

Astra High, без API/gold/редактирования, нашла и проверила:
конфликтующие дубликаты планов, новый план рядом со старым в narration,
retry после READ эвристики, пустой корневой набор параметров,
непоказанные источники и потерю области локального FALSE. Исправления внесены
до freeze. Сохраняется известная граница: совместное присутствие значений
не доказывает правильное спаривание вложенных сущностей.

## Модели, бюджет, остановки

GPT-OSS120b reasoning=low и Gemma4:31b, один prompt, temperature=0, output-limit8192,
timeout180. Не более одного повтора при невалидном JSON; LENGTH/402/429 не повторяются.
Сырые ответы сохраняются до разбора. Одинаковые запросы переиспользуются по hash
messages+model config+version без case ID; скрытые текущие параметры сверяются
кодом отдельно. Это особенно важно для контраста 2 против 999.

Единый существующий V11 ledger: 450 HTTP /3M tokens, старые расходы входят в предел.
На старте предыдущий frozen опыт завершён: 83 HTTP, 1045103 подтверждённых токенов,
159110 верхней оценки неизвестного расхода, pending0. Mistral breaker429 не снимается.
Provider quota останавливает provider; auth/budget прекращают новые вызовы.
Resume сохраняет частичные строки, не затирает результат пустым отчётом.

У Ollama Cloud schema-constrained structured outputs не поддерживаются по
[официальной документации](https://docs.ollama.com/capabilities/structured-outputs).
Поэтому не объявляем backend-guided decoding: используем явный JSON prompt,
строгую локальную схему и отчёт о формате отдельно от смысла.

## Метрики и ручная проверка

- На 84: TRUE/FALSE/UNKNOWN по модели и согласованному результату разных семейств;
  отдельно по инструменту, malformed arguments, причинам UNKNOWN и scope FALSE.
- Исторические 14 контрастов: исходные ожидания сохраняются. В courtesy_ru
  «Подтвердите действие для X?» не указана сумма 2 и операция не локализована;
  прежнее ожидание TRUE недостаточно обосновано для полного parameter binding.
  Историческую метку не переписывать; показать этот случай отдельно. Новый
  полноценный RU-контраст содержит сумму и действие до запуска.
- Три state-only peer-контраста относятся к другим механизмам. Полный peer-аудит17
  уже воспроизведён отдельно; не выдавать проверку 14 случаев согласия за все17.
- Дополнительные 11: длинное scoped согласие, conditional/quoted reply,
  фактический вопрос, действие пользователя, inspection-stage, утверждённый batch,
  список прозой, другой родитель с теми же детьми, новая операция после согласия
  на другую операцию той же сущности. Новая просьба не считается прежним согласием.
  FALSE по NEW_REQUEST без полного исходного инвентаря ранее утверждённых планов
  не включается автоматически: в этом протоколе такой контраст ожидает UNKNOWN.
- M1: offline source-deletion checks должны никогда не выдавать TRUE. Это
  проверка сохранённых модельных ответов на изменённых источниках, без нового
  модельного inference и без метки ошибки всего ответа.
- 20 контекстов для ручного аудита выбираются seed20261003 в прежнем порядке
  инвентаря до API. Проверить full trace и соответствие каждой рамки/ответа.
  Не называть такую проверку независимой оценкой всей совокупности.

Успех: ненулевое обоснованное покрытие согласия при нуле ошибочных разрешений
на заранее заданных отрицательных контрастах. Нельзя объявлять качество по
числу принятых рамок. Решение о дальнейшем runtime требует отдельной оценки
ошибочных TRUE/FALSE и областей применимости; улучшение public46 здесь не измеряется.
