# Замороженный consent pair v1: результат

Freeze commit: **355948b5**, реализация **f4831003**. Алгоритм после freeze не менялся.
Модели: GPT-OSS120b и Gemma4:31b; текущие аргументы целевого вызова им скрыты.
Статус всего опыта: **SHADOW_MODEL_SEMANTICS, code_proof=false**.

- Реальный набор: **19 применимых вызовов**, из них два с некорректными аргументами;
  остальные 65 из общего inventory84 не требуют этой explicit-yes проверки.
- Реальное покрытие: у обеих моделей и их согласования **TRUE0 / FALSE0 / UNKNOWN19**.
- 25 контрастов: согласование даёт **TRUE4 / FALSE1 / UNKNOWN20**; ни одного ошибочного
  разрешённого TRUE/FALSE относительно квалифицированных source expectations.
  FALSE имеет локальный scope, не доказывает отсутствие более раннего разрешения вообще.
- При этом GPT-OSS по отдельности дал неправильный TRUE на инструкции действовать
  **пользователю** (`extra/user_operation`); Gemma его не повторила.
- Цена: **84 HTTP**, **286705 known tokens**, unknown cost0; сумма HTTP времени295.374s.
  Это не измерение длительности всего исследования или токенов Codex.
- Общий ledger на момент окончания:167 HTTP,1331808 known +159110 unknown upper bound;
  старый Mistral breaker сохраняется. Повторных quota запросов этот опыт не делал.

Причины отказов на 34 реальных модельных ответах:15 неполных candidate inventories,
13 недословных action citations,3 schema errors,1 mismatched leaf binding inventory,
1 неподдержанное source значение,1 invalid reply citation. Здесь любая ошибка внутри
общего envelope отклоняла его целиком. Точная разбивка по admission reason записана
в result.json. Полезного переноса пока нет.

В частности, Gemma удаляет Markdown `**` из цитат, а GPT-OSS часто возвращает только
последний значимый план, не все candidate IDs. Но есть и смысловые ошибки: GPT-OSS
не нашёл отмену в airline7, в airline44 использовал native calls как сообщения-предложения;
простая починка JSON/цитирования их не устраняет.

Offline M1 readmission исходных ответов после удаления источников: **TRUE0 / FALSE1 /
UNKNOWN83** на84 model records. Это проверка admission invariant; модели на изменённых
диалогах повторно не вызывались. Нельзя представлять её как новый модельный benchmark.

Сырые ответы сохранены в `outputs/searh_23/v11/consent_pair_355948b5_complete.zip`;
score/result/M1 отдельно — в `outputs/searh_23/v11/consent_pair_probe/`.
Detector gold не открывался; известный airline21 был заранее раскрыт пользователем.

Следующий candidate должен отделить обработку **одного** предложения от инвентаризации
всего окна, выдавать span IDs вместо свободного копирования Markdown и изолировать
отказ отдельного неподходящего плана. Непроверенные поздние сообщения/планы должны
оставаться препятствием для TRUE. Такой алгоритм будет новой версией с новым freeze;
переоценка этих же ответов после исправления считается development replay.
