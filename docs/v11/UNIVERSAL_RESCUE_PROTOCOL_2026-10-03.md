# Универсальные исправления и новый опыт компиляции

Ветка `research/v11-universal-rescue-20261003`, база `a30bc69b` / peer `35ce9821`.
Старый пилот, manifest и freeze сохраняются. Gold не открывается. Production не меняется.

## Исправления до нового опыта

- Receipt связывает результат с единственным предыдущим assistant-вызовом.
  Orphan, user-call, неоднозначное спаривание и последний противоречивый результат
  дают UNKNOWN. Чужой явно адресованный read пропускается без потери своего старого read.
- TARGET требует доказать все идентификаторы цели на одной цепочке parent → child.
  ANY/ALL требуют область родительской коллекции до wildcard; ребёнок её не доказывает.
- Канонизация Decimal точная, без влияния precision. Null-сравнения с разной
  трёхзначной семантикой не объединяются; literal-null переживает сериализацию.
- Wrapper prior_call:{tool,binding} переносится lossless с журналом; конфликт
  binding и неправильная modality отклоняются. Эквивалентные necessary modalities
  используют общий ключ, FORBIDS и applicability guard остаются различными.
- Знаменатель frozen POSITIVE не зависит от наличия таблицы. RELATED_ONLY не получает
  recall-кредит; EXACT имеет приоритет. Отсутствующая таблица — пропуск.

## Подтверждение: доказательство и потеря покрытия

Прежнее ID + вопрос/утвердительный префикс не доказывало согласие на операцию.
Новый кодовый протокол принимает только полный исходный `Confirm TOOL: JSON?`
или `Подтвердите TOOL: JSON?`, а описание — `I will call TOOL: JSON` / `Вызову TOOL: JSON`.
Имя берётся из декларации, все фактически переданные аргументы сравниваются типизированно.
Реплика пользователя целиком должна принадлежать закрытой ru/en грамматике.
Изменение операции/параметров, новый неподтверждённый текст, intervening native act,
свободный хвост «Yes, I refuse …» остаются UNKNOWN. Retry сам по себе не доказывает
неуспешный эффект и не сохраняет согласие автоматически.

Это **ограниченный источник доказательств**, а не решение свободной семантики.
Обычная проза UNKNOWN: ожидается падение покрытия реального confirmation witness.
Старые тесты с `Confirm action on X?` заменены полными операциями в положительных
контролях; дополнительно старые неполные/фактические вопросы проверяются как UNKNOWN.
Непроверенный natural-language certificate от одного LLM не повышается до факта.

## Гипотеза компиляции

До lowering сохраняем source-backed ledger: disposition каждого пункта и каждую
найденную обязанность, её guard, исключения, точные цитаты. Потом отдельным запросом
переводим каждую обязанность в единый requirement-expression или UNSUPPORTED/AMBIGUOUS.
Непредставимость больше не превращается в «policy не требует ничего».
Clause inventory проверяет bookkeeping; **семантическую полноту это не доказывает**.
Обязанность с потерянным guard/exception не компилируется. Конкурсный успех только
по исходному замороженному замеру, а не по числу извлечённых obligations.

## Малый frozen сравнимый опыт

Перед API коммитятся код, тесты, этот протокол и `rescue_probe/freeze.json`.
По каждой из четырёх известных политик берётся лексикографически первый инструмент
с ролью !=READ. Это механический выбор без FN/gold. Все модели получают те же политики
и trigger. A: текущий one-shot с исправленным общим wire/witness-контрактом.
B: ledger по кодовым chunks ≤64 clause IDs + отдельный lowering. Каждый chunk
видит **полный** policy и все декларации; уменьшается только объём обязательного
ответа. Код проверяет coverage всех chunks и lossless namespace IDs обязанностей.
Оба рукава видят все декларации инструментов. B имеет больше одного вызова,
поэтому стоимость и латентность показываются отдельно; это не равный compute budget.

Модели: GPT-OSS120b high (max_output 32768), Nemotron ultra (12288), Gemma4:31b (8192),
temperature 0, timeout 300 секунд. Mistral имеет сохранённый provider breaker 429:
его не сбрасываем. Политики имеют 73/38/177/40 clause IDs: 7 inventory chunks
на модель, 4 one-shot + до 4 lowering = до **45 основных вызовов**, каждый с
максимум одним syntax retry (до 90).
Все расходы входят в общий V11 ledger **450 HTTP / 3M**, старые 44 попытки сохранены.
По квоте останавливается провайдер; auth/budget останавливают опыт. Технические
LENGTH/TIMEOUT/INVALID_JSON не называются семантическими empty.

До API отдельно сохранён `source_expectations.json`: source-only оценочная
инвентаризация четырёх trigger. Она не подаётся компилятору; reviewer ранее видел
старый banking pilot, это раскрыто. После результата нужен аудит сохранения смысла
по source: совпадение quote/lhs само по себе его не доказывает.

Метрики: формат, полнота clause dispositions, source span admission, найденные
obligations, compiled/unsupported/ambiguous/rejected, per-trigger атомы и cross-family
agreement, потерянные/невалидные кандидаты, стоимость/латентность отдельно A/B,
восемь существующих банковских контролей invariance. «Compiled» означает структурно
допустимый кандидат, а не доказанную эквивалентность обязанности. Никаких TP/FN по
этим метрикам. После ответа алгоритм этого опыта не меняется; новая правка — новая версия.
Новый ключ кэша включает полный prompt/protocol и параметры модели. Сырые ответы
сохраняются до admission. Результат опыта сам по себе не разрешает заменить predict.
