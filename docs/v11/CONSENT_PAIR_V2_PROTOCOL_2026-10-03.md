# Согласие v2: один источник предложения, отдельные операции

Дата: 2026-10-03. Ветка `research/v11-universal-rescue-20261003`.

## Что меняется

Production regex-witness остаётся UNKNOWN на19/19 реальных применимых вызовах.
Завершённый модельный pair v1 также остался UNKNOWN19/19:15 ошибок inventory,
13 недословных цитат и другие дефекты admission. Новый опыт проверяет другую
организацию работы, сохраняя полное совпадение параметров.

Код выбирает последнее сообщение ассистента с непосредственно следующим
пользовательским блоком; если такого нет — последнее сообщение ассистента.
Один запрос извлекает только предложения из этого сообщения, включая отдельные
операции пакета, и классифицирует **полный** ответ пользователя относительно
каждого предложения. Модель не получает текущий вызов или его значения.
Предыдущие четыре текстовых сообщения дают контекст ссылок; native calls и
результаты не используются для достраивания отсутствующих параметров.

Вместо копирования цитат модель выбирает ID строк исходного текста, включая
Markdown. Это механические границы показа, а не границы правил/смыслов.
Код проверяет существование и роли источников, порядок, JSON-pointer inventory,
поддержку значений источником и полное типизированное совпадение аргументов.
Ошибка отдельного постороннего плана не отклоняет весь envelope. Неразобранный
план того же инструмента или промежуточного вызова блокирует разрешение.

Каждый подтверждённый член пакета расходуется отдельно. Промежуточный вызов
проходит только при точном совпадении с другим подтверждённым членом, один раз.
Классификация READ по имени инструмента **не** является контрактом отсутствия
эффектов и не даёт обхода этого условия. Любой последующий непроверенный текст
агента или пользователя блокирует использование старого согласия.

CONFIRM даёт TRUE, REFUSE даёт локальный FALSE; остальные ответы — UNKNOWN.
Отсутствие ответа на локальное предложение не доказывает отсутствие более
раннего разрешения, поэтому в этом опыте не даёт FALSE. Для итогового результата
нужно совпадение двух семейств по операции, полным аргументам и источникам.

## Независимый просмотр до API

Astra High разобрала реальные источники и код. Исправлены найденные ею READ
обход и падение при смене роли/исчезновении источника. Отдельный агент подготовил
16 дополнительных контрастов. Проверки кода используют вручную заданные
семантические классификации: они не измеряют качество модели.

## Замороженный опыт

-41 контраст:25 из v1 с сохранением source-qualified ожиданий и16 дополнительных.
-19 неизменённых реальных native calls; два malformed сохраняются без API.
-19 M1: удалены пользовательские ответы после первого предложения, исходные
  native calls сохранены. Модели вызываются на изменённых источниках заново.
-Те же GPT-OSS120b и Gemma4:31b, temperature0,8192 output tokens,150s timeout.
-Один HTTP на уникальный packet/model, без повторов и синтаксических reasks.
-До112 новых попыток в существующем общем ledger450HTTP/3Mtokens. Старые затраты,
  reservations и Mistral breaker сохраняются. Первый неуспешный HTTP останавливает
  этот опыт. Разрешение на одноразовый foreground SSH уже получено ранее.
-Неверный разрешённый consensus на контрасте или TRUE на M1 останавливает опыт;
  исправление после этого требует новой версии/freeze. UNKNOWN не считается успехом.

Условия, исходники и SHA фиксируются в `consent_pair_v2_probe/freeze.json`,
коммитятся **до** API. Запросы не содержат ожиданий или detector gold. Реальные
диалоги ранее просмотрены: это development replay, не независимая проверка переноса.
Scope19 взят из прежнего ручного source-only разбора, не из нового compiler.

## Границы результата

Все результаты `SHADOW_MODEL_SEMANTICS`, `code_proof=false`. Принадлежность значения
полю, смысл действия и согласия остаются модельными гипотезами. Совпадение двух
моделей не является формальной гарантией. Coverage согласия не равно TP детектора.

Первая версия не освобождает технические поля от подтверждения, не достраивает
год даты, старые сегменты перелёта, данные пассажиров или платёжные значения из
receipt. Для этого следующий отдельный компонент должен иметь контракты
EXPLICIT / REFERENCED_ENTITY / PRESERVED / DERIVED с проверкой родительской сущности.
Неоднозначный receipt, неполные данные и неподтверждённая зависимость — UNKNOWN.
Отложенное ранее предложение, например отмены в airline44, не восстанавливается
по одному последнему сообщению. Конкурсный predictor в этом опыте не изменяется.
