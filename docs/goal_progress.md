# Полный план: состояние реализации и оставшиеся проверки

Цель остаётся полной: переносимая проверка ответа с графом, смысловой моделью,
приёмами выборочного/рекурсивного чтения, измерением пользы и исполняемой поставкой.
Этот документ не заменяет цель более узкой. Наличие кода и успешных синтетических тестов не означает завершение.
По последнему указанию пользователя сначала завершаем автономную базу и её проверки, реальную интеграцию токена оставляем на конец.

## Реализовано в текущем цикле

| Требование | Артефакт | Что проверено | Что ещё не доказано |
|---|---|---|---|
| Groq и заменяемый локальный сервер | `llm_client.py`, `runtime.py`, `settings.py` | Транспорт, категории ошибок, ограниченные повторы, отсутствие секрета при переключении на localhost | Успешная авторизация и качество на реальном Groq |
| Прямая модель как база сравнения | `LanguageAnalyzer`, режим `direct` | Формат запроса/ответа, источники и классификация через локальный тестовый сервер | Реальные точность, полнота, время, модель/порог для финала |
| Граф в смысловом потоке | `EvidenceReader`, режим `graph` | Подбор источников по аргументам и узлам, переходы к предыдущим/следующим наблюдениям | Положительный прирост относительно прямой модели |
| Приёмы RLM | Режим `rlm` | Реальный цикл запрос → локальное чтение → повторная оценка; ограничения раундов/запросов/контекста | Польза на длинной истории; это не полная реплика RLM с произвольным REPL |
| Общие предварительные условия | `rules.py` | Типы, даты, принадлежность, область сущности, исключения, неизвестность, ссылки | Перевод произвольной политики и подтверждённая модель переходов состояния |
| Утверждения и отказы | Структурированный ответ модели с claims и plan | Согласованность общего вывода, отдельные источники, доступность инструментов предложенного плана | Полнота извлечения, выполнимость плана и его существенность; модельный план не формальное доказательство |
| Итоговая метка | `decision.py` | Механические находки отдельно; явный порог сырого модельного риска; unknown-подстановка | Вероятности не откалиброваны; порог 0,5 технический, не оптимальный |
| Проверка переносимости | `benchmarking.py`, генератор сценариев | Связные группы происхождения, разделение, дубликаты, настройка только на calibration, парные интервалы | Новый независимо размеченный естественный набор; синтетика не заменяет его |
| Сравнение режимов | `scripts/compare_modes.py` | Одинаковые входы, ограничение ресурсов каждого режима, сохранение отчёта и исходных хэшей | Живое сравнение не выполнено до рабочего подключения |
| Поставка | CLI, `Dockerfile`, `.dockerignore` | CSV и JSONL, запись по мере готовности, секреты исключены из образа | Docker build/run, холодный запуск и лимиты платформы |
| Модель переходов и поиск плана | `planning.py` | Ограниченный поиск с предусловиями, явными эффектами и условными исходами | Перевод произвольной политики и соответствие модели реальному миру |
| Внешний резерв | `external_data.py`, импорт RAGTruth | Адаптация разметки, раздельные источники, неизменный исходный test | Живые модельные измерения; это фактический RAG, не полный конкурсный тест |

Текущая проверка: 163 автотеста проходят; автономный прогон всех 46 строк сохранил F1=0,414.
На контролируемом синтетическом резерве — 51 строка из 3 групп — автономная база получила F1≈0,889.
Это намеренно простые проверки механизмов, не доказательство конкурсного качества и не измеренный прирост от LLM.
Wheel собирается с изолированными build-зависимостями; версия до добавления планировщика прошла 143 теста после установки в чистое окружение.
После завершения новых модулей нужна повторная проверка поставки. Docker в текущей среде не обнаружен, образ ещё не проверен.

## Запуск

По умолчанию решение не обращается к сети:

```powershell
python scripts/predict.py --input valid.parquet --output outputs/offline.csv --audit outputs/offline.jsonl
python -m unittest discover -s tests -v
```

Ключ хранится только в `.env` (игнорируется Git), строка `GROQ_API_KEY=...`.
`.env.example` — пустой пример, туда нельзя коммитить секрет. Загрузка выполняется только явно запускаемыми CLI;
переменная настоящего окружения имеет приоритет над файлом. Файл хранится открытым текстом.

```powershell
python scripts/check_connection.py
python scripts/check_connection.py --live
python scripts/predict.py --input valid.parquet --output outputs/groq.csv --audit outputs/groq.jsonl --run-report outputs/groq_run.json --backend groq --mode rlm --max-requests 100 --seconds 1500
python scripts/compare_modes.py --input valid.parquet --output-dir outputs/comparison_01 --backend groq --limit 8 --max-requests 24 --seconds 240
```

`--backend groq` явно разрешает передачу `prompt` и `response` этому сервису; эталонные метки и объяснения
в запрос не включаются. Лимит запросов включает HTTP-повторы. Лимит символов — защитный предел объёма,
не точный токенизатор или денежный бюджет. Исчерпание ресурса оставляет пример неопределённым.
Сравнение на `valid.parquet` всегда диагностическое, не независимое доказательство переноса.

Для локального совместимого сервера:

```powershell
python scripts/predict.py --input test.csv --output predictions.csv --backend local --base-url http://127.0.0.1:8000/v1 --model LOCAL_MODEL_NAME --mode graph
```

Groq-ключ при этом не используется; при необходимости серверу передаётся отдельный `GUARDIAN_LOCAL_API_KEY`.
Запуск сервера и загрузка локальных весов не выполняются автоматически.

Основания транспорта: [совместимость API Groq](https://console.groq.com/docs/openai),
[форматы структурированного вывода](https://console.groq.com/docs/structured-outputs).
Используем стандартный HTTP-клиент и JSON object mode с собственной проверкой; не полагаемся на обещание
схемы как гарантию истинности. Поддержку модели нужно проверять перед живым запуском.

## Следующая проверка перед заявлением о завершении

1. Получить успешный ответ авторизации на фактически сохранённый ключ. Запрос с прежним значением вернул HTTP 401;
   значение ключа в этом отчёте намеренно отсутствует.
2. Провести ограниченный живой пробный прогон, затем одинаковое сравнение `direct`, `graph`, `rlm`;
   измерить незавершённые чтения, ошибочные ссылки, усечение ответа и потери контекста.
3. На новых сценариях проверить перевод политик, переходы и отказы. Не превращать модельный перевод в строгое правило без проверки.
4. Подготовить независимо размеченные естественные случаи и зафиксировать закрытые группы до настройки;
   измерить перенос и откалибровать выбранный вариант на отдельной части.
5. Проверить контейнер и реальную среду поставки, обновить итоговые схемы по измеренно выбранной архитектуре.

Пока остаются эти пункты, цель не считается завершённой. Отрицательный результат опыта тоже допустим:
ненужные расширения нужно исключать по данным, а не сохранять ради сложности архитектуры.
