# V2: автономная абляция начального выбора контекста

## Гипотеза и границы опыта

Проверяем, изменяет ли добавленный приоритет явных идентификаторов из ответа
доставку исходных свидетельств при ограниченном окне. Если совпадений нет,
этот же блок даёт приоритет последнему результату инструмента.

Это **абляция одного блока текущей реализации**, а не точное восстановление исторического reader.
Сравниваются нынешний `EvidenceReader.initialize` и его локальный подкласс в
[ablate_reader_selection.py](../scripts/ablate_reader_selection.py), где удалён только блок
`response_entity_chunks` / последнего результата. Не меняются:

- первый системный фрагмент;
- выбор последнего сообщения пользователя;
- чтение источников аргументов через существующий граф;
- лексический поиск и дочитывание остальных системных фрагментов;
- размер фрагмента 1800, общий предел свидетельств 4800, начальный предел 12000;
- отсутствие замены окна при первоначальном наполнении.

Выбор выполнен на **всех 46 строках**, включая строки, которые реальный каскад обрабатывает
механически без LLM. В отбор поступают только `prompt` и `response`.
Сначала выбираются оба пакета для всех строк; лишь затем загружаются аудитные координаты и метки.
Аудитные источники не участвуют в ранжировании.

Никаких API, ключей, генераций, новых предсказаний или F1 в этом опыте нет.

## Измерение

Исходные координаты взяты из [положительного аудита](v2_positive_reason_audit.json) и
[аудита FN/fallback](v2_unknown_reason_audit.json). Фрагменты проверяемого `response` исключены.
Одинаковые `(id, start, end)` дедуплицируются. Осталось **112 интервалов в 35 строках**.

Для каждого интервала измерено полное, частичное или нулевое пересечение с выбранным сырым текстом.
Для символьной доли знаменатель — объединение интервалов **внутри каждой строки**,
а числитель — пересечение этого объединения с объединением выбранных фрагментов.
Перекрывающиеся интервалы не увеличивают символьный знаменатель повторно.

Наборы «ошибки», «TP», «fallback» обозначают исходные решения strict из сохранённого запуска,
а не новые решения после отбора. Fallback пересекается с ошибками; строки подтаблиц нельзя суммировать.

| Аудитная группа | Строк / интервалов | Полностью: без приоритета → текущий | Частично | Не доставлено | Доля объединённых символов |
|---|---:|---:|---:|---:|---:|
| Все аннотированные | 35 / 112 | 54 → 64 | 1 → 0 | 57 → 48 | 39,67% → 44,82% |
| Strict FP/FN | 14 / 50 | 22 → 27 | 0 → 0 | 28 → 23 | 28,98% → 37,83% |
| Немеханические strict TP | 8 / 28 | 15 → 15 | 1 → 0 | 12 → 13 | 48,13% → 36,66% |
| Strict fallback | 18 / 56 | 24 → 32 | 0 → 0 | 32 → 24 | 38,32% → 47,14% |

По всем аннотациям: 38673 → 43694 доставленных символа из объединения длиной 97477.
Признак порядка/состава выбранного пакета изменился в **38 из 46 строк**;
в 34 изменился состав, ещё в четырёх — только порядок. Полный список находится в `changed_ids` отчёта.
У всех 35 строк с сохранённой исходной трассой начальный список текущего reader
совпал с `reading_trace[0].evidence_ids` запуска `claim_gate_20b_full`.

Падение в TP-подмножестве показывает цену вытеснения при фиксированном бюджете.
Нет оснований объявлять новый приоритет безусловно лучшим для каждой строки.

Ещё важнее: **не все аудитные интервалы являются нужным подтверждением ответа**.
Аудиты содержат и ошибочно использованные моделью источники, и контрсвидетельства к её объяснению.
Например, увеличение покрытия `airline__10::t19` включает запись другой даты,
которой модель неверно опровергала цены на нужную дату. Рост этой метрики сам по себе не означает пользу.
Полное чтение интервала тоже не доказывает правильность смыслового вывода.

## Отдельный проверяемый случай `airline__24::t14`

В исходном prompt есть результат `book_reservation` с бронью HATHAT:
символьный интервал **[28883, 29605)** длиной 722.
Он не входит в два аудитных набора; отдельная диагностическая проверка добавлена
после выбора пакетов и не участвует в суммарной таблице.

- Без дополнительного приоритета: 0/722 символов, запись не доставлена.
- Текущий reader: 722/722, запись доставлена полностью.

Это воспроизводит факт улучшения доставки, описанный в [журнале опытов](experiment_log.md).
Ранее живой диагностический повтор этой строки получил метку 0 **через fallback**,
так как один claim не имел допустимой опоры на prompt. Следовательно, ни прежний повтор,
ни нынешняя автономная проверка не доказывают исправление смысловой классификации.

В последующем [сравнении текущих graph/RLM](v2_modes_closed.md) обе модели уже выдали
на этой строке пригодный отрицательный score со ссылкой на результат бронирования,
не fallback. Это положительное наблюдение на одном случае, не изолированный
причинный эффект приоритета reader и не оценка переноса.

## Решение и воспроизводимость

Зафиксировано локальное изменение распределения ограниченного контекста, включая как приобретённые,
так и потерянные источники. В рамках этого опыта production-reader не изменён.
Текущий приоритет остаётся частью зафиксированной V2-базы, но не получает статус доказанного quality gain.
Для такого вывода нужен отдельный одинаково ресурсно ограниченный модельный опыт
с причинами решений и последующей проверкой переноса.

```powershell
python scripts/ablate_reader_selection.py --input valid.parquet --output-dir outputs/reader_selection_ablation
```

Артефакт: `outputs/reader_selection_ablation/report.json` — конфигурация, SHA-256 входа,
двух аудитов, исходного baseline-аудита, скрипта и ключевых модулей;
выбранные интервалы всех 46 строк, групповые результаты и изменившиеся ID.
Повтор требует нового каталога: существующий отчёт не перезаписывается.

Ручные аннотации уже изученного `valid` не являются полным gold-набором релевантных источников.
Графовые краткие описания и смысловая достаточность в символьной метрике не учитываются.
Результат закрывает автономную диагностику выбора контекста, **но не заменяет измерение F1 или причинного эффекта**.
