# Повторный аудит парсера и входного формата — 19.10.2026

Найдены воспроизводимые ошибки на границах формата и применения правил.
Исправления проверены локально. Они не подменяют код, данные или уже построенные
запросы работающего V4 train-v1: тот эксперимент и его автоматическое сравнение
продолжаются с зафиксированными исходниками. Нового измеренного прироста F1 пока нет.

## Исправления

1. **JSON-каталоги инструментов.** Старый парсер принимает только текстовый список
   организаторов, хотя synthetic renderer передаёт OpenAI function list в JSON.
   Добавлен разбор JSON с сохранением вложенных схем, nullable и локальных ссылок.
   Версия JSON Schema учитывается; внешние ссылки не разрешаются. При повторяющихся
   ключах/инструментах схема неоднозначна и не даёт обязательного обвинения.
   Неизвестные схемы остаются UNKNOWN. Компиляция схем ограниченно кэшируется;
   аргументы, оценки и решения строк не кэшируются. Нужен штатный dependency jsonschema.
2. **Продолжения результатов.** Документированный отступ TAB + два пробела внутри
   результата теперь обрабатывается до поиска стрелок и заголовков. Иначе текст
   инструмента с `TOOL_CALL` или `⟦USER⟧` мог становиться настоящим событием.
3. **Примеры в Markdown.** Стрелки и заголовки внутри fenced code остаются текстом.
   Незакрытая ограда фиксируется диагностикой; неоднозначность не доказывает нарушение.
4. **Владелец результата.** Явный requestor в header dialect не связывается с более
   ранним ожидающим вызовом другого владельца. Неявные стрелочные результаты
   по-прежнему используют FIFO по имени инструмента.
5. **Date-gate.** Одного упоминания старого запрета недостаточно: нужна отдельная
   действующая распознанная норма, однозначные часы SYSTEM, успешный связанный
   результат с тем же ID и отсутствие последующей записи, делающей состояние устаревшим.
   Цитаты, отменённые/условные нормы и неподтверждённое состояние не дают hard.
   Это ограниченная грамматика, а не универсальный анализ применимости политики.
6. **Исключения turn-shape.** Формулировка «This restriction does not cover read-only
   lookups» теперь блокирует обязательное обвинение за два вызова. Набор фраз не
   претендует на полноту естественного языка.

## Оставшиеся различия формата

Synthetic V4 renderer выводит отдельный `ASSISTANT` перед каждым tool result.
Сам парсер по вызову восстанавливает владельца, но модель видит лишнюю смену роли.
Кроме того, у многострочных результатов не был проставлен транспортный отступ:
парсер выделял только первую строку результата, остальное становилось текстом
в искусственном сообщении ассистента. Это подтверждено на **4/336** строках
нового holdout; среди успешно разобранных TRAIN/DEV такого расхождения не найдено.

Подготовлен отдельный [v4_format_probe.py](../../scripts/v4_format_probe.py).
Он оставляет результат внутри сообщения вызвавшего его участника, экранирует
продолжения отступом, нумерует сообщения без отдельных tool results и не передаёт
метки/доказательства модели. Неоднозначные связи отвергает, а не угадывает.
Политика, JSON tools и тело текущего ответа сохраняются. Работающий train-v1
этим renderer не меняется; обучение на нём заново не запускалось.

Roundtrip сравнивался с **исходными событиями**, а не с выходом старого парсера:
1425 TRAIN, все 152 DEV и все 336 HOLDOUT прошли проверку. В четырёх holdout
восстановлено исходное содержимое многострочных результатов и роль пользователя.
33 TRAIN из ToolACE используют имена инструментов с пробелами, которые не
представимы текущей стрелочной грамматикой: probe их явно отвергает.
В 36 TRAIN JSON-каталог остаётся неполным из-за таких имён; эти числа относятся
к разным проверкам, поэтому не обязаны совпадать. Записи работающего TRAIN не удалены.
Для будущего выпуска данных нужна отдельная согласованная нормализация этих
имён во всех источниках либо другой проверенный dialect, без изменения gold.

## Score и контекст

- На реальном tokenizer Qwen3-4B-Instruct-2507 проверены шесть YES и шесть NO
  token IDs; множества не пересекаются и точно совпадают с START.json обучения.
  Положительная цель 1 соответствует YES. Признаков перевёрнутого знака не найдено.
- Обучение использует logsumexp(YES logits) − logsumexp(NO logits). Общая
  нормализация сокращается в этой разности. Числовая проверка синтетического
  вектора дала разницу 0; это не сверка реальных logits Transformers и vLLM.
- В receipts текущего 35B regression_r1 и valid46_r1 обрезаны истории **двух**
  строк, политика и текущий ответ сохранены. В dev_r1b таких обрезаний нет.
  Потеря прежнего согласия из истории возможна, но её влияние здесь не измерено.
- .40 — квота положительных среди оценённых строк, не вероятность нарушения.
  Hard может превысить квоту. Неполное покрытие scores требует отдельного контроля.
- В dev520 нет каталога и структурных tool calls, распознаваемых этим парсером.
  Поэтому улучшение схемного парсера само по себе не устраняет его основные FP:
  там нужны более точное семантическое решение и проверенные обучающие данные.
