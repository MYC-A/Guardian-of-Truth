# V6: ограниченная донастройка копии LoRA 35B — 20.10.2026

Протокол до новых optimizer updates и просмотра новых quality scores. Пользователь
разрешил коротко специализировать готовую LoRA; главный критерий — перенос на
реальные данные, не увеличение F1 на тренировочных близнецах. Private-прирост
этим offline-экспериментом не доказывается.

Источник: завершённая V5 LoRA SHA
`eb7cee08c0a00c29ad1d21904aa94d29f4f83f126d53e1438dd65ef85a34ba4f`,
1458/1458, 100 тензоров в 50 модулях последних 8 слоёв текущей AWQ 35B.
Исходный адаптер и база неизменны. Импорт всех тензоров проверяется экспортом
до обучения и точным сравнением. Новый optimizer, новая задача и новый бюджет
явно отличаются от resume старой эпохи.

## Данные и задача

64 пары / 128 строк только из frozen-v2 TRAIN. Выбор по seed20261020 и round-robin
domain/family/template, максимум4 пары на шаблон, не больше одной пары из исходной
group_id. У пары должны совпадать domain/family/template/split_component/group_id,
быть обе метки0/1 и непустой source proof. Для legacy принимается прежний
MECHANICAL_SOURCE_CHECKED; для native повторяется bounded predicate audit по
истории/сохранённому результату среды после обратного восстановления aliases.
Дополнительно проверяются parser/shape/schema корректного близнеца и точная
цитата governing rule в политике. Провал исключает строку, неполная пара затем
не допускается. Это повторение
проверенных ранее тренировочных контрастов, не новые независимые данные и не
дополнительная человеческая проверка. Неполные пары не допускаются.

Перед выбором verify_frozen проверяет все исходные SHA; выбранные TRAIN components
и IDs не пересекаются с DEV/HOLDOUT. Используется прежняя decontamination provenance,
не выдаваемая за доказанную семантическую независимость. valid46, dev520, seen397,
real191 и их карточки/новые мутации не добавляются в TRAIN. Никаких новых
автоматических меток по «всем ходам до первой ошибки».

Сохраняются политика, история, целевой ход и production hints; trimming TRAIN
запрещён. Перед исходным YES/NO вопросом добавляется неизменная verifier-инструкция:
проверять применимость, actor/turn, proposal/execution, точное согласие, но также
остальные самостоятельные основания нарушения. Она не содержит gold или названия
ошибки из TRAIN metadata. Одинаковый renderer у TRAIN и всех eval arms.
Не учим снимать обвинение по одному факту согласия или по отсутствию notes.
Банковских TRAIN-пар нет; это явный пробел, не основание обещать исправление banking.

## Обучение и технический допуск

Warm start r16/alpha32/dropout.05, только прежние100 LoRA-тензоров. Base frozen.
BCE exact logsumexp(YES)-logsumexp(NO), обе метки поровну; lr5e-6, AdamW .01,
clip1, accumulation8, warmup2 updates. Пары остаются вместе в batch, порядок
детерминированный. Один короткий проход128строк или максимум5400 секунд optimizer
wall. Неполный batch без update отбрасывается; committed rows отмечаются отдельно.
Чекпойнт после каждого update, export по завершении; без выбора checkpoint по gold.

Проверить finite loss/gradients и полную загрузку weights. Повторить допуск compiled
AWQ-dequant: weight parity и baseline/repeat/compiled gradient probe с тем же RNG,
прежний относительный numeric gate из V5. При отказе compiled использовать original,
не ослаблять gate. Смена backend/пакетов, подмена базы и routed-expert training
не допускаются. Техническая проба не делает optimizer updates.

## Оценка

На одних verifier prompts сравниваются base, исходная LoRA и новая копия. GPU worker
получает только id/token IDs/tokens/text hash; gold остаётся в отдельном INDEX.
Полная GPU-привязка50/50 обязательна для каждого адаптера с устранением только
подтверждённых shared-expert alias reset. Отказ binding или exact coverage — технический
провал, не NO и не повод считать classifier успешным. Входы1405 прежних eval строк
не содержат TRAIN; первыми оцениваются real191, затем dev520, затем valid46/DEV/остальные.
Повторы и пересекающиеся cohorts не складываются в независимые задачи.
До новых quality scores добавлены ещё два точных повторных измерения всех valid46
для каждой версии (всего3 измерения). Не подбирать по ним порог: публиковать SD
разностей/sqrt(2), max delta и число изменений решений при прежнем нулевом пороге.
Штатный APC включён; повторные задачи не считаются независимыми примерами.

Решение verifier фиксировано до результатов: score>0 означает нарушение, score<=0
снимает подозрение; hard сохраняются. Никакого добора до квоты, настройки порога
на valid46 или выбора лучшего из серии новых адаптеров. Отдельно обычные classifier
метрики всех arms и парное снятие FP/потеря TP. Для valid46 дополнительно используется
сохранённый пул .70 лучшего baseline с fixes. Этот score-only эксперимент не является
точным replay полного runtime ZIP; дополнительный вызов и общий конкурсный бюджет
должны измеряться до упаковки.

Минимальная offline-приёмка для рассмотрения интеграции: на real191 и dev520
по отдельности меньше FP без потери TP относительно той же base-verifier задачи,
а также отсутствие новой потери TP на valid46. Неудача на одном наборе не скрывается
общим средним; новая LoRA не продвигается по одному локальному выигрышу. Даже прохождение
этих exploratory-регрессий не доказывает независимый/private прирост. Существующие
наборы уже просмотрены, человеческая проверка недоступна: HUMAN_UNVERIFIED сохраняется.

## Проверенные внешние ориентиры

[CompliBench](https://github.com/UCSB-NLP-Chang/CompliBench) публикует близкий
turn-level compliance benchmark и оценочный harness. В просмотренном README нет
готового training-профиля для нашей AWQ 35B; оценка reward-model threshold там
допускает поиск по домену, который мы не переносим на protected valid46.

[PolicyGuard, June2026](https://arxiv.org/html/2606.29225v1) — отдельный от PolicyGuard-4B
диалоговый верификатор. Полезны авторитет исходной политики и advisory checklist;
описаны чрезмерные блокировки от жёсткого checklist и ухудшение переноса на retail.
Мы не копируем правило доверия только tool results на пользовательское согласие
и не выдаём их Pass4 за F1 нашего конкурса. Это ориентиры, не воспроизведённые результаты.

Уже готовый [PolicyGuard-4B](https://huggingface.co/Rakancorle1/PolicyGuard-4B)
обучен на иной базе Qwen3-4B-Instruct-2507 и policy–trajectory данных. Его веса
не являются адаптером к нашей35B. Новый большой download или замена runtime в
короткий warm-start пилот не включаются.
