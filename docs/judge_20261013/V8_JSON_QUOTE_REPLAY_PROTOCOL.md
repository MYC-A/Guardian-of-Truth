## Подтверждённая ошибка контракта

На dev520 из 333 непринятых обоснований новой LoRA: 322 UNSUPPORTED_QUOTE,
11 TRUNCATED. INVALID_FORMAT и явного UNKNOWN нет. У base: 308 неподтверждённых
цитат и 15 обрывов. Значит, объяснять весь результат только данными было преждевременно.

Политика хранится в JSON, например `"Phase 4": "Verify profile: ..."`.
Модель цитирует `Phase 4: Verify profile: ...`. Старая проверка буквального
вхождения в сериализованный JSON отклоняет это представление. При точном
сопоставлении декодированного строкового значения и его непосредственного ключа
источник подтверждён для **235 из 322** таких цитат новой LoRA и **259 из 308** base.
Нормализация одних пробелов не исправляет ни одну dev520-цитату этого типа.

Это подтверждает причину отклонения цитат. Это **не доказывает**, что вердикты
после исправления станут лучше или что новое дообучение полезно.

## Единственное изменение V8

Источник цитаты допускается как буквальный raw span, тот же span с изменением
только пробелов, строковое значение из однозначного JSON path либо
`непосредственный ключ + ': ' + декодированное строковое значение`.
Разрешена непрерывная часть такого source unit. JSON escape-последовательности
декодируются штатным JSON parser. Дублирующиеся ключи блокируют структурное доказательство.
Числа, идентификаторы, знаки препинания и отрицания не заменяются; fuzzy match,
смысловая перефразировка и склейка разных ветвей запрещены.

Source path/span сохраняется. Это проверка происхождения текста, а не истинности
обоснования или применимости правила. TRUNCATED и UNKNOWN не снимают обвинение.

## Замороженный проверочный прогон

Те же 757 original inputs, те же base/new weights, те же сохранённые V7 reviews,
тот же threshold=0, hard и отсутствие добора квоты. Новые reviews не генерируются.
Все принятые exact final scores пересчитываются, включая ранее принятые случаи;
scores не подставляются из старого запуска. Для valid46 — три измерения exact score
на **одном и том же сохранённом review**, а не три новых генерации review.

Сравниваются отдельно: влияние admission fix внутри каждого arm и новый адаптер
против base после одного и того же исправления. Gold не читается при подготовке
и не поступает GPU worker. Подготовка фиксирует SHA source reviews, final-token
inputs, parser и worker до scoring. Данные и веса не дообучаются и не изменяются.

Результат остаётся EXPLORATORY/HUMAN_UNVERIFIED. Это технический replay после
просмотра V7, не независимый новый тест. Старый gate показывается без подмены;
нулевые FP baseline отмечаются отдельно. Для принятия конечной системы всё ещё
нужен полный парный quality/time/coverage тест целевой сборки.
