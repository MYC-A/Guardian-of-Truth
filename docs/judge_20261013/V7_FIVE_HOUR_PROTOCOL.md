## Основная гипотеза

Сохранить исходную V5 LoRA неизменной. Основной новый кандидат учится не только
последнемуYES/NO, но короткому обоснованию с цитатой действующего правила,
проверкой условий и вердиктом. Это приближает обучающий сигнал к проверенному
[CompliBench SFT](https://arxiv.org/html/2604.12312v1#A3), но не является воспроизведением
их1400GPT-5-траекторий/3эпох. Наша source-grounded краткая rationale строится из
проверяемого oracle; чужая модель не определяет gold.

Новые исходно сконструированные policy/dialogue контрасты: условия применимости,
предложение/исполнение, actor/phase scope, ранее выполненные предпосылки,
исключения, точное согласие и его отзыв, другой объект/сумма, reason binding,
факт по последнему результату, завершение без результата. Стремиться покрыть
insurance/healthcare/airlines/banking/retail/telecom. Это явно synthetic closed-world
workflow examples, не настоящие native tau2 разговоры и не человеческая разметка.
Политику и диалоги не брать из eval и не мутировать их. Новые документы/IDs/сценарии,
контрфактические близнецы0/1, отдельный production-совместимый target turn.

Каждую метку повторно проверяет bounded source-oracle по фактическому history/
target и literal policy rule; положительный twin отличается одним определяющим
условием/действием. Все новые случаи проходят parser/schema, exact/near/name-ID
decontamination против regression_seen/compli_dev/compli_eval. Metadata/gold/
oracle/rationale не входят в model inputs. Сохранять ошибки и исключать пару целиком.
Автоматический аудит не объявлять человеческой проверкой или семантическим proof.

Сначала оценить TRAIN-кандидаты готовой моделью без gold в GPU worker; использовать
ошибки/малый margin для TRAIN-only hard-example mining, не для переметки.
Ограничивать domain/family/template и сохранять обе стороны пары. Добавить небольшой
source-checked replay старогоTRAIN для сохранения верных обнаружений. Порядок,
token lengths, input/output renderer и freeze SHA публикуются до optimizer updates.

## Параметры и время

Предпочтительный новый профиль: LoRA r16/alpha32 на attention+shared-expert проекциях
последних16слоёв, а не только8. Прежние50модулей/100тензоров импортируются точно,
добавленные модули начинают с нулевыхB; routed experts/base/router не обучаются.
Это наше ресурсное решение, не доказанное оптимальное распределение слоёв и не
all-linear MoE из [LoRA Without Regret](https://thinkingmachines.ai/blog/lora/).
При техническом отказе/неприемлемом прогнозе доupdates допускается прежний8-layer
профиль, с отдельным receipt. Выбор не использует eval quality.

Один основной SFT-кандидат, без quality-перебора архитектур/learning rate. Начальный
lr2e-5, dropout.05, AdamW .01, clip1, accumulation8, seed20261020; source base frozen.
Loss по токенам короткого source-grounded обоснования и вердикта; подробные tensor
alignment/answer-mask проверки обязательны. Бюджет обучения выбирается из
оставшегося deadline с резервом на native eval и off-box export. Полный проход
может быть не достигнут: публиковать committed rows/steps/epoch fraction.

## Оценка и принятие

Заморозить один и тот же новый verifier prompt/процедуру для base, исходнойV5LoRA
и основного нового кандидата. Краткая review + exact verdict score — отдельные
вызовы, их время учитывается; свободно сгенерированная метка не заменяет exact
logP(YES)-logP(NO). Привязка GPU всех новых модулей проверяется по source tensors,
без вывода по одним warnings. Учесть shared-expert aliases при новом числе слоёв.

На real191 и dev520 отдельно: TP/FP/FN/TN, F1/P/R, полученные/потерянныеTP,
снятые/добавленныеFP, conversation-group bootstrap95%CI. Сравнить как с base
verifier в той же роли, так и с замороженным исходным baseline отдельно указывая
overall-only versus best-ZIP open-review/MAX. На valid46 — регрессия и3измерения
decision stability, без настройки порога. UNKNOWN/invalid review сохраняет
исходное обвинение; hard защищены; после снятия обвинений добора в квоту нет.

Минимальный фильтр на рассмотрение интеграции сохраняется: меньшеFP без потерянных
TP на real191 и dev520 по отдельности относительно сравнимого base-verifier,
нет новых потерьTP на valid46. Point estimates без интервалов и source limitations
не выдаются за перенос. Все наборы ранее исследованы; HUMAN_UNVERIFIED/
EXPLORATORY сохраняются, private-прирост не измерен. Окончательный ZIP допустим
только после отдельного end-to-end quality/time/coverage контроля, не по факту
успешного обучения. Никаких обещанийF1.62 из локального числа.
