# V4: обучение завершено, перенос не подтверждён — 19.10.2026

LoRA улучшает базовую Qwen4B на подготовленных DEV/HOLDOUT, но фиксированная
смесь 35B + V4 не показывает устойчивого превосходства над 35B на прежних наборах.
В свежем GPU-прогоне valid46 смесь уступила 35B с теми же исправлениями.
По этим данным рекомендовать смесь как улучшение конкурсного решения нельзя.
ZIP смеси собирается по явному поручению пользователя как экспериментальный кандидат.

## Завершённое обучение и оценка

5102.83 с. LoRA r16/alpha32 на семи типах линейных проекций; адаптер
132187888 bytes, SHA256
`4b06ca6a09894b965a32bd7d3646bc559c88b1591a49ffe5d8213a05e0b14477`.
Это адаптер для 4B; он не переносится на 35B. В смеси работают два отдельных скорера.

Парная оценка base/adapter завершена: 2810/2810 exact scores. Отдельная 35B-оценка
новых DEV/HOLDOUT: 488/488 строк, 1567.89 с. Чекпойнт по holdout не выбирался.
Исходный RESULTS.json сохранён локально; его SHA и компактная сводка опубликованы в
[V4_FINAL_SUMMARY.json](v4_evidence/V4_FINAL_SUMMARY.json).

Все значения ниже — F1 при квоте .40. Левые три столбца используют прежнюю механику;
правые два добавляют bounded turn-shape к тем же сохранённым scores. Это CPU replay,

не складываются в общий независимый тест. Статус: EXPLORATORY, HUMAN_UNVERIFIED.

## Свежий GPU-прогон кода сборки

Runtime-код закреплён на `2365fdc3a9c0b2f294fada1eb7f78a798a1fb318`.
На A6000, в host venv, на ранее просмотренном valid46:

| Вариант | TP | FP | FN | TN | F1 |
|---|---:|---:|---:|---:|---:|
| Смесь 50:50 + fixes | 17 | 1 | 6 | 22 | .8293 |
| Те же scores 35B + те же fixes | 18 | 0 | 5 | 23 | .8780 |

Полный pipeline занял 696.77 с, обе модели дали 46/46 exact; использован именно
`rank_50_50`, без fallback. Стадия 4B заняла 164.38 с; процесс выгружен перед 35B.
Паритет 4B Transformers/vLLM: длины token IDs совпали на 46/46, Spearman .9962,
знаки scores 46/46, максимальная абсолютная разница .482 log-odds. Это разные backend
и вычисления, поэтому побитовое совпадение scores не заявляется.

Смесь в этом прогоне потеряла одно TP и добавила одно FP относительно 35B.
Исторические scores 35B дали .8293; свежие дали .8780. Поэтому свежая таблица содержит
контроль из того же прогона: историческое равенство не подменяет текущего сравнения.
Этот один повтор не устанавливает распределение шума или устойчивый прирост самой 35B.

Результаты: [GPU receipt](v4_evidence/V4_RELEASE_GPU_VALID46_DONE.json),
[4B parity](v4_evidence/V4_RELEASE_SECONDARY_PARITY.json).
Полный закрытый тест и время на конкурсной GPU не проверены. Это запуск runtime-кода
в host venv; исполнение всего упакованного runtime на GPU не заявляется.

## Решение

Механические исправления выглядят полезнее текущей V4-смеси на исследованных данных.
Повторять обучение на тех же шаблонах без разбора переноса оснований нет. Следующий
исследовательский шаг — парный разбор ошибок смеси против 35B на dev520 и группировка
по условиям применимости, согласия и истории; затем новые контрастные данные только
из train-источников. Текущий адаптер и измерения сохраняются без подбора по valid46.

Сборка ZIP, его SHA256 и независимая проверка будут записаны отдельно в release receipt.
