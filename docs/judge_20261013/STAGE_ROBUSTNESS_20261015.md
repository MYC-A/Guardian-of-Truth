## Что перенесено и дополнено

1. JSONL читается по LF. U+2028/U+2029/U+0085 внутри полей больше не делят одну
   запись на несколько; CRLF и пустые строки допускаются.
2. Ошибка первоначальной сборки, повторной сборки, варианта вопроса или подсчета токенов
   записывается для своей строки как `PROMPT_BUILD_ERROR`; остальные строки продолжаются.
   Неудачная группировка по политике только отключает оптимизацию группировки для этой строки.
3. Отклоненная пачка повторяется по одному запросу. Ошибка конкретного запроса получает
   `GENERATE_ERROR`. Если все повторы и известный проверочный запрос не работают,
   ошибка движка остается ошибкой стадии, а supervisor сохраняет существующий fallback.
   Текст проверочного запроса сохранен.
4. В дополнение к патчу проверяется время перед первоначальным вызовом пачки, каждым
   повтором и проверкой движка. После достижения дедлайна новый такой вызов не начинается.
   Уже выполняющийся вызов может закончиться позже: жесткая остановка остается у supervisor.
5. Неотправленные из-за дедлайна строки имеют явные записи `DEADLINE`, включая оставшиеся
   строки при остановке внешнего цикла. Добавлены счетчики `row_errors`, `group_errors`,
   `deadline_rows`. Повторная сборка использует тот же код ошибки и detail, что первоначальная.

Нормальный путь по-прежнему: прежний bounded context builder -> Qwen overall@on ->
primary score -> прежняя квота от оцененных строк. Квота, веса, exactness, сохранение primary
перед extras и выходной формат не менялись. Новых production-модулей нет;
`scripts/judge_stage.py` уже входит в CODE упаковщика.

## Проверки

Команда, с PYTHONPATH активного checkout:

```text
python -m unittest tests.test_transcript tests.test_judge_mechanical tests.test_judge_transcript_integration tests.test_judge_v3 tests.test_judge_stage_rows tests.test_evidence_packer -v
```

Windows, Python 3.13: 127 тестов, 124 passed, 3 skipped из-за POSIX process groups.
Пути импортированных prompting и judge_stage проверены: оба из активного checkout.
`git diff --check` проходит. Это целевой набор judge/transcript/packer, не все 323 тестовых
модуля исследовательского репозитория.

В workflow добавлен `tests.test_judge_stage_rows`: Linux проверяет также настоящий
supervisor и настоящую stage отдельным процессом с fake vLLM. До результата Actions
не считать этот Linux-прогон успешным; ссылка и статус сообщаются после push.

Новые регрессии проверяют реальные prepare_stage/read_jsonl/build_prompt, целостность
response до generate, literal/duplicate id, группировку, ошибки сборки/вариантов/токенизации,
отказ одного запроса в пачке и отдельно, поломку движка и границы дедлайна с управляемым временем.
Это проверка протокола и отказоустойчивости; fake engine не измеряет качество или GPU-скорость.

## Границы результата

**Доказано:** прежний splitlines ломается на файле настоящего prepare_stage с указанными
Unicode-разделителями; исправленный путь сохраняет три записи и текст. Изолированные ошибки
обрабатываются согласно тестам. Бинарный output при отказах остается обязанностью supervisor.

**Гипотеза:** были ли такие символы/ошибки в закрытом тесте и насколько они повлияли на F1.
Полного платформенного лога по-прежнему нет.

**Не проверено:** реальный A100/vLLM (`GPU_UNTESTED`), время полного запуска,
изменение F1. Полный ZIP и веса в этой работе не пересобирались и не проверялись заново.
U2, D4 и изменения production-парсера этим патчем не реализованы.
