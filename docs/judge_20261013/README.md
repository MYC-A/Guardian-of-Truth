# Guardian of Truth: single-pass judge (13.10.2026)

`python scripts/predict.py --input <test.parquet|csv> --output <predictions.parquet|csv>`

Выход `id,label`, id в исходном порядке. Читаются только `id, prompt, response`. Без сети, всё из архива
(встроенный рантайм vLLM 0.19.1 из прежнего проверенного архива).

## Почему так

- Платформенный каскад: F1 0.32448, P 0.26316, R 0.42308. Recall всех команд лидерборда кратен 1/130,
  значит в публичном тесте 130 ошибок из 548 (23.7%). Отсюда TP=55, FP=154, FN=75, TN=264: модель нашла
  42% ошибок и ложно пометила 37% чистых строк, это почти угадывание. valid46 сбалансирован 50/50,
  поэтому любой порог, подобранный на нём, на тесте даёт лишние «1».
- Топ лидерборда: P около 0.61, R около 0.63, «1» стоит у 25-34% строк. Это обычный приличный
  классификатор, а не что-то недостижимое.
- Скорость определяется чтением контекста моделью. 27B dense на A100 не прочитает ~548 строк
  по ~12K токенов за отведённое время даже без генерации. FP8/AWQ на A100 чтение не ускоряют.
  Поэтому: MoE с ~3B активных параметров, один проход на строку, без генерации текста.

## Как работает

1. **Механика (CPU, секунды)**, `src/guardian_truth/judge/mechanical.py`.
   Железные «1»: инструмента нет в каталоге; нарушена схема (обязательное поле, тип, enum);
   аргументы не объект; id в аргументах, которого нет нигде в контексте; явный запрет политики
   на несколько вызовов или на текст плюс вызов в одном ходе; узкий date-gate.
   Подсказки для модели (меток не ставят): числа, которых нет в данных и которые не получаются
   простой суммой, разностью или кратным; id в тексте, которых нет в контексте; «сделал» без вызова;
   отказ; передача человеку; повтор прежнего вызова.
2. **Судья (GPU, один проход)**, `scripts/judge_stage.py` + `prompting.py`.
   Системное сообщение с определением галлюцинации из правил соревнования, затем исходный prompt
   как есть (политика и инструменты в начале, общие для домена, кэшируются), проверяемый ход,
   подсказки, вопрос. Оценка = P(YES) первого токена. Длинные строки режутся с середины:
   системный блок и последние ходы целиком, из середины сохраняются строки с id из ответа.
   После первых чанков измеряется скорость и подбирается лимит токенов на строку так,
   чтобы успеть оценить все строки.
3. **Решение**, `decision.py`: все железные «1» плюс верхние `positive_rate` (по умолчанию 30%)
   оценённых строк по рангу. Порога вероятности нет.
4. **Надзор**, `scripts/judge_submission.py`: стадия в отдельной группе процессов, файл ответов
   перезаписывается атомарно каждые 20 с, новые чанки не начинаются после 23 мин, стадия убивается
   в 25.5 мин, сторожевой выход в 28 мин. Если модель не дала ни одной оценки, файла нет
   и код выхода ненулевой: платформа не засчитывает попытку.

Настройки: `JUDGE_CONFIG.json` (в архиве в корне).

## Порядок действий

0. Модели (на сервере с A100):
   ```
   huggingface-cli download cyankiwi/Qwen3.6-35B-A3B-AWQ-4bit --local-dir models/qwen36-a3b-awq
   huggingface-cli download cyankiwi/Qwen3.5-35B-A3B-AWQ-4bit --local-dir models/qwen35-a3b-awq
   ```
   Запишите commit каждой модели со страницы HF: он нужен сборщику.
1. Тесты (CPU): `PYTHONPATH=src python -m unittest tests.test_judge_mechanical -v`
2. Механика на valid (CPU):
   `python scripts/eval_judge_valid.py --input valid.parquet --mechanical-only --out runs/mech`
   **Ворота:** `hard_rows_on_label0` = 0. Если срабатывает `unknown_identifier` на строке с меткой 0,
   поставьте `"hard_unknown_identifier": false`: проверка станет подсказкой.
3. Выбор модели (GPU), для каждой из двух:
   `python scripts/eval_judge_valid.py --input valid.parquet --model models/qwen36-a3b-awq --python <archive>/runtime/python/run_python.sh --out runs/q36`
   Сравнивать `auc_judge` и `auc_with_mechanical`. Ориентир: Granite на коротком контексте давал
   AUC 0.794. Берём модель с большим AUC; при разнице меньше 0.02 берём Qwen3.6. `f1_at_rate`
   на valid (50/50) смотреть при 0.40-0.50; `best_threshold_in_sample` оптимистичен.
4. Скорость (GPU), выбранная модель:
   `python scripts/eval_judge_valid.py --input valid.parquet --model <dir> --python <run_python.sh> --timing-rows 560 --seconds 1380 --out runs/timing`
   **Ворота:** `scored` = 560, `total_wall_seconds` < 1400. Посмотрите в `stage.log` события `cap`:
   если лимит упал ниже 16000 токенов, можно попробовать `"engine_overrides": {"enforce_eager": true}`
   (быстрее старт) и `max_num_batched_tokens` 32768, и повторить замер.
5. Сборка ZIP (источник: прежний проверенный полный архив с рантаймом, тот же, что для каскада):
   ```
   python scripts/build_judge_submission.py --source-zip <full.zip> --source-sha256 <sha> \
       --model-dir models/qwen36-a3b-awq --model-id cyankiwi/Qwen3.6-35B-A3B-AWQ-4bit \
       --model-revision <commit> --output judge-q36.zip
   ```
   Сборщик выбрасывает все прежние веса, проверяет каждый файл и лимит 40 ГБ.
6. Сквозная проверка архива на A100: распаковать, `pip install .`,
   `python scripts/predict.py --input valid.parquet --output /tmp/p.parquet`.
   В логе должны быть строки `GUARDIAN_JUDGE mechanical`, `progress`, `final` с `scored` = 46.
7. Сабмит. По P и R с лидерборда: TP = R x 130, FP = TP / P - TP. Пришлите эти два числа.
8. Следующий сабмит меняет только `positive_rate` (например 0.27 или 0.33), если TP/FP показывают,
   что меток слишком много или мало.

## Что не входит

B2, blind-проходы, длинные рассуждения, Granite, асинхронные воркеры, RLM и формальные переводчики.
Они либо не помещаются во время, либо не показали переносимого прироста.
