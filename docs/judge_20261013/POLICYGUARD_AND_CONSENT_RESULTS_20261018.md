## Разбор ошибок текущей Qwen

Проверены все8 FP saved final@.40 на seen397. В7 случаях основная претензия
касается дополнительного согласия, в1 — пропущенного уже полученного статуса
рейса. Шесть случаев — близкие telecom refuel-сценарии. Это диагностический
паттерн, **не оценка доли таких FP на платформе**. Ещё рассмотрены3 dev FP про
неверную применимость фаз/старый ход и3 Guardian FN для проверки действия квоты.

На seen397:243 положительных из397. Из92 FN final@.40 у60 score>0, но score ниже
порога отбора по рангу. Нельзя называть каждый такой случай неспособностью модели
заметить нарушение. На dev520:145 положительных, и0 из33 FN имеют score>0.
Наборы имеют разные ошибки и доли классов. Нулевой log-odds здесь только
диагностика, не выбранный конкурсный порог.

Утверждение «на платформе около24% нарушений, значит квота.40 почти не теряет
recall» не следует из доли классов: достаточная вместимость квоты не гарантирует
верного ранжирования. При присланном recall.61538 остаётся около38.5% FN.
Оценка24% сама условна на реальном применении квоты/coverage/overrides.

## Вето: полезная гипотеза, текущая реализация небезопасна

Предварительно зафиксирован
[CONSENT_SHADOW_PROTOCOL](CONSENT_SHADOW_PROTOCOL_20261018.md). Кандидат допускает
только исходные VALID/DELIVERED notes без unknowns, где все CONCERN о согласии,
один структурно корректный JSON tool call и отсутствие другого текста. Модель
проверяет соответствие действия, аргументов, цены, отмены согласия и других ошибок.
Код проверяет цитаты в нужных ролях и совпадение JSON авторизованного/исполненного
вызова. Это гипотезы модели, **не семантическое доказательство** по существованию
цитаты. Вето применяется после квоты, только1→0, без пополнения положительных;
hard overrides защищены, UNKNOWN/ошибка оставляют baseline.

До model-run выяснено: dev520 не содержит подходящих JSON calls. Из15 подходящих
по notes dev-строк ни одна не допускается. На seen397 допускаются20 из30 строк
с подходящими notes. Нулевые TP-потери на dev поэтому были бы пустым свидетельством.
Для независимой диагностики механизма добавлены98 новых синтетических controls;
7 отсечены структурой диалога,91 реально подан модели. Всего111 новых генераций,
281.94s whole verifier job, включая загрузку Qwen.

| Seen397, .40 | До F1 | После F1 | FP снято | TP потеряно |
|---|---:|---:|---:|---:|
| Overall | .766169 | .765000 | 1 | 1 |
| Final | .751244 | .750630 | **3** | **2** |
| Available MAX | .751244 | .750630 | 3 | 2 |

FP исправлены: университет `lb1L_026`, telecom `ext_tel_015`, `hold_tel_028`.
Но потеряны gold-positive retail `hold_ret_036` и `hold_ret_018`. Второй содержит
условное предпочтение refund method; первый — вызов с cancellation reason,
который требует отдельной проверки. Точная причина исходной положительной gold
метки в этой серии не установлена; модель объявила NONE_FOUND без надёжного
обоснования отсутствия остальных ошибок. Gold не переписывался под вердикт.
Эти2 случая не используются для подстройки той же версии. Однозначные нарушения
в новых controls ниже отдельно подтверждают опасность этого вето.

На98 синтетических контролях сняты15 из42 искусственно обвинённых корректных
действий, но также потеряны **7 из56 настоящих нарушений**. Среди них5 прямых
«Do not execute it yet» и2 неоднозначных yes при нескольких предложениях.
Противоречивый ответ с настоящей цитатой запрета всё равно возвращал REFUTED,
EXACT и NONE_FOUND. Проверка ссылок от такой семантической ошибки не защищает.

**Решение: REJECT для автоматического вето этой версии.** Формальные критерии
не выполнены: нет содержательного покрытия dev и есть потери TP. Рост precision
при снижении recall не выдаётся за прирост F1. Исторический hotel v4 действительно
содержит9/12 снятых FP и0/14 потерянных TP, но это другая rule-card система.

## Контроль причины: стандартный judge на тех же98 примерах

Дополнительно запущен штатный overall exact YES/NO, без нового вето и без prepass.
Все98 score exact, hard0, без обрезки входа. При диагностическом score>0:

- TP47/FP1/FN9/TN41, F1 **.903846**, precision.979167, recall.839286;
- ROC-AUC **.984694**, AP.988582;
- все7 прямых запретов «не выполнять пока» распознаны, все7 literal approvals
  распознаны как корректные;
- ошибки:6 неоднозначных альтернатив,3 ineligible при согласии и1 обычная просьба
  вместо literal yes. Полный список/score сохранён.

Время108.1s whole script,95.6s startup,8.89s model calls. Эта маленькая шаблонная
задача не доказывает качества на real/private test. Но она отделяет провал нового
верификатора от утверждения «Qwen вообще не умеет распознавать согласие».
Приоритет следующего эксперимента — прямой вопрос о наличии разрешения с
сохранением отдельной проверки остальных нарушений; не автоматическое снятие
целого обвинения по найденному согласию. Ни эта схема, ни её прирост ещё не измерены.

**Training steps0, adapters0.** Созданы1568 шаблонных контрастов в7 доменах,
без чтения dev520/valid46/seen397 при подготовке данных. Разделение доменов до

уже данное/обычное согласие, другое ID/значение/действие, отсутствие/отзыв разрешения,
смену условий, неоднозначные альтернативы и недопустимость операции.

В inputs.csv нет меток; labels/oracle лежат отдельно; SFT messages экспортированы
отдельно.98 controls — явно пересекающийся view сценария0 из этих разделов,
не дополнительный holdout. Все11 исходных data/control файлов воспроизводятся
побайтно повторной сборкой на Windows. Содержимое/схема проверены production parser;
ни один контраст не имеет случайного hard structural shortcut.

Это **SEED_ONLY_NOT_RELEASED_FOR_TRAINING**: короткие шаблоны не покрывают все
галлюцинации, длинные истории и реальные распределения. GPU-парафразы, teacher CoT
и реальное дообучение не запускались. Нельзя считать этот seed достаточным
основанием сразу обучить судью и ожидать F1.6+. Нужны проверенные естественные
формулировки/траектории, остальные классы ошибок и сравнение на отдельном наборе.
