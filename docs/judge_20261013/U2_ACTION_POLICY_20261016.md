# U2: якорь «действие -> политика» и опции dense, v3 (16.10.2026)

## Дополнительные исправления локальной интеграции

Поверх присланного V3 добавлены:

- Прямые лексические совпадения действия с заголовками имеют приоритет перед совпадениями
  по синонимам. Синонимы рассматриваются для действия только при отсутствии прямых кандидатов.
  `match_kind` в диагностике различает `exact` (с учётом прежнего сравнения основ слов),
  `synonym` и `none`. Это вид поиска, а не доказательство применимости правила.
- Резерв якоря сначала обходится по кругу между прямыми совпадениями; дополнительные
  синонимные разделы используют оставшийся резерв. Это устраняет найденное вытеснение
  условий отмены при добавлении синонимного раздела изменения рейса. Полнота всех правил
  при ограниченном контексте всё ещё не гарантируется; итоговое покрытие сообщается отдельно.
- Каждый возвращаемый кусок для реального энкодера обязан помещаться в его окно. При
  невозможности вместить минимальный кусок возникает `EncoderWindowError`; строка
  повторно собирается обычным U2 с именованным `dense_fallback`. Короткий кусок не даёт
  права молча обойти токенную проверку.
- Добавлены регрессии на повторяющиеся реплики с точным адресом второй цитаты, приоритет
  прямых разделов при добавлении синонимов, невозможное окно и длинный путь заголовков
  с сохранением последнего утверждения на настоящем MiniLM.

Рекомендуемый экспериментальный профиль по-прежнему без синонимов. Исправление известного
случая не является оценкой обобщающей способности или основанием включить их в основной
профиль. Конфигурация production по умолчанию остаётся `legacy`.

База: `9573f9b05f25b16740ca9be0a5126e518b49ce62` (код совпадает с `6d70314`; 9573f9b0 добавил только аудит).
Все опции **выключены по умолчанию**: без новых ключей `u2` и `u2_dense` дают прежний пакет (аудит 9573f9b0:
46/46 одинаковых хэшей контекста для v1). `JUDGE_CONFIG.json`, модель, ревизия, overall@on, `positive_rate=0.30`,
exact scoring и один вызов модели на строку не меняются. Новых модулей нет, состав ZIP прежний.

## v3: исправления по проверке v2

| Находка проверки v2 | В v3 |
|---|---|
| С `action_synonyms` dense_v2 на строке 6 снова вытесняет условия отмены; без синонимов они на месте | `dense_v2` **без** синонимов. Синонимы остаются выключенной опцией и только диагностическими плечами (`diag:*`). Не включать в A/B |
| Тест настоящего энкодера требовал больше двух окон от `_windows`, который сам обрезает до двух | Исходные окна считаются токенизатором (`return_overflowing_tokens`), `_windows` проверяется на ровно `max_windows` |
| Смещения повторяющихся цитат восстанавливались поиском по тексту и могли указать на первую из одинаковых реплик | `context_for(..., with_spans=True)` отдаёт смещения из самого пакера (те же `merged`, по которым рендерится текст); поиск по тексту удалён. По умолчанию ключа `spans` в записи нет |
| Длинный путь заголовков может сам переполнить окно | Явный откат: внешние заголовки снимаются по одному, пока в окне не останется места для 32 символов текста; ближайший заголовок держится дольше всех, в конце префикса нет. В пакете `dense_windows`: `queries`, `unfit_queries`, `passages`, `unfit_passages`, `prefix_trimmed_units`; невлезшее считается, а не прячется |

Причина регресса синонимов в присланном V2 (воспроизведена в локальном аудите): с ними `update_reservation_flights`
находит «Modify flight», и при том же резерве деление по кругу отдаёт половину его изменению рейса, и условия
отмены уже не влезают. Локальное усиление V3 выше ставит прямые совпадения первыми, чтобы дополнительный
синонимный раздел не отнимал их резерв. Недостаток места для нескольких прямых разделов всё ещё возможен:
это риск фиксированного резерва, видимый в `final.coverage` и `missing_text`.

## Опции

| Ключ стадии | Флаг `u2_context` | Поле `PackerConfig` | Что делает |
|---|---|---|---|
| `u2_action_policy: true` | `--action-policy` | `action_policy` | RANKED-политика: защищать разделы, чей путь заголовков называет вызванное действие |
| `u2_action_synonyms: true` | `--action-synonyms` | `action_synonyms` | **Не рекомендуется (v3).** Вместе с предыдущим: глагол совпадает с общей группой синонимов |
| `u2_dense_fusion: "remainder"` | `--dense-fusion remainder` | `dense_fusion` | Dense упорядочивает только фрагменты без lexical/entity/recency, после них |
| `u2_dense_scope: "policy"` | `--dense-scope policy` | `dense_scope` | Векторизуется только политика |
| `u2_dense_query_chars: 400` | `--dense-query-chars 400` | `dense_query_chars` | Запросы режутся по предложениям, затем до одного окна энкодера |
| `u2_dense_passage_pieces: true` | `--dense-passage-pieces` | `dense_passage_pieces` | Фрагмент политики оценивается по лучшему куску размером в одно окно |

Выбранные опции пишутся в стартовое событие и каждую запись пакета (`packer_options`) и в событие стадии `packets`
(`u2_options`). В записи строки: `action_policy` (по каждому действию статус, `coverage`, `missing`,
`missing_spans`), `action_anchor` (статус попытки) и `action_complete`.

## Правило якоря

1. Термины из имени вызванного в проверяемом ходе инструмента (`_ - .`, camelCase, без стоп-слов); первый термин = глагол.
2. Кандидат: markdown-заголовок политики, в пути которого (он и предки) есть глагол или, с `action_synonyms`,
   член его группы. Счёт = 1 + число остальных терминов в пути.
3. Лучший счёт побеждает; предок поглощает потомков-победителей. Счёт ниже `min(2, терминов)` принимается только
   при единственном кандидате. Больше 2 победителей: `AMBIGUOUS`.
4. Блоки под победителем (с подразделами) идут в резерв `action_policy_share` (0.5 остатка доли политики) по кругу
   между действиями; родители и управляющие абзацы добавляет замыкание пакера.
5. После сборки пакета: `final` по каждому действию. Якорь гарантирует попытку и честный отчёт, но не полноту:
   при нехватке бюджета будет `PARTIAL` или `NONE` с перечнем отсутствующего.

## Что проверено и что нет

**ДОКАЗАНО (песочница автора, CPU, без checkout):** логика v2 на копии разбиения политики `6d70314` и на
реконструкции airline-политики по текстам из аудита: при `book_reservation` + `cancel_reservation` и резерве на
6 блоков v1 давал отмене 0 блоков, v2 даёт каждому действию по 3; с синонимами `update_reservation_flights` /
`_baggages` / `_passengers` находят «Modify flight» / «Change baggage and insurance» / «Change passengers»,
а `modify_user_address` в retail по-прежнему пропускается как слабое совпадение. `fit_pieces` на 400 x U+6F22 с
моделью «1 символ = 1 токен» даёт 4 куска по 100. Скрипт применения прогнан на каркасах с настоящими якорями.

**НЕ ПРОВЕРЕНО автором:** тесты на настоящем коде (в т.ч. `RealEncoderWindow` с настоящим MiniLM), поведение
на `valid.parquet`, время dense_v2, Linux CI, любой прогон Qwen и F1.

**ГИПОТЕЗЫ:** справедливый резерв вернёт условия отмены в строке 3; синонимы заметно сократят 25 ABSENT без
новых ложных разделов; запросы в одно окно и куски политики улучшат dense-отбор. Это проверяется `diffs.jsonl`
(все изменения в обе стороны), а не отдельными удобными строками.
