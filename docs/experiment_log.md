# Журнал измеримых экспериментов

Завершён [контроль одного цикла UNKNOWN](uncertainty_experiment.md): на 12 заранее выбранных
строках initial F1=0,5455, directed=repeat=0,5000; +1 FP, без исправленных FN. Цикл выключен.
Разбор исходных причин — [V2 baseline](v2_baseline_error_analysis.md);
доставка контекста — [offline reader-абляция](reader_selection_ablation.md).
Также закрыто [сравнение текущих graph/RLM](v2_modes_closed.md): на 8 строках F1=0,75/0,5714,
одно расхождение из-за HTTP-сбоя; RLM ни разу не запросил дополнительный источник.

Следующий завершённый опыт V2: [строгие claims против общего verdict, все 46 строк](claim_gate_ablation.md).
F1 обоих вариантов 0,6667; ослабление проверки даёт +1 TP и +2 FP, поэтому strict сохранён.

Рабочий `valid.parquet` уже изучен и не является закрытым тестом. Пороги по нему не настраиваем.
Метки в модель не передаются. Результаты ниже относятся к конкретным сохранённым запускам,
а не к гарантированной точности на неизвестных данных.

## Приоритеты после первого живого подключения

1. **Довести доставку контекста до модели.** У исходного прямого режима 6 из первых 8 запросов
   отвергнуты по размеру; сравнивать качество рассуждения на таких ответах нельзя.
   Минимальная гипотеза: ограничить не только свидетельства, но и служебные описания,
   разрешить RLM заменять фрагменты заполненного пакета.
2. **Проверить цену атомаризации и проверки ссылок.** Модель может вернуть полезный общий вывод,
   но неверно оформить одно основание; сейчас это обнуляет весь смысловой результат.
   Нужна отдельная абляция простого смыслового классификатора и контура claims,
   без превращения неподтверждённых слов модели в точные нарушения.
3. **Каскад после точного нарушения.** Если окончательная метка уже 1 по точной проверке,
   смысловой запрос не нужен для классификации. Проверить экономию запросов и неизменность меток.
4. **Типизированные переходы и поиск опровержений.** Пока ниже в списке: без устойчиво работающего
   смыслового контура дополнительный граф не исправляет основной источник пропусков.

Это качественное ранжирование, а не выдуманные проценты ожидаемого прироста.

## Автономная база

Все 46 строк: TP=6, FP=0, FN=17, TN=23; precision=1, recall=0,261, F1=0,414.
Проверены источники, правила и планировщик; графовые совпадения сами не превращаются в нарушения.
Артефакты: `outputs/final_base.csv`, `outputs/final_base.jsonl`, `outputs/final_base_run.json`.
40 ответов используют технический fallback, а не доказательство корректности.

Синтетический резерв: 51 строка из 3 групп, TP=12, FP=0, FN=3, TN=36, F1=0,889.
Это тест механизмов, не оценка конкурсного качества. См. `outputs/synthetic_models_verified/`.

## Подключение Groq: установленная причина сбоев

Ключ из сохранённого `.env.example` принят: `GET /openai/v1/models` → HTTP 200.
Стандартный `Python-urllib` получил HTTP 403; тот же запрос с `User-Agent: guardian-truth/0.2`
прошёл с HTTP 200. Ранее транспорт ошибочно объединял 401 и 403 в `authentication`.
Теперь `forbidden`, `request_too_large` и `model_or_endpoint_unavailable` различаются отдельно.
Серверные тела ошибок и ключи в отчёт не включаются.

`llama-3.3-70b-versatile` отсутствовала в списке моделей этого ключа и вернула HTTP 404.
`openai/gpt-oss-120b` и `openai/gpt-oss-20b` успешно выполнили небольшие JSON-запросы.
Основной эксперимент использует явно зафиксированную `openai/gpt-oss-120b`.
Актуальность доступных моделей проверяется по API, не предполагается из старого примера конфигурации.

Precision на этом срезе 1, recall 0,333. Изменений FP/FN относительно автономной базы на том же срезе нет.

Эти прогоны не используются для выбора порога или утверждения превосходства RLM.

### Почему одного уменьшения исходных фрагментов недостаточно

При пакете 6000 символов описание графа занимало до 14038 символов, каталог — до 6579.
В трёх запросах граф оказался больше исходных свидетельств. Теперь суммарные метаданные ограничиваются
половиной бюджета свидетельств, максимум 6000 символов; обрезание помечается явно.
Полный граф и все фрагменты остаются локально доступны для поиска.
После исправления метаданные первых 8 запросов занимают 814–2921 символ,
сериализованный пользовательский пакет — 6433–11226 символов. Это измерение объёма, не точная токенизация.

Замена фрагментов включается только `--rolling-evidence`; по умолчанию отключена до подтверждения пользы.
Удалённый из текущего пакета источник нельзя цитировать. Все запрошенные вместе и поместившиеся фрагменты
защищаются от вытеснения в рамках одного запроса чтения. Исполняемых команд модели нет.

### Итог `live_bounded_120b`

| Режим | TP / FP / FN / TN | Precision | Recall | F1 | Смысловых оценок |
|---|---|---:|---:|---:|---:|
| graph | 2 / 1 / 1 / 4 | 0,667 | 0,667 | 0,667 | 4 из 8 |
| rlm + замена окна | 2 / 2 / 1 / 3 | 0,5 | 0,667 | 0,571 | 4 из 8 |

У graph исчезли отказы по размеру запроса. У RLM две строки достигли общего предела 360 секунд,
ещё одна генерация усечена. Это не ресурсно полное сравнение качества; RLM **не выбран лучшим**.

Проверка конкретных изменений graph:

- `airline__21::t7`: FN → TP. Но объяснение модели частично неверно: она объявила отсутствующей
  реально существующую бронь. Эталонная ошибка относится к платному багажу и подтверждению обновления.
  Совпадение метки не подтверждает правильность построенного основания.
- `airline__24::t14`: TN → FP. Модель объявила оформление неподтверждённым, потому что результат
  инструмента с нужной бронью не попал в пакет. Ненайденное в отобранном контексте ошибочно принято за ложное.

Решение: транспортные исправления и ограничение метаданных сохраняем как устранение установленных
технических сбоев, **не как доказательство прироста обобщающего качества**. Замену окна оставляем
выключенным по умолчанию экспериментом. Усложнение графа и «скептик» пока откладываются.

### Следующая минимальная проверка: приоритет явной сущности

Добавлен общий поиск источников с точным непреобразованным идентификатором из ответа
(`*_id` / `*_number`), до широкого поиска по общим словам. При отсутствии такого совпадения
приоритет получает последний результат инструмента. Это ранжирование, не доказательство владения
или актуальности. Имена доменов и строки `valid` в механизм не включены.
Тест переименовывает идентификаторы и добавляет объёмные нерелевантные фрагменты; регистр ID сохраняется.

На диагностическом повторе `airline__24::t14` исходная запись теперь действительно попала в пакет.
Метка стала 0, но через **fallback**: модельный вывод был отклонён из-за опоры одного claim только
на ответ. Поэтому нельзя сообщать о надёжно исправленной смысловой проверке.
Полный живой повтор 46 строк и независимое измерение этой правки ещё не выполнены.
Следующая содержательная абляция — простой независимый смысловой вывод против обязательных claims,
с одинаковым поиском и ресурсом. Проверка должна учитывать не только F1, но и качество оснований.

После всех правок автономный прогон 46 строк сохранил TP=6, FP=0, FN=17, TN=23.
Новых детерминированных FP/FN нет. Проходят 175 автотестов.

## Ресурсные ограничения

В наблюдавшемся ответе HTTP 413 причина связана с TPM и размером запроса, не с авторизацией.
В [публичной таблице Groq](https://console.groq.com/docs/rate-limits) для выбранных моделей указаны
8K TPM и 200K TPD свободного тарифа; фактические ограничения организации могут отличаться.
Увеличение локального `--seconds` не повышает квоту провайдера. Автоматической покупки лимитов нет.

Для переноса подготовлен отдельный [резерв RAGTruth](external_validation.md), но живые результаты
на нём пока не получены. Его test не просматривался ради исправления примеров `valid`.
