# Frozen pilot protocol

The first pilot uses four newly authored families, two development and two
family-held-out, with eight contrasts each (32 cases). Splitting is by family
before constructing variants. Gold relations and decisions are authored from
the source policy before obtaining any model answers. This is an author-controlled
synthetic holdout, not an independently collected or externally blinded benchmark.
The historical 46 rows and System V2 sealed remain regression material.

Controls cover positive/negative prerequisites, lookup versus execution, rename,
counterfactual read effects, wrong identity, chronology, remote exception,
Boolean scope, unknown effects and a false success claim. Missing observations
stay UNKNOWN; explicit negative native observations may establish FALSE.

Main comparison: A0 contextual, A1 unchanged early graph, A2 candidate discovery
plus late local lowering, A3 additional independent target-to-original-policy
discovery plus the same lowering. All use the same selected model, temperature 0,
same complete source policy/catalogue and same available history. A1's internal
views and schemas are unchanged. A1 supports current native calls only: unsupported
prose cases are reported as scope exclusions, never mixed into call-only rankings.

Model replies cannot see gold, case IDs, family names, splits or expected metrics.
The scorer alone opens gold after prediction artifacts are saved. Prompts and
runner source, inputs, gold and options are hashed in a manifest before inference.
No post-holdout tuning of the confirmatory arms. Diagnostics after scores are
explicitly post-hoc and do not overwrite original requests or results.

First API model: `ministral-14b-latest`, using existing server credentials.
If unavailable, one availability probe per supplied endpoint/model; 401/402/403/
429 and transport errors stop that provider without retries. Other independent
work continues. No new credits, model downloads or server rental.

Hard pilot limit: 360 HTTP attempts, 1,000,000 provider tokens or conservatively
reserved unknown usage, 120 seconds/request. Every exact wire request is hashed
with endpoint category, model and configuration. Failed/reserved requests are
never retried automatically. Raw receipts and costs are saved before parsing.
Identical discovery requests across cases may be reused only by exact hash.

Report schema validity, source-address validity (not semantic support), discovered
gold source groups, extra false candidates, applicability/effect, formula/identity/
time errors, 3-way accuracy, coverage, decided accuracy, false ERROR, and UNKNOWN.
Binary ERROR→1, other→0 is an explicit abstention mapping; 3-way UNKNOWN remains
visible. Cost comparisons use real calls, tokens, latency and shared-cache reuse.
Dollar cost stays unknown unless the provider reports it or a verified tariff is
available; tokens do not imply a known bill.

Selection rule: retain a mechanism only if it improves measured errors without
unacceptable false accusations/cost. No architectural winner is guaranteed. Even
a perfect 32-case score does not establish generality.
