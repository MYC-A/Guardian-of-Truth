# Внешняя проверка фактической опоры: RAGTruth

Чтобы не ограничиваться 46 изученными строками и собственным генератором, добавлен отдельный импорт
[RAGTruth](https://github.com/ParticleMedia/RAGTruth), корпуса ответов с человеческой разметкой галлюцинаций.
Это проверка переноса фактической проверки, а не замена конкурсного теста с бизнес-политиками и инструментами.

Используем зафиксированную ревизию `c103204b9ce28d6bbad859304bf30de72b8ed8fe` официального репозитория.
Оригиналы скачиваются только по явному `--download`, в игнорируемую `outputs/`;
сохраняются текст лицензии репозитория и SHA-256 каждого файла. Производные тексты не включаются в пакет или образ.
Данные содержат материалы разных первичных источников; для дальнейшего распространения нужно учитывать их условия,
не считать лицензию кода универсальным разрешением на любые исходные тексты.

Правила адаптации зафиксированы до просмотра результатов модели:

- Сохраняем исходный `prompt` без объяснений и меток разметки.
- Берём ответы только с `quality=good`; усечения и отмеченные неверные отказы исключаем, не делаем отрицательными примерами.
- Метка 1 означает наличие хотя бы одного человеческого отмеченного фрагмента, кроме `implicit_true=true`.
  Авторы определяют `implicit_true` как фактически верное, но не упомянутое в контексте; это отдельный выбор адаптации,
  не тождество всем возможным определениям контекстной ошибки. [Описание полей](https://github.com/ParticleMedia/RAGTruth#dataset)
- Все ответы одного `source_id` остаются в одной группе. Исходный `test` не перемещаем в разработку.
- Из исходного `train` детерминированно выделяем calibration по хэшу источника; остальное остаётся train.
- Для небольшого резерва отбираем группы по хэшу, без отбора по меткам или поведению текущего детектора.

```powershell
python scripts/prepare_ragtruth.py --download --raw-dir outputs/ragtruth_raw --output outputs/ragtruth_reserved.jsonl --manifest outputs/ragtruth_manifest.json --max-groups-per-split 100
```

Подготовка не запускает LLM и не выводит содержимое закрытых примеров. Испытания импортёра используют отдельно написанные
мини-примеры, не просмотренные ошибки реального резерва. После фиксации версии можно выполнить:

Резерв подготовлен: 1785 ответов из 300 групп источников; train — 594, calibration — 593, test — 598.
Отдельные тестовые тексты и ошибки модели не использовались при разработке импортёра.

```powershell
python scripts/benchmark_models.py --input outputs/ragtruth_reserved.jsonl --output-dir outputs/ragtruth_run_01 --backend groq --baseline-mode direct --candidate-mode rlm --calibrate --max-requests 2500 --max-input-chars 20000000 --seconds 1500
```

Это пример командного интерфейса, не рекомендация сразу тратить весь бюджет: первый живой прогон должен быть небольшим.
Каждый вариант получает свой указанный предел запросов; отчёт отмечает исчерпание ресурса.
Сначала фиксируется конфигурация, затем оценивается calibration, подбираются пороги и только после этого оценивается test.
Предсказания, диагностика и интервалы сохраняются. Вызовы API учитываются вместе с повторами.

Ограничения: корпус публичный и мог присутствовать в предобучении модели; ручная разметка может быть неполной;
не проверяются все конкурсные определения существенности ошибки. После просмотра тестовых ошибок набор становится
изученным для нашей разработки. Положительный результат здесь — дополнительное свидетельство, не гарантия победы.
