# Qwen3.5 B2 on platform vLLM, 2026-10-13

Экспериментальный сабмит: Qwen/Qwen3.5-35B-A3B-FP8, фиксированная ревизия
9d1823d2dee688a6b25e77009dc727688c44936e. Полный legacy B2 сохранён: независимый
blind-проход, основной review, последующие компоненты и слои, прежний admission и
output recovery. Granite не используется. Историческое F1 0.619 / 16.8 строк/мин
относится к прежнему B2-бенчмарку с 64 слотами; качество этой новой сборки не измерено.

## Окружение

Используются установленные на платформе Python, Torch/CUDA, Triton и vLLM 0.19.1.
Собственного Python, libc, gcc, CUDA и vLLM в архиве нет. В комплекте небольшой
compat/site-packages с Transformers 5.8.0 и точным замыканием его зависимостей,
а также Pydantic/JSON Schema для B2. Эти файлы взяты из ранее проверенного рантайма
и сверены с его SHA256-манифестом. Overlay используется только этим процессом и
его дочерним сервером; глобальные пакеты платформы не перезаписываются.

Зачем overlay: журнал платформы показывал Transformers 4.57.1, который не
распознавал семейство qwen3_5. Лог также подтверждал системный vLLM 0.19.1 и
Torch 2.10.0+cu128 на A100 80GB. Настоящий запуск именно Qwen3.5 и нового overlay
на платформе/A100 пока не проверен. Интернет во время инференса не нужен.

## Настройки

- 16 параллельных задач B2, 32 слота сервера, контекст 32768.
- gpu_memory_utilization=0.88, вычисления BF16, KV auto (= dtype модели).
- Prefix caching, chunked prefill, CUDA graphs; max_num_batched_tokens=8192.
- language-model-only исключает мультимодальные входы и лишний vision-профиль.
- Xgrammar с disable_any_whitespace=true, thinking отключён в исходном адаптере.
- KV не квантуется дополнительно; speculative decoding и offload не включены.

Настройки выбраны без доступного GPU, поэтому ускорение не заявляется.

https://docs.vllm.ai/en/v0.19.1/configuration/engine_args/
https://huggingface.co/Qwen/Qwen3.5-35B-A3B-FP8

## Надёжность и время

Используются id/prompt/response. Внутренний ключ — позиция строки, повторяющиеся
и необычные id выводятся дословно в исходном порядке. CSV допускает большие поля;
Parquet определяется по содержимому. Выходной формат задаётся расширением.

Полный файл из резервных нулей записывается до старта модели и обновляется по мере
готовности строк. Поэтому серверная ошибка, технический сбой или истечение времени
сохраняют корректный бинарный файл. Уже полученные метки не теряются. Происхождение
каждой метки и DEFAULT_ZERO считаются отдельно; fallback не является подтверждением
отсутствия нарушения. Завершение процесса платформой может оставить последний
полный checkpoint. Невалидный вход, отсутствие места и принудительное уничтожение
до первой записи этим не исправляются.

Внутренний бюджет 1740 секунд от начала runner, включая чтение и запуск сервера.
Оставлена минута на внешнюю установку/импорты и финальную запись. 30 минут чистого
инференса не предполагаются. Остановка vLLM учитывает отсутствие pidfd в системном
Python: приватная группа процессов закреплена невостребованным дочерним лидером
до завершения очистки, как в успешной диагностической пробе платформы.

На stdout выводятся окружение, старт, количество выполненных строк, метки, owners,
резервные ответы и итоговый SHA256. Полные квитанции — во временной папке; итоговый
run-manifest также пишется рядом с выходным файлом. Доступность этого соседнего
файла в интерфейсе платформы не гарантируется, поэтому сводка дублируется в stdout.

## Запуск

```sh
python scripts/predict.py --input test.csv --output predictions.csv
```

Настройки могут быть явно изменены через --workers и --slots; это отдельный
неизмеренный профиль. Пакет для pip install . собирается без сетевых зависимостей.

Сборка скачивает фиксированные веса с официального Hugging Face, сверяет SHA256
каждого safetensors-шарда, упаковывает по одному файлу и удаляет только его временную
скачанную копию. Полная проверка ZIP сверяет SHA256, CRC, режимы, индекс шардов и
лимит 40 000 000 000 байт. CPU-тесты не заменяют GPU-прогон и оценку F1.
