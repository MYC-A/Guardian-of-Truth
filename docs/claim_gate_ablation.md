# Абляция проверки отдельных утверждений

## Проверяемая проблема

В живых опытах общий вердикт модели иногда отклонялся из-за одного некорректно
оформленного claim. Неизвестно, защищает ли это от FP или теряет больше TP.
Усложнять атомаризацию до ответа на этот вопрос нецелесообразно.

## Минимальный опыт

Одна генерация на пример, один набор контекста, одна модель, неизменный порог 0,5.
Два способа интерпретации одного и того же JSON:

- `strict`: прежняя проверка каждого claim, его ссылок, согласованности claims и verdict, плана.
- `overall`: те же проверки формата общего verdict/risk, диапазона score, наличия содержательного
  reason и допустимых ссылок на исходный prompt; без обязательной проверки списка claims/plan.

`overall` — модельная гипотеза, не формальное доказательство. Он не заменяет рабочий score автоматически.
Unknown, отсутствие общей опоры, противоречие verdict/risk и неполученный ответ остаются fallback.
Точные нарушения всегда имеют метку 1 и не требуют обращения к модели.

Это абляция **последующей проверки результата**, а не сравнение промптов с атомаризацией и без неё.
Генерация всё ещё запрашивает claims. Обнаруженный эффект нельзя приписывать самому разбиению ответа.

## Зафиксированный запуск

```powershell
python scripts/ablate_claim_gate.py --input valid.parquet --output-dir outputs/claim_gate_20b_full --backend groq --env-file .env.example --model openai/gpt-oss-20b --mode graph --max-evidence-chars 4800 --max-output-tokens 2048 --max-requests 120 --max-input-chars 3000000 --seconds 1800 --retries 3
```

Весь `valid`: 46 строк. Конфигурация, хэши исходников и входа сохраняются до вызовов API.
Ключ, id, label и explanation не включаются в модельный запрос.
Бюджет един для обеих интерпретаций, поскольку используется одна генерация.
Уменьшенный пакет выбран для ограничений API, не по эталонным меткам.

`configuration.json` содержит фактическую конфигурацию, `audit.jsonl` — каждую обработанную строку,
оба решения и проверенные общие основания, `report.json` создаётся после завершения.
Отчёт сравнивает все строки, включая fallback; отдельно показывает покрытие и ошибки.
Парный bootstrap использует 45 групп траекторий, но не превращает изученный valid в независимый тест.

Автономный пробный прогон выполнен: оба варианта дают TP=6, FP=0, FN=17, TN=23,
F1=0,413793. Изменений меток нет, пропущено 6 ненужных для классификации смысловых запросов.
Живой запуск начат; до его окончания вывод о пользе `overall` не делается.

## Критерий решения

Сопоставить F1, precision/recall, изменения TP/FP/FN/TN, причины новых FP и потерянных TP,
долю модельных оценок и транспортных сбоев. Даже положительный результат на valid — только
основание для отдельной проверки переноса, не для настройки многочисленных исключений.
Если эффект отрицательный — сохраняем строгий рабочий контур, эксперимент не включаем в классификацию.
