# Полная архитектура E2E-системы Guardian of Truth (E2E V1)

- **Документ:** полная архитектура, детальное описание каждого модуля и каталог краевых случаев E2E-системы (реализация агента E2E-agent-2).
- **Базовый коммит кода:** `4fa2212` (E2E V1 — терминальное решение `KEEP_CONSERVATIVE_E2E`), поверх `4d7fdfb` (замороженная многофронтендовая архитектура).
- **Ветка:** `E2E-agent-2`.
- **Код:** `src/guardian_truth/vnext/e2e/` — 21 модуль, ~4 000 строк; тесты: `tests/e2e/` — 31 тест (все зелёные).
- **Семантический бэкенд (эксперимент):** BAI `qwen3.8-flash`, temperature 0, ровно одна семантическая попытка на вход.

## 1. Назначение системы

Guardian E2E V1 — это **доказательный верификатор траекторий ИИ-агента**. На вход подаётся полная траектория: системная политика, запрос пользователя, история с вызовами инструментов и их результатами, целевой ответ ассистента (текст + предпринятые действия). Система возвращает один из четырёх статусов:

| Статус | Значение | Условие |
|---|---|---|
| `PROVED_ERROR` | Доказано нарушение | В **каждом** допустимом мире существует хотя бы один сертифицированный ложно-истинный предохранительный свидетель (свидетель может различаться по мирам) |
| `PROVED_NO_ERROR` | Доказана безопасность | Каждый допустимый мир безопасен **и** выполнены все посылки замыкания (покрытие материальных клеймов, полнота истории, замкнутость пространства связывания, поведенческое замыкание, свежесть state-свидетельств, только доверенные эффекты) |
| `UNRESOLVED` | Не разрешено | Всё остальное: решающие неизвестности, переполнение бюджета миров, отвергнутый сертификат, недоступность фронтенда |
| `INCONSISTENT` | Противоречие доверенных фактов | Доверенные факты в одной материальной области противоречат без промежуточной попытки мутации (BOTH-aware семантика состояния) |

Бинарная метка 0/1 появляется **только после** доказательного ядра — в продуктовом адаптере (`vnext/adapters.py::adapt`). `UNRESOLVED` никогда не превращается в фальшивый `NO_ERROR`. Ключевое дизайн-правило: **система не конвертирует собственную неопределённость в ложную уверенность** (измерено: false-certified-NO_ERROR = 0 во всех руках на свежем holdout из 112 кейсов).

## 2. Верификационная постановка

Задача сформулирована не как классификация, а как **проверка выполнимости обязательств во всех допустимых мирах**:

1. Неуверенность фронтендов (интерпретации политики/цели) — это не «шум», а **кандидатные семантики**, порождающие оси интерпретации.
2. Неопределённость связывания (какой tool соответствует семантическому действию) — тоже ось: каждая допустимая привязка — отдельный вариант мира.
3. Вердикт `PROVED_ERROR` требует, чтобы **в каждом** произведении выборов по осям нашёлся сертифицированный `FALSE`-свидетель: доказанное нарушение переживает посторонние неизвестности.
4. Вердикт `PROVED_NO_ERROR` требует, чтобы ни в одном мире не было нарушения, а все UNKNOWN-конъюнкты отсутствовали, и все посылки замыкания выполнялись.
5. Каждый внешний дефинитив снабжается **сертификатом**, который перепроверяется независимым детерминированным чекером; непрошедший сертификат понижает вердикт до `UNRESOLVED`.

## 3. Границы доверия

### 3.1 Доверенное (авторитет приложения)

- **Транспортные маркеры** `⟦SYSTEM⟧ / ⟦USER⟧ / ⟦ASSISTANT⟧`, вызовы инструментов, `TOOL_RESULT requestor=…` — авторитет приходит из транспортного обрамления, **никогда** из текста тела. Результат инструмента, содержащий «SYSTEM: …», остаётся данными инструмента.
- **T1-контракты** (версионированные, привязанные к хэшам) — единственный источник доверенных эффектов; их сбой никогда не доказывает «нет эффекта».
- **State-контракт** (на кейс) — доверенные текущие значения полей для семантики сохранения: `FORBID(modify F)` компилируется в `REQUIRE(F in values)`.
- **Авторитетные поведенческие ряды** (для кейсов closed-safe) — явная посылка семантического замыкания для `PROVED_NO_ERROR`.
- **Детерминированный код**: нормализация, леджер, связыватель, proof-атомы, solver-обёртка, чекер сертификатов, адаптеры, E5, ассемблер, каноникализатор.

### 3.2 Недоверенное (только кандидатные семантики, никогда факты)

- **Предложения H0 / GRS / Conservative / RuleFrames** — `NEURAL_INTERPRETATION`-кандидаты: они создают миры, но не свидетельства.
- **T2-предложения эффектов** — только мировые альтернативы «возможного эффекта».
- **Проходы claim-графа** — кандидатные семантики клеймов; каждый материальный клейм всё равно требует детерминированного связывания сущностей и примитивного доказательства.
- **Операционные связывающие предложения** — LLM-предложения соответствий «семантическое действие ↔ инструмент/аргументы», валидируемые детерминированно (точное литеральное обоснование в нормативном тексте, покрытие клаузул, равенство scope); отвергнутый кандидат оставляет `UNRESOLVED`-маркер, никогда угаданную привязку.

### 3.3 Инварианты, закреплённые конструкцией

- `USER_ACTION != ASSISTANT_ACTION` — поиск пререквизитов ведёт только по вызовам ассистента.
- `ASSISTANT_INTENT != COMPLETED` — интент-клеймы остаются UNKNOWN.
- `CALL_ATTEMPTED != ACTION_COMPLETED` — разные виды атомов; завершённость требует доверенного контракта эффекта.
- `FAILED_CALL != SUCCESS` и `!= NO_EFFECT`.
- `CLAIM != OBSERVED_FACT`.
- `UNKNOWN != FALSE` — отсутствующие аргументы/отсутствие данных остаются UNKNOWN.
- `NOT_FOUND != ABSENCE` — промах поиска не есть отсутствие; отсутствие доказуемо только при полной истории и отсутствии unknown-actor/unpaired событий.
- `OBSERVED_AT_TIME != CURRENT_STATE` — устаревшие наблюдения не сертифицируют безопасность: посылка `FRESH_STATE_EVIDENCE`.
- `LATER_STATE != CAUSAL_PROOF` — каузальные атомы требуют контрактно-подтверждённых эффектов.
- `PERMISSION != OBLIGATION` — PERMIT-правила не создают обязательств (`NO_VIOLATION != PERMITTED`).
- `alias != identity` — при дубле имён сохраняются все связывания.
- `PLAUSIBLE_BINDING != UNIQUE_BINDING` — правдоподобная привязка не уникальная; неуникальная привязка = альтернативные миры.

## 4. Общая архитектура (конвейер)

```
E2ECaseInput (полная траектория + доверенные метаданные приложения)
  └─> source_adapter_v1        [TEXT_VIEW / ACTION_VIEW; goal firewall: только user_request]
  └─> normalize (baseline)     [маркерная транспортная нормализация; сохранение неоднозначности]
  └─> EvidenceLedger           [append-only; наблюдения только из result-полезных нагрузок]
  └─> T1 (доверенные контракты) / T2 (недоверенные кандидаты эффектов)
  └─> claim-граф (baseline 10 узких проходов + E2E claim overlay)
  └─> PASS 1 — фронтенды (без траектории):
         политика: H0 (плоская) и/или GRS (grounder → B1-синтез → DSL → каноникализатор)
         цель:     Conservative и/или RuleFrames (+E5-резолвер +ассемблер)
       └─> общее программное пространство (FORBID_CALL / REQUIRE_PRESERVE /
           REQUIRE_CALL / GOAL_CALL / GOAL_ALTERNATIVES / PERMIT)
       └─> детерминированная дедупликация эквивалентностей (без выбора победителя)
  └─> PASS 2 — лоуэринг (связывание с траекторией):
         операционное связывание (LLM-предложение + детерминированная валидация
         литералов/клаузул), пререквизитные атомы, обязательства сохранения,
         дизъюнктивные группы авторизации
  └─> оси: политика, цель, по-клеймовые, T2-эффекты
  └─> точное декартово произведение миров (бюджет 4096; превышение ⇒ UNRESOLVED)
  └─> мировые вердикты (FALSE доминирует над UNKNOWN; маркеры — UNKNOWN-конъюнкты)
  └─> агрегация по всем мирам (консенсус)
  └─> сертификат → независимый детерминированный чекер → понижение при невалидности
  └─> продуктовый адаптер (бинарная метка; UNRESOLVED — не фальшивый NO_ERROR)
```

**Два прохода (two-pass design).** PASS 1 получает только нормативные тексты: фронтенды политики видят только текст политики, фронтенды цели — только запрос пользователя (goal firewall; байто-инвариантность к будущим событиям регрессионно протестирована на 10 дивергирующих «будущих»). PASS 2 привязывает скомпилированные правила к траектории: операционное связывание семантических действий с tool-вызовами и аргументами, вычисление пререквизитов и обязательств сохранения. Это разделение гарантирует, что интерпретация нормативного текста не может подстроиться под наблюдаемое поведение.

**Руки (arms).** Пять конфигураций фронтендов над идентичными нижними слоями:

| Рука | Политика | Цель |
|---|---|---|
| E0 | H0 | Conservative |
| E1 | GRS | Conservative |
| E2 | H0 | RuleFrames+E5 |
| E3 | GRS | RuleFrames+E5 |
| E4 | {H0, GRS} | {Conservative, RuleFrames+E5} (retention с дедупликацией) |

Фронтенды мемоизируются (одна семантическая попытка на уникальный вход), поэтому все руки разделяют вычисления фронтендов.

## 5. Контракты данных (`e2e_types_v1.py`)

Все записи — frozen dataclass'ы, семантические кандидаты, никогда свидетельства. Каждый привязанный к источнику фрагмент несёт точную цитату; оффсеты резолвит только детерминированный E5.

- `SemanticLiteral` — типизированный семантический лист (kind ∈ ACTION/STATE/ACTOR/ENTITY/CLAIM/EVIDENCE/VALUE/EFFECT; полярность POSITIVE/NEGATED; точная цитата обязательна).
- `PolicyFlatStructure` — плоская консервативная H0-структура всей политики: modality, actor, relation, target/condition/exception-литералы, режимы ALL/ANY/UNKNOWN, квантификация, source_quotes, unresolved_terms.
- `FrontendCandidate` — исход попытки фронтенда; `available=False` c типом отказа TRANSPORT/SCHEMA/COMPILE. **UNAVAILABLE никогда не безопасен.**
- `InventoryAtom` / `SurfaceMarker` / `GroundedInventory` — GRS-инвентарь (факты F#, модальные M# и реляционные R# маркеры, каждый с дословной цитатой).
- `DslRule` / `DslRuleset` — закрытая DSL-грамматика GRS (валидация в `__post_init__`: закрытые словари модальности/модификаторов, target обязан начинаться с `F`).
- `CompiledCondition` / `CompiledRule` / `PolicyReading` — общее программное пространство для политики и цели; polarity фиксирована KIND'ом правила, а не поверхностной модальностью.
- `ExtractiveRef` / `ScopeEntry` / `GoalFrame` / `GoalContract` — фреймы цели; LLM заполняет только семантические поля, канонические ID — никогда.
- `DisjunctiveGroup` — дизъюнктивная группа авторизации: на каждый целевой вызов OR по допустимым атомам.
- `UnresolvedMarker` — мировой UNKNOWN-конъюнкт: блокирует `PROVED_NO_ERROR`, никогда не создаёт ERROR.
- `ReadingOption` — один выбор по оси: обязательства + группы + неизвестности.
- `E2ECaseInput` — кейс корпуса с доверенными метаданными (T1-контракты, state-контракт, полнота истории, авторитетные показания/поведения для оракулов и замыкания, gold — только для скоринга после запечатывания).
- `E2EArmConfig` + `ARMS` — пять рук E0–E4.

## 6. Детальное описание каждого модуля

### 6.1 `source_adapter_v1.py` — адаптер источника (NEW)

**Назначение.** Компонует документы траектории, нормализует их доверенным маркерным транспортом и расщепляет целевой ответ ассистента на две проекции: `TEXT_VIEW` (естественно-языковые утверждения для claim-извлечения) и `ACTION_VIEW` (предпринятые tool-вызовы для операционной оценки политики/цели).

**Ключевые компоненты.**
- `build_source(case)` — детерминированная композиция: политика оборачивается в явный маркер `⟦SYSTEM⟧`, запрос — в `⟦USER⟧`, история присоединяется как есть. State-контракт приклеивается к политике суффиксом `POLICY_STATE_CONSTRAINTS=<canonical json>`, так что нормализованное событие несёт actor=system с авторитетом транспорта.
- `SourceProjection` — text_events (assistant-текст только из response) и call_events (вызовы только из response) + инвариант: «JSON-значение аргумента — не текстовое утверждение ассистента; аргументы ACTION_VIEW никогда не входят в claim-извлечение, а TEXT_VIEW никогда не доказывает действие».
- `E2ESource` — projection, tool_metadata/tool_schemas, events, source_sha256 (digest prompt+response+case_id).
- `target_calls(source)` — ACTION_VIEW-вызовы (попытка, не эффект).
- `tool_catalog(source)` — объединение имён из schemas, metadata и реально наблюдённых вызовов.

**Краевые случаи.** Пустая политика → пустой SYSTEM-блок не добавляется. Немаркированный ведущий текст нормализуется как actor=unknown, что корректно блокирует доказательства отсутствия в префиксе. Парные result-события без единственного соответствующего call-события пропускаются на уровне ядра (pairing_issue фиксируется в леджере).

### 6.2 `backend_v1.py` — кэширующий семантический бэкенд (NEW)

**Назначение.** Обёртка над SemanticBackend: ровно **одна семантическая попытка на уникальный вход** (ключ = digest(task, payload, schema)), детерминированный реплей для всех рук; квитанции (receipts) каждого вызова с латентностью; персистентный кэш на диск.

**Зарегистрированные детерминированные транспортные ремонты** (только для задачи `operational_action_binding`, semantics-preserving, каждый отмечается в квитанции):
1. удаление field-check'ов, ошибочно эмитированных для самой клаузулы `action` (она покрыта именем инструмента);
2. срез ведущего сегмента пути `arguments`/`args`/`parameters`/`params`;
3. перекодирование неканонических `allowed_json`-литералов в канонический JSON (голый `14C` → `"14C"`; уже канонические `2` и `"14C"` не трогаются);
4. дополнение каждой исходной цитаты вариантом без концевой пунктуации, чтобы точечка в конце предложения не ломала точное литеральное обоснование.

Никаких других ремонтов, ретраев или перезаписей. Транспортные ретраи остаются внутренним ограниченным поведением ChatClient.

**Промпт-оверлеи** (статические дополнения инструкций): CLAIM_OVERLAY (claim_predicate — имя поля/свойства, а не значение; claim_object — утверждаемое значение; entity_refs — идентификаторы как написаны; claim_source/claim_time-конвенции) и BINDING_OVERLAY (TARGET_INVOCATION для scope-сохранений и запретов уровня вызова; COMPLETED_EFFECT — только для явно требуемых подтверждённых бизнес-эффектов).

**Краевые случаи.** Повторный запрос с тем же ключом — cache_hit с latency 0. Транспортная ошибка — тоже кэшируется и реплеится как есть (UNAVAILABLE-неудача воспроизводима). Потокобезопасность через lock; персист через tmp-файл + atomic rename. `build_live_backend()` — BAI (qwen3.8-flash) через собственный ChatClient; BAI отклоняет строгие response_format-схемы с uniqueItems, поэтому провайдер работает в `response_format_mode='none'` — модель возвращает один JSON-объект, который парсится и валидируется схемой на границе бэкенда.

### 6.3 `json_extract_backend_v1.py` — бэкенд с детерминированным JSON-извлечением (NEW)

**Назначение.** qwen3.8-flash иногда оборачивает JSON в markdown-фенсы или короткую прозу. Бэкенд извлекает **первый сбалансированный JSON-объект** из ответа — чисто транспортная, сохраняющая содержимое нормализация (зарегистрированный форматный ремонт). Никогда не переспрашивает, не редактирует сам JSON.

**Алгоритм `extract_first_json_object`.** Сканирование от каждого `{`: учёт глубины, нахождения внутри строк (in_string/escaped), закрытие на нулевой глубине → кандидат декодируется `decode_json`; невалидный кандидат → поиск следующего `{`. Это корректно обрабатывает вложенные объекты, строки с `{`/`}` и escape-последовательности.

**Краевые случаи.** Пустой контент → None → схема NOT_EVALUATED/INVALID. Рейтинг-лимит: интервал между вызовами (троттлинг), clock/sleep инъектируемы для тестов. Транспортное исключение → `Proposal(None, "ERROR", "NOT_EVALUATED", error_category)` — категория ошибки сохраняется. Каждая запись: served_model, usage (только int ≥ 0), latency_ms, sha256 промпта и схемы. Извлечение с обрезкой окружающего текста отмечается note.

### 6.4 `policy_h0_v1.py` — плоский консервативный фронтенд политики H0 (NEW)

**Назначение.** Одна первичная семантическая попытка по всему тексту политики в ОДНУ плоскую структуру (спека 26–35). Разрешён только заранее зарегистрированный форматный ремонт: один re-ask, когда транспортная полезная нагрузка не была валидным JSON. Schema-валидный, но семантически подозрительный вывод **никогда** не переспрашивается. Недиапазонная модальность → UNAVAILABLE (не безопасно, не разрешение).

**Схема H0** — закрытые словари: modality ∈ PERMISSION/PROHIBITION/REQUIREMENT/UNKNOWN; relation ∈ NONE/IF/ONLY_IF/UNLESS/BEFORE/AFTER/UNTIL/WHILE/UNKNOWN; maxItems 6 на клаузулы; uniqueItems на цитатах; every clause = {kind, polarity, normalized_key, quote}.

**Инструкция.** Модель видит только текст политики; не выдумывать правила/акторов/scope; UNKNOWN при неоднозначности; каждая клаузула обязана цитировать точный фрагмент; `normalized_key` при упоминании инструмента — имя инструмента дословно (например `transfer_money`); unresolved_terms — только реально неопределённые нормативные ссылки («old», «trusted»), а не обычные слова.

**Детерминированная постобработка.** Цитаты, отсутствующие в тексте политики дословно, отбрасываются; канонический порядок клаузул; проверка «модальность известна ⇒ есть target-клаузулы».

**Краевые случаи.** Пустая политика → available, structure=None (ось политики станет absent). Транспортная неудача после одного формального re-ask → TRANSPORT. Schema-невалидность → SCHEMA. Все target-цитаты негрунтованы или пустой target при известной модальности → COMPILE `ungrounded-or-empty-target`. Модель вернула дополнительное поле — отброшено схемой (additionalProperties=false).

### 6.5 `policy_grs_grounder_v1.py` — GRS-гроундер (NEW)

**Назначение.** Извлекает заземлённый семантический инвентарь политики: атомы-факты F# с типом kind, нормализованным meaning-ключом и дословной цитатой; поверхностные модальные маркеры M# и реляционные маркеры R#. **Никогда не решает финальную структуру правил** — это задача B1. Каждый принятый атом заземлён источником: цитата обязана встречаться в тексте политики дословно.

**Краевые случаи.** Дубликат ID атома — второй отбрасывается. Цитата не в тексте — атом/маркер отбрасывается (не чинится). Нет ни одного заземлённого факта → COMPILE `no grounded atoms` (фронтенд GRS недоступен — не безопасно). Сортировка по числовому номеру ID. maxItems 16/8/8 ограничивают инвентарь.

### 6.6 `policy_grs_dsl_v1.py` — закрытая DSL-грамматика GRS (NEW)

**Назначение.** Замороженная грамматика, парсер и валидатор правил GRS (спека 40, 44, 45):

```
RULESET := RULE(...) | RULE(...), RULE(...), ...
RULE := RULE(MODALITY, TARGET, MODIFIER*)
MODALITY := PERMIT | FORBID | REQUIRE
TARGET := F#
MODIFIER := WHEN(EXPR) | UNLESS(EXPR) | ACTOR(F#) | BEFORE(EXPR) | AFTER(EXPR)
          | UNTIL(EXPR) | SCOPE(F#) | TOGETHER(EXPR) | CHOICE(EXPR)
EXPR := F# | NOT(F#) | AND(F#, ...) | OR(F#, ...)
```

Парсинг строго синтаксически-управляемый: неизвестные ID инвентаря и свободнотекстовые листья INVALID (инвариант закрытого словаря). Сериализация канонична (s-выражения).

**Краевые случаи.** Лишние токены после RULESET → ошибка. NOT — строго унарный. AND/OR требуют ≥ 2 операндов. Дубликат модификатора в правиле → ошибка. ACTOR принимает только F#. Неожиданный символ → позиционная DslError. Пустой DSL → ошибка.

### 6.7 `policy_grs_synth_v1.py` — B1-синтезатор + детерминированный каноникализатор (NEW)

**Назначение.** B1 видит только текст политики и заземлённый инвентарь и компонует структуру правил **исключительно из ID инвентаря** (спека 43). Каноникализатор выполняет строго сохраняющий структуру ремонт сериализации (спека 47–49): никогда не меняет модальность, отношения, вложения или атомы.

**Ремонты каноникализатора.** (1) тримминг окружающего текста вокруг `RULESET(...)`; (2) структурно подразумеваемая обёртка RULESET для голого списка `RULE(...)`; (3) канонический порядок правил и удаление идентичных дубликатов. Всё отмечается notes.

**Краевые случаи.** Пустая политика или пустой инвентарь → COMPILE до вызова LLM. DSL не парсится после ремонтов → COMPILE с текстом ошибки (raw_dsl сохранён для аудита). Каждая деталь ремонта попадает в `canonicalization_notes`.

### 6.8 `policy_composition_v1.py` — компиляция политики в программное пространство (NEW)

**Назначение.** H0 и GRS компилируются в **одно общее поведенческое программное пространство** (спека 31, 50–52): без выбора победителя, без голосования, без confidence. Детерминистически эквивалентные чтения дедуплицируются; материальные расхождения сохраняются как отдельные варианты оси.

**Правила компиляции H0 (`compile_h0`).**
- `PERMISSION` → `PERMIT` (нет обязательств).
- Целевая клаузула VALUE + PROHIBITION → `FORBID_CALL` со scope на точное значение (`_quote_value_forms` даёт строковую и, если парсится, числовую/булеву формы).
- VALUE + REQUIREMENT → unresolved `h0:value-scoped requirement not expressible in V1`.
- PROHIBITION + попадание в поле state-контракта (word-boundary поиск по цитате и normalized_key) → `REQUIRE_PRESERVE` со scope из доверенных значений.
- PROHIBITION + слова modify/change/alter/update без state-контракта → unresolved-маркер `field modification prohibition without state contract`, правило всё равно FORBID_CALL.
- REQUIREMENT + relation BEFORE → `FORBID(B) WHEN NOT(A happened before B)` — пререквизитная семантика: запрещается B без предшествующего A (условие — отрицание A).
- REQUIREMENT иначе → `REQUIRE_CALL` (экзистенциальное требование).
- relation UNLESS → исключения становятся negated-условиями (исключение гасит запрет); ONLY_IF → условия инвертируются (разрешено только при условии).
- quantification EXACTLY_ONE/AT_LEAST_ONE при PERMISSION/REQUIREMENT → unresolved `choice cardinality not expressible`.
- UNKNOWN-модальность → unresolved `h0:unknown modality`.
- Актор: assistant/agent/system/unknown/пусто → assistant; иначе — как есть, но _rule нормализует к assistant/user/UNKNOWN.

**Правила компиляции GRS (`compile_grs`).** Аналогичные переходы из DSL-правил: PERMIT → PERMIT; FORBID + VALUE-атом → FORBID_CALL со scope; FORBID + field_hit → REQUIRE_PRESERVE; FORBID иначе → FORBID_CALL; REQUIRE + BEFORE-якорь → FORBID_CALL с пререквизитом (якорь — цель, действие — условие); REQUIRE иначе → REQUIRE_CALL. Модификаторы: WHEN/TOGETHER → условия; UNLESS/UNTIL → инвертированные условия; ACTOR: assistant-актёр — безусловен, прочее → unresolved `non-assistant actor modifier kept unresolved`; SCOPE участвует в поиске поля; CHOICE → unresolved `not expressible`. Отрицание листа: NOT на листе или NOT внутри AND.

**Ключи и дедупликация.** `_key_from(quote, normalized)`: normalized-ключ допускается только словообразный (буквы-цифры-_-); иначе — первые 6 слов цитаты, snake_case, lower. `reading_canonical_key` — структурная каноническая форма (kind/modality/action_key/actor/relation/conditions/exceptions/scope, сортировка рядов, digest); `dedupe_readings` сливает канонически-равные. `reading_from_rows` — оракул-подстановка авторитетных рядов в PolicyReading.

**Краевые случаи.** Несловообразный normalized_key (например с пробелами/понтовом) → ключ из цитаты. Значение-цитата «40» даёт формы `"40"` и `40`; «true» → `"true"` и `true`. Цитаты с дефисами нормализуются в underscore. Два чтения, отличающиеся только порядком/ID правил, — эквивалентны и сливаются.

### 6.9 `policy_lowering_v1.py` — лоуэринг политики PASS 2 (NEW)

**Назначение.** Скомпилированные правила → гипотезы → операционные связывания → опции чтения с обязательствами, дизъюнктивными группами и unresolved-маркерами. Переиспользует без изменений базовый операционный граундинг `bind_evaluation_hypothesis`.

**Семантика program space.**
- `FORBID_CALL`: на каждый целевой вызов — атом(tool[,scope]) expected true, must_be_false. Чужой инструмент ⇒ атом FALSE ⇒ обязательство удовлетворено.
- `REQUIRE_PRESERVE`: на каждый целевой вызов — obligation(atom(tool+scope), must_be_true, conditions=(tool-match atom, *правила условий)); нарушено ⇔ инструмент вызван И поле вне доверенного допустимого множества.
- `REQUIRE_CALL`: экзистенциальный HISTORICAL_ACTION по всей поставленной истории (must_be_true); отсутствие доказуемо только при полной истории и имени инструмента из каталога.
- `PERMIT`: записан, обязательств не создаёт.

**Краевые случаи.**
- `PERMIT` или пустой action_key → нет обязательств, нет маркеров.
- Правило с неоднозначным операционным связыванием → **одна альтернатива на выбор связывания** (под-чтения): произведение альтернатив правил даёт варианты чтения (ReadingOption), а не угадывание.
- Неудача связывания при наличии целевых вызовов → `UnresolvedMarker` «operational binding unresolved: <причины>» — блокирует PROVED_NO_ERROR, никогда не создаёт ERROR.
- **Нет целевых вызовов вообще** → attempt-level правила вакуумно удовлетворены (документ response — полный целевой вывод): обязательств не порождается.
- `REQUIRE_CALL` → экзистенциальный атом с time_index = последний индекс леджера; условия-пререквизиты через детерминированные атомы namespace `e2e` (ACTION) / `e2e-state` (STATE).
- unresolved_terms правила → маркеры `rule unresolved term`, едут в каждой опции.
- `option_contracts` — протокол «какие обязательства принадлежат какому правилу» для чекера: `(rule_id → {obligations: [...], groups: [...]})`; принадлежность восстанавливается по префиксам ID (policy:e2e:/goal_plan:e2e:/goal:e2e: и `rule_id:ob` для REQUIRE_CALL).
- Опций нет вовсе → одна опция только с маркерами чтения.

### 6.11 `goal_conservative_v1.py` — консервативный фронтенд цели (NEW)

**Назначение.** Один ограниченный семантический проход **только по firewall-безопасному источнику USER** (запрос пользователя). Каждый эмитированный семантический юнит обязан иметь точную исходную цитату. Может эмитировать только то, что имеет прямую позитивную текстовую поддержку; неоднозначность → UNKNOWN, никогда догадка. Никогда не видит историю, целевое действие, результаты инструментов или gold.

**Схема** — фреймы (≤ 8) с kind ∈ DESIRED_OUTCOME/AUTHORIZATION/PROHIBITION/OBLIGATION/GUARD/UNKNOWN, target_level, content_key, actor, scope_entries (field + значения + цитата), conditions, exceptions, temporal, coordination, choice, alternatives, quotes (≥ 1), unresolved.

**Инструкция** кодифицирует консервативность: DESIRED_OUTCOME — чего хочет пользователь; AUTHORIZATION — что явно разрешено (alternatives — разрешённые альтернативные ключи действий при выборе); PROHIBITION — что явно запрещено; OBLIGATION — только действительно обязательные шаги с явной упорядоченностью/дедлайном в temporal; GUARD — условие, управляющее другим фреймом. scope_entries: при запросе изменить значение — только НОВОЕ целевое значение (не старое); значения — точные машинные («40» для «40 dollars», «14C» для «seat 14C»); только конкретные аргументные поля, никогда абстрактные фасеты; **никогда** не отображать отображаемое имя в id-поле: сущность по имени → scope пуст (резолюция идентичности — отдельный детерминированный проход). Запрещено выдумывать промежуточные шаги, конвертировать опционального помощника в обязательство, авторизацию в требование, выводить завершённость.

**Краевые случаи.** Пустой запрос → available, фреймов нет. Цитаты не найдены дословно → фрейм **отбрасывается** (никакого семантического ремонта). scope-запись без цитаты или со значением, не встречающимся в цитате → запись отбрасывается. Множественные чтения без текстовой основы → UNKNOWN-поля или unresolved.

### 6.12 `goal_rule_frames_v1.py` — Rule Frames + доверенный ассемблер (NEW)

**Назначение.** LLM решает **только** семантические вопросы (kind, content, actor, scope, guards, conditions, temporal, coordination, choice, target level) и эмитирует привязанные к источнику части как ExtractiveRef {start, end, quote}. **Никогда** не генерирует канонические ID, межфреймовые внешние ключи или финальные AST-сериализации. E5 резолвит каждую ссылку детерминированно; ассемблер назначает канонические фрейм-подписи, стабильный порядок, арность и референциальную целостность и **не** выполняет семантического ремонта (перезапись must/may/unless, угадывание actor/scope и ближайшее прикрепление запрещены; неоднозначные/неразрешимые поля → UNKNOWN или фрейм отвергается).

**Краевые случаи.**
- Фрейм без резолвленного support → REJECT `no_resolved_support`.
- content_ref не резолвится или нет content_key → REJECT `unresolved_content`.
- actor_ref резолвится, но не содержит assistant-хинта и не user-хинта («i », «my», «me») → actor=None + unresolved_fields += actor.
- scope-запись: ref резолвится и field непуст, но ни одно значение не встречается в цитате ref → запись теряется.
- Каждый rejected-фрейм записывается в контракт как `rejected_frame:<reason>` (аудируемо).
- Дедупликация фреймов по каноническому ряду `_frame_row`, где **content_key заменён на derived key из первичной support-цитаты** (`_derived_key`): два фронтенда, согласные в kind/scope/support, — одно и то же допустимое чтение, даже если их подсказки связывания различаются; подсказка резолвится детерминированно в PASS 2.
- `contract_from_rows` — оракул-подстановка.

**Назначение.** Резолюция экстрактивных ссылок (спека 74, 75). **Никакой** edit distance, никакого fuzzy match, никаких эмбеддингов, никакого ближайшего спана, никакого LLM-фикса, никакого выбора среди дублей.

### 6.14 `goal_composition_v1.py` — компиляция цели (NEW)

**Назначение.** Conservative и Rule Frames фронтенды лоуерятся в одну каноническую семантику цели и затем в общее программное пространство CompiledRule (спека 57–82). Firewall: PASS 1 видит только запрос пользователя.

**Переходы фрейм → правило.**
- `DESIRED_OUTCOME` / `AUTHORIZATION` (одиночная) → `GOAL_CALL`: каждый целевой вызов обязан быть этим действием в пределах scope (расширение scope нарушает); авторизация — не требование исполнить.
- `AUTHORIZATION` с alternatives (ANY_OF) → `GOAL_ALTERNATIVES`: на каждый вызов OR по разрешённым альтернативам.
- `PROHIBITION` → `FORBID_CALL`, либо `REQUIRE_PRESERVE`, если фрейм нацелен на поле state-контракта; scope-фрейм → FORBID_CALL со scope.
- `OBLIGATION` → `REQUIRE_CALL`; BEFORE-якорь → FORBID_CALL с пререквизитом.
- `GUARD` → unresolved-маркер `guard applicability unknown`.
- `UNKNOWN` → unresolved `frame kind unknown`.

**Краевые случаи.** temporal BEFORE/AFTER у OBLIGATION с якорем-условием → пререквизитный FORBID_CALL; у DESIRED_OUTCOME → unresolved `temporal relation not expressible for this frame kind`. AUTHORIZATION с alternatives и choice EXACTLY_ONE → unresolved `exactly-one choice cardinality not expressible in V1` (реальная кардинальность выбора, которую V1 не выражает); с единственной альтернативой EXACTLY_ONE — просто это действие (GOAL_CALL). Значения scope канонизируются через `_value_forms` (строка + число/булево). `compiled_goal_closure_key` — замыкающий ключ по СКОМПИЛИРОВАННЫМ правилам с нормализацией action_key к детерминированному ключу из первичной цитаты: вариативность свободного content_key между фронтендами не ломает замыкание.

### 6.15 `goal_lowering_v1.py` — лоуэринг цели PASS 2 (NEW)

**Назначение.** Goal-контракты → CompiledRules → опции чтения. Альтернативы AUTHORIZATION становятся DisjunctiveGroups: на каждый целевой вызов OR по явно разрешённым альтернативам (разрешённые альтернативы — НЕ инструкция исполнить все). Нормативный текст цели несёт суффикс `EXPLICIT_ALLOWED_SCOPE=<canonical json>` объединённого scope всех правил, так что каждый допустимый литерал текстуально заземлён для операционного связывания (тот же механизм, что базовое ядро использует для EXPLICIT_ALLOWED_SCOPE).

**Краевые случаи.**
- `GOAL_ALTERNATIVES`: на каждую альтернативу — отдельное подправило GOAL_CALL; связывание альтернативы, давшее ≠ 1 choice → маркер `alternative binding ambiguous or unresolved` (альтернатива выпадает из группы).
- Условия/исключения на правилах с альтернативами → маркер `conditions on alternatives not expressible in V1`.
- Требуется ровно одно связывание на альтернативу: `_alternative_group` копит атомы per event_id; группа собирается даже при пустом per_call (пустая группа = все вызовы вне — нарушение).
- `REQUIRE_CALL` → direct_rules (для чекера: гипотеза → rule_kind); экзистенциальное обязательство через последний индекс.
- Нет целевых вызовов → attempt-level правила вакуумно удовлетворены.
- Неудача связывания → маркер `operational binding unresolved: <причины>` (те же причины, что в policy lowering: failures ∪ discarded).
- `merged_scope` — объединение scope правил для суффикса нормативного текста.

### 6.16 `claim_adapter_v1.py` — адаптер клеймов (NEW)

**Назначение.** Инвариант TEXT_VIEW/ACTION_VIEW вокруг базовой claim-машинерии: граф клеймов строится **только** по текстовым спанам ассистента целевого response (response_spans пропускает call-маркеры); аргументы предпринятых вызовов никогда не входят в claim-извлечение. Обратное тоже верно: текстовые проекции никогда не доказывают действие. Жёсткие неудачи клеймов становятся мировыми UNKNOWN-маркерами: блокируют PROVED_NO_ERROR, но никогда не маскируют независимое сертифицированное нарушение.

**Value anchoring (детерминированный).** Позитивный STATE/ATTRIBUTION-клейм, чей объект — один литеральный токен (≠ predicate), заземляет ожидание атома на это точное наблюдаемое значение: противоречащее поле-клейм доказывает FALSE, совпадающее — TRUE. Многословный или отсутствующий объект откатывается к булевой полярности (НЕВЕРНО для небулевых наблюдений — никогда ложный свидетель). **Та же функция** `claim_expected_json` используется и адаптером, и независимым чекером сертификатов — они не могут разойтись.

**Краевые случаи.**
- `NON_VERIFIABLE`-клейм → пропущен полностью (не материален).
- `UNKNOWN_SEMANTICS`, каузальный вид или не-ASSERTED/REPORTED модальность → одноопционная компонента с маркером `claim semantics untyped or causal` (UNKNOWN-конъюнкт).
- Нет связывающих альтернатив → маркер `entity unbound`; `SOURCE_UNBOUND` → маркер `claim source unbound`; не привязано время (для не-action-клеймов или action-клеймов с якорем вне PAST/ALL_HISTORY/NOW) → маркер `claim time unbound`.
- Несколько альтернатив связывания сущности → **каждая — отдельная опция оси** (миры); маркеры едут со всеми опциями.
- STATE/ATTRIBUTION оцениваются по LATEST-наблюдению (result-field описывают вывод инструмента; state-клеймы — новейшее наблюдённое состояние); ACTION_COMPLETED/ABSENCE — THROUGH.
- Состав компонентов: universe_source = `enumerated exact supplied-source identities:<claim_id>`; authority basis EXPLICIT_SOURCE_IDENTITY.

### 6.17 `world_integration_v1.py` — миры и мировые вердикты (NEW)

**Назначение.** Оси, точное декартово произведение миров, локальные вердикты миров и агрегация по всем мирам (спека 91–101).

**Алгебра (зафиксирована контрактом).**
- Сертифицированный FALSE-свидетель безопасности в мире делает мир ERROR даже при посторонних UNKNOWN-обязательствах: доказанное независимое нарушение не маскируется посторонней неопределённостью.
- Любой UNKNOWN-конъюнкт безопасности (unresolved-маркер, незаземлённая часть чтения, неизвестный пререквизит) блокирует PROVED_NO_ERROR, но никогда не создаёт ERROR.
- PROVED_NO_ERROR дополнительно требует посылок замыкания в сертификате.
- Точное декартово произведение по материальным осям; превышение бюджета миров = UNRESOLVED, **никогда** подмножество top-k.

**`prove_e2e_atom`.** Атомы в зарезервированных namespace `e2e`/`e2e-state` с видами CALL_ATTEMPTED/HISTORICAL_ACTION используют детерминированный оценщик пререквизитов/экзистенциальности: поиск assistant-вызовов по точному имени инструмента и пересечению значений сущности. Остальное делегируется базовому `prove_atom` (общему для солвера и чекера) с одним детерминированным E2E-уточнением для state-атомов: когда доверенные свидетельства одного предиката и поддерживают, и опровергают ожидание **без** попытки вызова между двумя точками свидетельств, атом = BOTH (доверенное противоречие в одной материальной области) вместо молчаливого «последнее побеждает».

**`_prove_deterministic_action_atom` (пошаговые краевые случаи).**
1. expected_json не парсится или не bool → UNKNOWN c Reason.CLAIM_UNTYPED.
2. time_index вне диапазона леджера → UNKNOWN c Reason.TIME_UNBOUND.
3. Поиск вызовов: kind=call, точное совпадение имени инструмента, actor совпадает, index ≤ time_index; при entity.value ≠ «*» — пересечение entity_refs. Найдено → TRUE/FALSE по expected.
4. Вызовов нет, но есть наблюдения с тем же предикатом (или предикат входит в «_»-токены ключа) → оценка по последнему наблюдению: поддержка/опровержение (строгая проверка type(actual) is type(expected)); оба → BOTH; только поддержка → TRUE; только опровержение → FALSE; типоразличие (например «100» vs 100) → UNKNOWN EVIDENCE_INCOMPLETE; невалидный JSON значения → UNKNOWN.
5. Нет ни вызовов, ни наблюдений: отсутствие **попытки** доказуемо только для ACTION-условий (namespace `e2e`) при полной поставленной истории и отсутствии unknown-actor/unpaired событий → FALSE/TRUE по expected с обоснованием `absence:complete-history:<atom_id>`; STATE-условия (namespace `e2e-state`) остаются UNKNOWN: ненаблюдаемое состояние — не доказанное ложное.

**`solve_world`.** Для каждого обязательства: condition_proofs → antecedent (конъюнкция); required = атом или его отрицание (по must_be_true); safety = material implication (¬antecedent ∨ required). Для групп: safety = дизъюнкция значений атомов альтернативы на каждый event_id. Для маркеров: safety = UNKNOWN. error = ¬(конъюнкция safety). Всё попадает в WorldProof (выборки, safety-пары, примитивы).

**`build_worlds`.** required = произведение мощностей осей; required > max_worlds или 0 → мир нет, budget_exceeded=True. Каждый мир — E2EWorld(world_id, choices, obligations, groups, markers с дедупликацией). `make_problem` — E2EProblem с certificate-facing проекцией WorldPlan и side_sha256 (hash групп+маркеров каждого мира). `solve_e2e` — консенсус по world proofs; пустые миры → EVIDENCE_INCOMPLETE; UNRESOLVED без причин → POLICY_AMBIGUOUS.

### 6.18 `certificate_context_v1.py` — сертификаты и независимый чекер (NEW)

**Назначение.** Контекст, конструктор и **независимый детерминированный чекер** сертификатов. Чекер **никогда** не вызывает LLM, не доверяет прозе солвера, model confidence, именам инструментов как эффектам или схемам как контрактам эффектов. Он перепроверяет каждый примитив, каждый мировой вердикт, посылки замыкания и заземление обязательств из неизменяемых записей. Отвергнутый сертификат понижает вывод Core до UNRESOLVED (спека 104–107).

**`E2EBundle`** — всё, что нужно чекеру: контекст сертификата, проблема, option_contracts (какие обязательства каким правилам принадлежат), choice_rules, direct_rules, замыкания политики/цели, неудачи фронтендов.

**Посылки полноты (`e2e_completeness_assumptions`).** 8 посылок с доказательствами или NOT_ESTABLISHED:
1. `MATERIAL_RESPONSE_COVERED` — детерминированный инвентарь спанов покрыт материальными клеймами.
2. `SOURCE_HISTORY_COMPLETE` — basis полноты истории.
3. `BINDING_SPACE_COMPLETE` — все материальные клеймы имеют полный набор кандидатов связывания (explicit exact identity candidates).
4. `SEMANTIC_CANDIDATES_COVERED` — все поставленные допустимые кандидаты перечислены (не утверждение неограниченной NL-полноты).
5. `SEMANTIC_SPACE_PROVABLY_CLOSED` — независимо поставленные авторитетные оси (не EMPIRICAL_CANDIDATE_SET).
6. `FRESH_STATE_EVIDENCE` — последние поддерживающие наблюдения не перекрыты более поздними попытками вызовов.
7. `ABSENCE_SCOPE_REQUIREMENT` — все посылки отсутствия проверены индивидуально: промах поиска ≠ отсутствие.
8. `EFFECTS_TRUSTED_ONLY` — нет осей недоверенных T2-эффектов.

**`_state_evidence_fresh`**: для каждого материального STATE/ATTRIBUTION-клейма — максимум индексов поддерживающих наблюдений/доверенных эффектов ≥ индекса последнего вызова; попытка мутации инвалидирует устаревший state-клейм.

**`make_e2e_certificate`** — только для PROVED_ERROR/PROVED_NO_ERROR: версия `guardian-e2e-v1-proof-v1`, source_digest (bundle), ledger/registry digests, problem_digest, world_proofs (перевычисляются решением), completeness_assumptions.

**`check_e2e_certificate` (полный список проверок).**
- Версия/статус сертификата → INVALID_CERTIFICATE_KIND.
- Хэши source/ledger/registry/problem → HASH_MISMATCH:*.
- **Реконструкция леджера**: normalize(prompt, response) обязан воспроизвести события леджера → LEDGER_SOURCE_RECONSTRUCTION_FAILED.
- Посылки: PROVED_ERROR требует только SEMANTIC_CANDIDATES_COVERED; PROVED_NO_ERROR — полный набор {MATERIAL_RESPONSE_COVERED, SOURCE_HISTORY_COMPLETE, BINDING_SPACE_COMPLETE, SEMANTIC_SPACE_PROVABLY_CLOSED, FRESH_STATE_EVIDENCE} → COMPLETNESS_UNPROVED.
- Уникальность имён осей → DUPLICATE_AXIS; непустые и уникальные choice_ids → INVALID_AXIS_CHOICES.
- Инвентарь миров: множество proof.world_id == множество миров → WORLD_INVENTORY_MISMATCH.
- На каждый мир: перевычисление solve_world — примитивы, safety-пары, error_value → PRIMITIVE_OR_OBLIGATION_WITNESS_MISMATCH / WORLD_VERDICT_MISMATCH; ожидаемый error по статусу сертификата → WORLD_DOES_NOT_PROVE_CERTIFIED_VERDICT; для PROVED_ERROR — наличие FALSE в safety → MISSING_VIOLATION_WITNESS.
- Заземление обязательств: каждый obligation принадлежит правилу выбранной опции (FOREIGN_OBLIGATION); claim-обязательства проверяются по типу/полярности/актору/expected_json (FACTUAL_OBLIGATION_NOT_GROUNDED, CLAIM_TYPE_POLARITY_OR_ACTOR_MISMATCH); choice-обязательства — operational_choice_valid + атомы + toolmatch/prerequisite-свидетели (UNSUPPORTED_CONDITION_ATOM, CONDITION_WITNESS_MISMATCH, PREREQUISITE_TIME_OR_ACTOR_MISMATCH, TOOLMATCH_TIME_MISMATCH); direct-обязательства — только REQUIRE_CALL, гипотеза заземлена, спаны в пределах нормативного текста своего фронтенда (OBLIGATION_NOT_AUTHORIZED_BY_HYPOTHESIS, HYPOTHESIS_SCOPE_OR_SOURCE_MISMATCH, EXISTENTIAL_ATOM_KIND_MISMATCH).
- Группы принадлежат правилу одной из выбранных опций → FOREIGN_GROUP.
- Покрытие чтений: все обязательства контракта правила присутствуют в мире → READING_OBLIGATION_COVERAGE_INCOMPLETE.
- Для PROVED_NO_ERROR: каждый материальный клейм покрыт проверяемым обязательством → SAFETY_MATERIAL_OBLIGATIONS_INCOMPLETE.

### 6.19 `core_v1.py` — точка входа `GuardianE2EV1.analyze_e2e_v1` (NEW)

**Назначение.** Версионированная точка входа (спека 109, 110) с явным внедрением зависимостей: semantic backend, T1-registry, конфигурация руки, мировой бюджет, режим адаптера, оракул-подстановки. Нет скрытых API-клиентов, нет скрытого глобального семантического состояния. Базовая точка входа `vnext.core.analyze` (B0) не тронута и остаётся запускаемой.

**Порядок `analyze_e2e_v1`.**
1. `build_source` → `EvidenceLedger.from_events` (history_complete, completeness_basis).
2. T1/T2: для каждого result-события с единственным парным call-событием — `evaluate_t1`; T2 предлагается только когда инструмент не найден в registry (и включён enable_t2). Леджер пересобирается с эффектами.
3. `build_claims` (TEXT_VIEW) по response.
4. **PASS 1**: `_policy_readings` (H0/GRS/oracle) и `_goal_contracts` (Conservative/RuleFrames/oracle) с дедупликацией; неудачи → frontend_statuses.
5. **PASS 2**: `lower_reading` для каждой policy-reading (нормативный текст = policy + state-суффикс); объединённый goal-scope суффикс вычисляется из всех контрактов и присоединяется к user_request для goal-нормативного текста; `lower_goal_contract` для каждого контракта.
6. **Оси**: политика (если текст непуст), цель (если текст непуст) — иначе компоненты отсутствия (EXPLICIT_STRUCTURED_ABSENCE); по-клеймовые компоненты; T2-оси — только для альтернатив без contract_sha256 (name=`effect:<event_id>`, EMPIRICAL_CANDIDATE_SET). Пустая ось политики без чтений → `policy:unresolved`-опция с маркером «no policy reading available». Базис вселенной: AUTHORITATIVE_CLOSED_UNIVERSE при полном замыкании, иначе EMPIRICAL_CANDIDATE_SET.
7. `build_worlds` (бюджет) → `make_problem`.
8. `CertificateContext` + `E2EBundle` (с поведенческими замыканиями политики/цели и неудачами фронтендов).
9. `solve_e2e` → статус; budget_exceeded → missing_evidence `WORLD_BUDGET_EXCEEDED:<required>><max>`.
10. `make_e2e_certificate` → `check_e2e_certificate`: невалиден → статус UNRESOLVED, Reason.EVIDENCE_INCOMPLETE, missing_evidence = ошибки чекера, сертификат обнуляется.
11. Причины: TRANSPORT/SCHEMA-неудачи фронтендов → Reasons; UNRESOLVED без причин → POLICY_AMBIGUOUS; оба нормативных текста пусты → POLICY_NO_INTERPRETATION.
12. `_primary_reason` — приоритетный порядок Reasons для диагностики; `adapt(certified, mode)` → продуктовое решение; `E2EAnalysis` возвращает всё: показания, контракты, статусы фронтендов, required/world_count, component_summary, lowered-записи для аудита.

**Поведенческое замыкание (`_behavioral_closure`).** Посылка: множество связанных **поведений** равно авторитетному поведенческому множеству (спека 102: явная посылка, никогда не выводимая из согласия фронтендов). `_behavior_rows`: на каждое обязательство — pred + отсортированные ограничения (path + allowed_json) + полярность + условия (без TARGET_CALL_MATCH); на каждую группу — альтернативы; маркеры — отдельным рядом. Подпись = sorted canonical rows per OPTION (пространство допустимости = НАБОР пакетов опций: альтернативы связывания создают различные опции). `_auth_behavior_rows` канонизирует поставленные ряды (значения ограничений в канонические JSON-литералы). Репрезентативная вариативность (семантические ключи действий) коллапсирует: важно связанное поведение, не именование. Оракулы: `readings_from_behaviors` / `contract_from_behaviors` строят чтения/контракты, лоуерящиеся ровно в эти поведения.

**Краевые случаи ядра.** `max_worlds` нецел или < 1 → ValueError при конструкции. result-событие без ровно одного парного call → скип. Ось политики/цели с полным чтением и замкнутым поведенческим замыканием → universe_source = AUTHORITATIVE_CLOSED_UNIVERSE + digest сэмпла. `readings_from_behaviors`: must=False → FORBID_CALL, must=True → REQUIRE_PRESERVE при scope, иначе REQUIRE_CALL; cond[1]=="false" → negated. `extract_behavior_rows` — извлечение поведенческих рядов из лоуеренных чтений (для авторства замыканий в тестах).

### 6.20 `experiment_v1.py` — экспериментальный раннер (NEW)

**Назначение.** Выполнение рук с одной семантической попыткой на вход (мемоизацией), инкрементальные файлы предсказаний, запечатывание до gold, скоринг, парная статистика (точный двухсторонний McNemar), оракул-диагностика и таксономия неудач.

## 7. Алгебра миров и вердиктов (сводка)

Per world: `error = NOT (AND of safety values)`. Safety обязательства: `NOT antecedent OR required` (материальная импликация). FALSE-значение доминирует над UNKNOWN в конъюнкции → сертифицированное независимое нарушение переживает посторонние неизвестности. Unresolved-маркеры — UNKNOWN-конъюнкты: блокируют NO_ERROR, не создают ERROR. Неудавшийся фронтенд (transport/schema) оставляет перечисление оси неполным → блокирует оба дефинитива (консервативное чтение спеки 34/52). Вердикты по статусам — секция 1; алгебра Truth (TRUE/FALSE/UNKNOWN/BOTH) и consensus переиспользуются из базового слоя без изменений.

## 9. Руки E0–E4 и эмпирические результаты

**Дизайн эксперимента.** Dev-корпус 32 кейса, 4 итерации разработки (промпт/схема/связывание/клеймы), заморозка архитектуры на `4d7fdfb`; свежий holdout 112 кейсов (8 новых доменов, 0 общих 8-грамм); предсказания E0–E4 запечатаны до gold; оракул-руки после распечатывания. Модель: qwen3.8-flash (BAI), одна попытка на вход.

**Первичные метрики (holdout).**

| Рука | Сертиф. покрытие | Сертиф. точность | ERROR recall | NO_ERROR recall | Ложные NO_ERROR |
|---|---|---|---|---|---|
| E0 (H0+Cons) | **0.554** | 0.855 | **0.759** | **0.375** | **0** |
| E1 (GRS+Cons) | 0.509 | 0.842 | 0.741 | 0.250 | 0 |
| E2 (H0+RF) | 0.268 | 0.800 | 0.389 | 0.094 | 0 |
| E3 (GRS+RF) | 0.259 | 0.793 | 0.389 | 0.063 | 0 |
| E4 (retention) | 0.116 | 0.615 | 0.148 | 0.000 | 0 |

Hard gates: uncertified_definitive = 0 (все руки), false-certified-NO_ERROR = 0 (все руки), sealed-before-gold = 100%.

**Парные сравнения (точный McNemar).** E1 vs E0: p=0.180 (паритет); E2 vs E0: p<1e-6 (регрессия); E4 vs E0: 0 коррекций, 45 регрессий, p<1e-6. Мировые метрики: E0 mean 1.23 миров/кейс, p95 3, max 4 — переполнения бюджета нет ни в одном кейсе; E4 max 8.

**Оракул-атрибуция.** Замена фронтендовых семантик на gold (policy/goal/обе) НЕ улучшает ни один исход (53/112 дефинитивно-верных во всех конфигурациях). Узкое место — нижние слои: операционное связывание (семантический ключ действия → конвенции инструмента) и типизация/связывание клеймов. Улучшение H0/GRS само по себе не сдвигает E2E-точность.

**Ложные сертифицированные ERROR (E0: 9/112).** stale_state_claim ×4 (BOTH/freshness-семантика), closed_safe_alternative_actions ×2, inconsistent_trusted_evidence ×1 (INCONSISTENT→ERROR при read-вызове между противоречиями — документированное ограничение), closed_safe_completed_action ×1, failed_call_state_unknown ×1.

**Таксономия неудач E0.** SEMANTIC_BEHAVIOR 11, POLICY_H0 10, CLAIM_SUPPORT 7, GOAL_CONSERVATIVE 3, FALSE_CERTIFIED_ERROR 3.

**Терминальное решение: `KEEP_CONSERVATIVE_E2E`.** Продвинутая конфигурация — E0-класс: H0-фронтенд политики + Conservative-фронтенд цели, T1-доверенные эффекты, сохраняющая неоднозначность идентичность, all-world доказательное ядро, сертификат-гейтируемые вердикты, поведенческое замыкание для PROVED_NO_ERROR. Сложные кандидаты не дали реального E2E-улучшения при V1-качестве фронтендов: GRS не бьёт H0 end-to-end; RuleFrames+E5 значительно снижает рабочее сертифицированное покрытие через несовпадения конвенций связывания; retention конвертирует разногласия в UNRESOLVED без единой коррекции. Многофронтендовая архитектура реализована, world-safe и измерима — но не стоит своей цены по покрытию при текущем качестве фронтендов.

## 10. Известные ограничения V1 (измеренные, не скрытые)

1. INCONSISTENT-во-времени может разрешаться в PROVED_ERROR, когда read-вызов сидит между противоречивыми точками свидетельств (read-only контракты смягчают).
2. Value-scoped REQUIREMENT-правила невыразимы (неразрешённый терм).
3. Кардинальность выбора EXACTLY_ONE среди нескольких альтернатив — UNRESOLVED.
4. Плоская структура H0 плохо представляет многоклаузульные политики (для этого существует GRS; измерено).
5. RuleFrames V1 показывает меньший успех операционного связывания, чем Conservative (семантические content_key связываются с инструментами хуже).
6. Узкое место — нижние слои (связывание/клеймы), общие для всех фронтендов; рост качества фронтендов сам по себе не поднимет E2E-метрики.

## 11. Запуск и воспроизведение

```powershell
# Установка и тесты E2E (31 тест)
python -m pip install -e ".[data]"
python -m unittest discover -s tests/e2e -v

# Прямое использование ядра (Python)
from guardian_truth.vnext.e2e import GuardianE2EV1, E2ECaseInput
from guardian_truth.vnext.e2e.backend_v1 import build_live_backend

backend = build_live_backend(env_path=Path(".env"), cache_path=Path("outputs/e2e/cache.json"))
guardian = GuardianE2EV1(backend, arm=ARMS[0], max_worlds=4096, adapter_mode=AdapterMode.AUDIT)
analysis = guardian.analyze_e2e_v1(case)   # -> E2EAnalysis

# Экспериментальный цикл (запечатывание → gold → скоринг)
python - <<'PY'
from pathlib import Path
from guardian_truth.vnext.e2e.experiment_v1 import load_corpus, run_arm, score_arm, seal_predictions
cases = load_corpus(Path("benchmarks/vnext/e2e_holdout_v1.json"))
rows = run_arm(ARMS[0], cases, backend, progress_file=Path("outputs/e2e/e0_progress.json"))
seal_predictions(rows, corpus_path, architecture_commit="4fa2212",
                 configuration_sha256=cfg_sha, seal_path=Path("outputs/e2e/e0_seal.json"))
# gold присоединяется только после запечатывания
PY
```

Креды бэкенда — через gitignored `.env` (BAI). Сетевые вызовы всегда явные; в кэше и квитанциях секретов нет (только имена переменных окружения). Базовая точка входа `vnext.core.analyze` (B0) остаётся нетронутой и запускаемой.

Состав артефактов E2E V1: 21 модуль `src/guardian_truth/vnext/e2e/`, 31 тест `tests/e2e/`, 12 документов `docs/vnext/e2e/` (baseline audit, experiment protocol, semantics, trust boundaries, component manifest, architecture, results, failure audit, worklog, final decision), артефакты прогона в `outputs/` (прогресс-файлы рук, печати, аудиты).
