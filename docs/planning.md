# Ограниченное планирование и переходы состояния

`planning.py` ищет путь к цели только в явно заданной модели `[GUARDIAN_PLANNING]` внутри SYSTEM.
Исходные переменные читаются из графа или явного контекста модели. Предусловия, исключения (через логические выражения)
и эффекты заданы данными. Ни Python-код, ни реальные инструменты не выполняются.

```json
{
  "version": 1,
  "initial": {"phase": {"literal": "new"}},
  "goal": {"eq": [{"state": "phase"}, {"literal": "done"}]},
  "actions": [
    {
      "id": "finish",
      "tool": "complete",
      "arguments": {"ticket_id": "T"},
      "require": {"eq": [{"state": "phase"}, {"literal": "new"}]},
      "effects": {"phase": {"literal": "done"}},
      "outcome": "conditional"
    }
  ]
}
```

JSON помещается между `[GUARDIAN_PLANNING]` и `[/GUARDIAN_PLANNING]`. Инструмент `complete` должен быть объявлен
в `[AVAILABLE TOOLS]`, а его аргументы — соответствовать поддерживаемой схеме. Формат — контракт нового механизма,
не утверждение, что конкурсные данные уже размечены таким образом.

Для чтения исходного поля вместо `literal` можно использовать `fact` из [исполнителя правил](rules.md),
с явными `tool`, `role`, `field` и `entity`. Переменные `context` внутри модели доступны для привязки сущности.
Неизвестное исходное значение сохраняет неизвестность; отсутствие подтверждения нельзя заменить воображаемым успехом.

Результаты:

- `plan_in_declared_model`: путь найден при явно гарантированных в модели эффектах. Не гарантия реального мира.
- `conditional_plan`: путь требует хотя бы одного эффекта, который наступит только при успехе операции.
- `no_plan_in_declared_model`: путь не найден в исследованной явно заданной модели; не доказательство общей невозможности.
- `unknown` / `limit_reached`: данных или допустимого поиска не хватило.

По умолчанию максимум 6 шагов и 128 состояний. Посещённые состояния запоминаются; циклы не ведут к бесконечному поиску.
Статусы и источники попадают в `Review.planning`, а в режимах `graph`/`rlm` доступны смысловому проверяющему.
Они сами не выставляют метку ошибки отказа: нужно проверить цель пользователя, разрешённые исключения для эскалации
и полноту описания действий. Произвольный текст политики автоматически в эту модель не переводится.

Симуляция относится только к плану. Она не переписывает фактическую историю и не объявляет реальные вызовы успешными.
