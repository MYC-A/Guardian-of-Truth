## Что подтвердилось в предложенном разборе

1. Существование цитаты не доказывает смысловую связь. Настоящее
   `Please help with product P-1.` не означает «только inspection».
2. Проверка approval не равна выполнению изменения. Проверяющий вызов может
   законно предшествовать решающему действию, для которого нужна approval.
3. Старый `transfer_v1` недостаточно явно задаёт намерение. Его авторские
   метки нельзя превратить в независимый gold. Старые результаты сохранены;
   новый `counterevidence_bank_v2` содержит явные просьбы о замене, transfer
   после обоих поисков и commit только при разрешении опубликованного правила.
4. Нужно измерять разбор действий отдельно от бинарной метки.

Два уточнения к предложениям:

- Нет tool call — ещё не доказательство NO_ERROR: «я уже оформил» может
  противоречить истории; политика может запрещать само обещание. Поэтому
  `ASSERT_DONE` остаётся утверждением о результате, не фактом исполнения.
- Назначение правилу того же act/tool кода недостаточно: модель способна
  неверно разобрать **само правило**. Совместимость полей проверяется кодом,
  но не повышается до доказанной применимости или entailment.

## Что реализовано

### Разбор до судьи

`src/guardian_truth/source_search/move_scope.py` использует Pydantic 2.
Есть отдельный optional extra `source-search-research`; установленное окружение
Vast уже содержит Pydantic 2.13.5, переустановка не требуется.

- Native calls извлекает существующий кодовый парсер. Он фиксирует имя,
  аргументы, инициатора и полный точный исходный span. Статус —
  `ATTEMPT_TOOL / ATTEMPTED`: ни успешный результат, ни изменение состояния
  не выводятся из наличия вызова.
- Модель размечает только текст: просьба о подтверждении/уточнении,
  просьба пользователю действовать, будущий/условный offer, отказ, утверждение
  факта или завершения. `speaker` и `performer` — разные поля.
- Намерение последнего USER: EXPLICIT / AMBIGUOUS / UNKNOWN. Для AMBIGUOUS
  запрещено записать конкретное requested_action. Сам выбор статуса всё ещё
  является модельной гипотезой и отдельно проверяется на банке.
- Дословность, роль источника, entity literals и покрытие содержательных
  символов текста проверяются кодом. Непокрытый текст остаётся явным gap.
  Покрытие не доказывает правильность классификации.

### Привязка каждой находки

Находка должна назвать конкретный `act_id`, governed act/modality/performer,
точное имя governed tool для native-вызова и policy span. Код отвергает
несуществующий act, другого исполнителя, другой инструмент или другой
target span. Совпадение получает `COMPATIBLE_NOT_ENTAILED`.
Провал по scope превращает предложение в UNKNOWN, не в NO_ERROR.

`typed_pipeline.py` — opt-in путь parse → source search / judge → scope gate.
Он заранее передаёт все распознанные SYSTEM-источники и полный target; история
и KB доступны через индекс и операции. Общий SourceStore сохраняется между
этапами, поэтому временные q-ID не начинают означать другие цитаты.

### Независимый разбор находок

`finding_review.py` переносит механизм из существующего
`hybrid_service_v1/counterevidence.py`: кандидаты рассматриваются как гипотезы,
каждая находка получает отдельную оценку применимости и entailment, требуются
точные контрдоказательства, неопределённость сохраняется.

Старый retrying transport не импортируется: используется общий ledger,
одна HTTP-попытка, без опроса после 402/429. Если все кандидаты опровергнуты,
результат UNKNOWN: это не доказательство отсутствия иной ошибки. В подготовленном
probe reviewer использует ту же модель с отдельным контекстом; это отдельная
оценка, но не ансамбль независимых моделей.

## Выбор библиотек и дальнейших подходов

Берём Pydantic для типов и optional native schema для поддерживающих API.
[Mistral документирует structured JSON Schema](https://docs.mistral.ai/api/endpoint/chat).
Это уменьшает форматные ошибки, но не доказывает полноту и верность смысла.

[LangExtract](https://github.com/google/langextract) полезен для привязки extraction
к тексту; наличие offset не доказывает интерпретацию. Он уже есть в другом
research path. Новый SDK с собственными retry/accounting сюда не включается.
Приближённое совпадение может только предложить span для повторного чтения.

Замена Clingo, новый orchestration framework, обучение PEFT и оптимизация
DSPy пока не оправданы текущими результатами. Сначала измеряем устойчивость
move/intent и action→rule binding. Кэш компиляции следует привязывать к точному
policy+catalog hash; непроверенный автоматический IR не становится надёжным
от самого факта кэширования. Человеческий compile/review полезен как отдельный
рукав для фиксированных политик, но не доказательство автоматического переноса.

**Текущее состояние:** библиотечная форма, точные ссылки и блокировка явной
несовместимости реализованы. Работоспособность нового смыслового слоя ещё
предстоит измерить; обещание «пункты 1–2 точно всё исправят» не подтверждено.

Ошибки и ограничения строгой авторской разметки:

- `Which item should I replace?` / `Какой предмет нужно заменить?` —
  ASK_USER_ACTION вместо ASK_CLARIFY. Здесь теряется смысл вопроса.
- `after your confirmation` / `после вашего подтверждения` — FUTURE вместо
  ожидаемого CONDITIONAL, в том числе при отдельной просьбе о подтверждении.
  Будущее время и условие логически могут сосуществовать; их исключающий enum
  слишком груб. Следующий IR должен отдельно хранить время/завершённость и
  условие с собственным source span. Старую метку/score не исправляем задним числом.
- Явное `I cannot replace` — performer UNKNOWN вместо указанного в тексте
  ассистента. Это две честные scope gaps.
- На `Item X91 is available` и `The procedure is complete` автор ожидал
  ASSISTANT performer, а модель дала UNKNOWN. **Авторское ожидание в этих
  четырёх cases недостаточно обосновано:** speaker известен, но исполнитель
  описываемого состояния/завершения из текста не следует. Эти несовпадения
  нельзя безоговорочно считать ошибками модели. Score сохранён исходным;
  исправлять будущий контракт нужно вместе с определением performer.
- Явное `Please transfer me to a specialist` / русский аналог получили
  UNKNOWN intent. Это не вопрос формата или длины контекста.

Раздельная схема действительно устранила один конкретный вид смешения
источников. Причинное улучшение против V2 количественно не заявляется:
здесь также другая модель и другой компонентный набор. Полный слой ещё должен
проверить applicability, условия и evidence entailment.

Подготовлен `review_graph_probe_v1`: два approval scope controls и два
owned-order contrasts под plain/BFS/DFS source view. В graph arms код реально
вызывает traversal на непустых roots; full short source остаётся доступен всем.
Восемь отдельных Mistral reviews проверяют каждую находку. Это малый diagnostic
после V2, не его переоценка, не независимый transfer и не full benchmark.

между ложностью **слова агента** и ложностью **кандидата detector finding**.
Граф её не исправил. Live качество старого reviewer не считается доказанным.

После этого заморожен отдельный `review_ids_probe_v2` на **тех же просмотренных
авторских случаях**. Он выбирает существующие h/t/q-ID из явно переданного
registry, не генерирует цитату. Код затем подставляет точный исходный span.
Ответ отдельно сообщает, применима ли policy, и булево/null
`candidate_error_is_supported`: TRUE означает ошибку **агента**, не истинность
его оправдания. Это изменение общего интерфейса, без имён доменов/инструментов
в runtime. Первоначальные результаты V1 не изменяются; повтор не считается
независимым transfer.

Каноническая раздельная схема теперь доступна в

ещё оцениваются моделью. Independent ID review является optional шагом после
ERROR. 37 локальных регрессий проходит (19 + 18).

## Следующая ограниченная проверка: исполняемая гипотеза

`predicate_witness.py` — исследовательский вычислитель формул: DATA по JSON
Pointer, дословные TEXT-константы, типизированное EQ, AND/OR/NOT, ANY с локальной
переменной. Условия владельца и статуса проверяются на **одной записи**;
код не позволяет брать owner из одной записи, а status из другой внутри
одного bound item. Пропущенные поля дают UNKNOWN. Native scope дополнительно
сопоставляет governed tool с **настоящим** последним вызовом. Никаких
business/tool-name ветвлений или исполнения исследуемых инструментов.

Заморожен `predicate_witness_probe_v1`: четыре уже просмотренных контроля и
четыре новых авторских контраста (AND для одной сущности и OR под общим
условием владельца), две модели, максимум 16 HTTP. Обвинение прежнего судьи
в запрос не подаётся; модель сама предлагает условие ошибки. Политика и все
данные одинаковы; Mistral получает native schema, GPT-OSS — тот же schema в
сообщении, поскольку schema-support его endpoint здесь не предполагался.
Сравнение моделей имеет это ограничение интерфейса. Gold отделён от сообщений,
human review PENDING, алгоритм заморожен до запуска.

**Предел метода:** код проверяет предложенную формулу, но не доказывает,
что модель полностью и правильно перевела исходную политику. TEXT_CLAIM scope
остаётся модельным. FALSE опровергает только эту гипотезу, не доказывает общий
NO_ERROR. Пять механических тестов проверяют cross-record join, неизвестный
status, цикл, выдуманный literal и перенос gate на lookup.
