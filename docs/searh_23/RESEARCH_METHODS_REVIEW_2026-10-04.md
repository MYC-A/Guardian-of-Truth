# Что дают новые исследования для Guardian

Дата: 2026-10-04. Ветка: `research/evidence-graph-probe-20261004`.
Основной checkout другого агента сохранён. Это разбор предложений и текущих
свежих результатов; новых модельных фаз во время обзора не запускали.

## 1. Что действительно получилось

Завершены **94/94** запроса frozen A/B,
расход **399 533** токенов по provider usage, неизвестный расход — 0.
Модель обоих рукавов — `ministral-14b-latest`. Повторов и HTTP-сбоев нет;
Supervisor-задача завершилась, новых очередей не запускали.
Источники: `outputs/searh_23/evidence_graph_address_probe_20261004/`
(`progress.json`, `score.json`, `admissions.json`, `raw/`).

| Проверка | A: числовые позиции | B: точные цитаты |
|---|---:|---:|
| Принятые EFFECT | 16/16 | 11/16 |
| Принятые INVENTORY | 2/31 | 0/31 |
| Решения текущих native вызовов | UNKNOWN 37/37 | UNKNOWN 37/37 |

«Принят» означает, что ответ прошёл проверки схемы и адресов. Ни правильность
смысла, ни полнота политики этими числами не измерены. TP/FP здесь не считаем:
конкурсные метки не открывались. Это полный итог первоначальной очереди.

У A 15 INVENTORY отклонены из-за arity формулы, 14 — из-за привязки к чужому
окну. У B 29 INVENTORY отклонены из-за отсутствующей/неоднозначной цитаты,
один — из-за arity, один — из-за невалидного/незавершённого JSON.

У A первое принятое INVENTORY имеет статус **UNRESOLVED**, 19 узлов и 12
использований одного ответа. Второе имеет статус REVIEWED, 21 узел и 11
использований. Поэтому `requirements_logical=459` означает повторные
использования 40 узлов двух ответов, не 459 разных правил.
Оба ответа не выдерживают проверки источника. Примеры первого:

- `obtain_explicit_user_confirmation` указывает на
  `d.\r\n- If the status is **delayed** or **on time**,`;
- `valid_json_only` — на `t has not `;
- `communicate_in_russian` — на `my**, **business**. `.

Дословные короткие обрывки здесь — наши входные данные, не цитирование статьи.
Позиции существуют, но не подтверждают извлечённые утверждения. Сохранён
`accepted_inventory_source_audit.json` с точными адресами и исходными строками.
У второго ответа `authenticate_user` ссылается на вводное описание вариантов
хода (`turn you can either ... Make a tool call`), а `cancel_order` — на
обрывок `Try to be helpfu`. Статус REVIEWED не устанавливает верность разбора.

Также проверены все 16 EFFECT-ответов A: только 10 наборов action-span
достигают содержательного описания, остальные указывают на обрывки имён или
разделитель. В B точная цитата не мешает модели назвать математический
`calculate` изменением состояния. Это проверка поддержки исходным описанием,
а не измерение конкурсной точности.

Обходы BFS/DFS и полный обратный поиск ещё не измерены моделью: очередь
исполняет только INVENTORY/EFFECT, LINK/WITNESS не запускались. Делать вывод
«новый граф не помогает» по этому опыту пока нельзя. Извлечение не подготовило
надёжный материал для такого сравнения.

## 2. Какие разные ошибки надо закрыть

| Ошибка | Что её действительно ограничивает | Что остаётся неопределённым |
|---|---|---|
| Модель придумала позиции/изменила цитату | Адреса, выданные кодом; локально ограниченное копирование | Верна ли выбранная цитата по смыслу |
| AND/BEFORE без нужного числа детей | Грамматика дерева с arity в wire schema | Правильный ли оператор и область его действия |
| Условие перенесено с исполнения на lookup | Независимая проверка scope и контрасты по исходному правилу | Достоверность семантической проверки |
| Потеря AND/OR, исключения, общего IF | Сравнение интерпретаций, обратная вербализация, контрпримеры | Пропущенные исходные директивы |
| Одобрение другой сущности/после действия | Native связи, parent ID, порядок событий в коде | Правильно ли распознано содержание согласия |
| Нужный факт далеко внутри длинного результата | Поиск по окнам всего источника | Выбрана ли правильная связь факт → условие |
| Не найдено само требование | Учет всех исходных участков и незакрытых задач | Полнота смысла не доказывается покрытием символов |

## 3. Разбор предложенных работ

### Roundtrip Verification and Repair — приоритет для проверки смысла

Метод делает независимые переходы NL → F1 → NL' → F2, сравнивает F1 и F2
в SMT и локализует этап для исправления. Авторы прямо предупреждают о
стабильной неверной интерпретации: эквивалентность не доказывает верность
исходному NL. NLI служит дополнительной диагностикой. В их опыте используется
фиксированная схема предметной области с ручной доработкой, более сильные
модели и до пяти исправлений синтаксиса на формулу.
[Статья, v3](https://arxiv.org/html/2604.25031v3).

Теперь доступен реальный [репозиторий](https://github.com/daneshvar-amrollahi/roundtrip-autoformalization).
Проверен commit `a0bd0bef6461a66ccb02820ed5d794e755234c5c`: orchestrator,
prompts, схемы, repair и Z3 checker существуют; файл LICENSE содержит MIT.
Полезно перенести stateless стадии и локализацию ошибки. Перед переносом
нужна адаптация: SDK-клиент делает до восьми автоматических повторов, а
traffic prompt допускает приближённое кодирование и отображает `may` в
existential. Для нашей нормативной семантики разрешение не означает, что
действие действительно произошло. Это вывод из прочитанных prompts, а не
обнаруженная ошибка на данных авторов.

Проверен ещё один технический риск. Авторский
[Z3 checker](https://github.com/daneshvar-amrollahi/roundtrip-autoformalization/blob/a0bd0bef6461a66ccb02820ed5d794e755234c5c/src/z3_checker.py)
ищет подстроку `unsat`, не проверяя return code и сообщения об ошибке.
В контролируемом mock с ошибкой про символ `unsatisfied`, return code 1 и
отдельной строкой `sat` он вернул UNSAT. Это offline проверка парсера ответа,
**Z3 не запускался**. При переносе нужен строгий разбор статуса, отказ при
ошибках и извлечение реального countermodel.

### QuoteLLM — полезный способ получения адресов, с ограничениями

В [QuoteLLM](https://github.com/mwestera/quotellm) есть реальный
`LogitsProcessorForQuotes`: маскирует генерацию локальной Hugging Face модели,
чтобы цитаты были фрагментами исходного текста. Это кандидат против ошибок
копирования и подсчёта позиций. Проверен commit
`493847be8f5b637a53511c87954f39a31b7347c4`; default `must_unique=False`
выбирает одно из повторных вхождений. На повторённом одобрении двух родителей
этот выбор воспроизведён без модели. Нужны unique/occurrence binding и проверка
tokenizer. В API Mistral такой клиентский logits hook не предоставляется;
для текущего API практичнее ID исходных фрагментов. Репозиторий без LICENSE;
код пока не переносился.

Дословность не доказывает поддержку утверждения и не обнаруживает пропущенную
директиву. Модель всё ещё может выбрать настоящее правило про другое действие.

### CHyD — интересная грамматика копирования, готового decoder нет

CHyD ограничивает extractive участок допустимыми продолжениями suffix tree
контекстов. В статье различаются literal faithfulness и правильность ответа:
для Mistral-Nemo на одном SEMAeroSQuAD режиме EFA 0.983 при EM 0.368.
[Статья](https://arxiv.org/html/2609.10046v2).
В указанном [репозитории](https://github.com/quentin-sgn/Constrained-Hybrid-Decoding),
commit `7f97c93de7259b1d8a836314967fce4b5e9108ee`, только README и dataset,
decoder и LICENSE отсутствуют. Поэтому сейчас можно воспроизвести механизм,
но нельзя просто установить опубликованный decoder. На текущем remote API
это также не подключаемая библиотека.

### Grammar-constrained extraction — взять проверку структуры

Исследование grammar-constrained extraction относится к fine-tuned моделям
на 211 аннотированных clinical trial abstracts. Ухудшение pointer-generator
в этом опыте не доказывает непригодность любого выбора адресов.
[Статья](https://www.frontiersin.org/journals/artificial-intelligence/articles/10.3389/frai.2024.1406857/full).
Для нас полезен общий механизм: допустимые формы формулы и адреса должны
задаваться декодированию. В исходном API-рукаве Python validator arity не
переносился в JSON Schema; именно это уже исправлено в следующем кандидате.

### Defeasible Deontic Logic — представление норм, не готовый extractor

В работе DDL двухэтапная схема atoms → rules уступила лучшему варианту
без этого разделения; авторы связывают основной сбой с извлечением atoms.
[Статья](https://arxiv.org/html/2506.08899v1).
Заимствовать имеет смысл явные obligation/permission/prohibition и
приоритеты исключений, если они установлены самой политикой. Простая замена
на DDL не установит правильный governed action и не восстановит пропущенные
условия. Приоритет «частное всегда важнее общего» автоматически не выводим.

### ProoFVer и Know Your Limits — контроль доказательств

[ProoFVer](https://aclanthology.org/2022.tacl-1.59/) строит цепочки natural logic
для fact verification; [код](https://github.com/krishnamrith12/ProoFVer)
содержит обучение и inference поверх GENRE. Это полезный образец проверяемой
цепочки claim/evidence, но не готовый переводчик tool policy с временем,
сущностями и обязательствами. Сейчас не добавляем его стек зависимостей.

[Know Your Limits](https://arxiv.org/html/2606.16118v1) разбирает ошибки
автоформализации и LLM-интерпретации solver в юридических задачах. Для нас
практический вывод: статус solver и arithmetic вычисляет код; модель не может
объявлять их результатом доказательство, которого инструмент не вернул.

### Req2LTL/OnionL — уже исследовано

Не повторяли прежнее сравнение. В нашем frozen A/B/C/D на 12 политиках все
рукава имели exact IR 0/12; C не собрал финальные директивы, D собрал одну
без совпадения. Это ограниченное воспроизведение методов, не опровержение
статей. Подробности и ограничения в
[отчёте сравнения](REQ2LTL_NL2LOGIC_ARCHITECTURE_COMPARE_2026-09-27.md).

## 4. Практический контроль границ roundtrip

Запущен `experiments/searh_23/research_methods_review/limits_probe.py`.
Результат: `outputs/searh_23/research_methods_review_20261004/limits_probe.json`.
Без API, моделей, GPU и установленного solver; полный перебор булевых
назначений для вручную заданных формул. Это контрпримеры свойствам метода,
**не новый тест качества модели**.

Исходное правило: выполнение требует одобрения, проверять его наличие можно
без одобрения. Правильная формула: `execute → approval`. Неверный перевод:
`lookup → approval`. Если обратный перевод и следующий compiler сохранят
эту ошибку, F1 ≡ F2 пройдёт на всех восьми назначениях. Но два назначения
различают неверную формулу и исходную семантику.

Перебор также находит отличия при AND → OR, потере исключения, потере
parent/time binding и перестановке необходимого и достаточного условия.
Всего сохранено 10 различающих назначений. Это показывает, зачем проверять
перевод относительно источника отдельно от его самосогласованности.

## 5. Что подготовлено и что имеет смысл измерить дальше

**Уже написано, моделью ещё не измерено:** кодовые span ID, arity в wire
schema, явная семантика condition/guard/modality, запрет чужого inventory
anchor, BM25 по всем окнам длинного источника. Структурный тест доставляет
свидетельство из участка после 40 тысяч символов. Это проверка доставки,
не измерение верности witness. Старый frozen A/B не исправлялся.

У нового worker отдельно закрыты восстановление breaker после сохранённой
ошибки, незавершённые резервы расхода, redirected HTTP, идентичность cache и
ledger. Исправления инфраструктуры не считаем ростом конкурсного качества.

**Порядок следующей проверки:**

1. Первоначальная очередь завершена без изменений, причины отказа сохранены.
   Новые фазы во время этого обзора не запускались.
2. Маленький frozen опыт с ID/arity на той же модели: отдельно admission,
   поддержку span исходным текстом и completeness. Он проверяет комбинацию
   изменений, а не чистый эффект адресации.
3. Для валидных формул сравнить без проверки перевода / с roundtrip /
   с roundtrip плюс независимой проверкой исходного правила. Входным
   сторонам roundtrip не давать исходный NL там, где статья его не даёт;
   независимой проверке наоборот дать original, родительский контекст и
   смысл выбранных predicates. Она не должна видеть объяснение агента.
4. Контрасты выводить из исходной нормы до открытия ответов compiler:
   lookup/execution, AND/OR, exception, другой parent, approval after action,
   permission без выполнения. Самогенерация тестов из F1 не является
   независимой проверкой F1. Синтетические author controls отделить от
   реальных входов; ручной reference не объявлять машинным доказательством.
5. Считать ошибки и пропуски проверки, не только долю принятых формул:
   неверный IR пропущен фильтром / правильный отвергнут / UNKNOWN,
   scope, modality, logic, time, source support, API расход.
6. Только после этого сравнивать поиск/обходы на одном зафиксированном IR.
   Отдельно автоматический IR и вручную проверенный diagnostic IR: первый
   измеряет цепочку целиком, второй локализует ошибку поиска. Не смешивать их.

Roundtrip сам по себе не переводит слой в DECISIVE. Положительный статус
возможен лишь для той локальной проверки, для которой установлены source,
применимость, факты и native binding. Отсутствие найденного нарушения не
разрешает выводить NO_ERROR при неполном разборе политики.

**Рекомендация:** сначала кодовое владение адресами и корректная структура,
затем контроль верности перевода с независимыми контрастами. QuoteLLM —
возможный отдельный локальный decoder-опыт. DDL/новый граф/другой обход сами
по себе нынешний сбой извлечения не закрывают. Пользовательские предложения
содержат полезные механизмы; готового универсального Guardian в них нет.
