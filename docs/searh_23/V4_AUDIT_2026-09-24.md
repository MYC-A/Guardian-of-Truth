# v4 FP layer audit and repair (2026-09-24)

Base: `0a248f2`. The Mistral extraction and pgjudge outputs are frozen inputs in
this audit; the model calls were not rerun. The deterministic layer was replayed
on both saved sets after the repair.

## Findings

- The structural guard fires on hotel `pair12::viol` and `pair13::viol`, but is
  **decisive for only one TP**. With the guard disabled, `pair12` still has a
  `KEEP` card, while `pair13` changes from TP to FN.
- The original history-satisfaction check searched IDs only in response prose.
  A tool-only response therefore supplied no target ID, and an unrelated
  approval could discharge the card. Changing the target reservation in
  `pair13::ok` from `R-2301` to `R-9999` while leaving approval for `R-2301`
  still produced `REFUTED, REFUTED` before this repair. That is a counterexample
  to the claimed entity binding of the layer given the same candidate cards;
  it is not a measured full pgjudge run on the changed input.
- The old scorer held `FN = base_fn` when a TP was cleared. Its reported recall
  was therefore 1.0 in the no-guard ablation despite one lost TP. Correct
  no-guard metrics are TP13/FP3/FN1, recall .9286, F1 .8667.

## Repair

- For action calls, read the target reservation and refund amount from parsed
  call arguments. For text responses, use an explicit reservation in the
  response or latest user turn; an explicit incident number can bind an
  incident claim. Ambiguous or absent targets cannot discharge an observed
  precondition.
- Parse tool observations as JSON and require matching target ID and expected
  tool family. Approval for a different amount cannot discharge a refund
  precondition. Remove the inference that `cancelled_at` or a late-checkout log
  itself satisfies identity verification.
- Count every cleared TP as an FN in the output metrics.

reservation, a foreign approval reservation, a mismatched approval amount,
and the no-guard scoring/causality check. They do not establish transfer to a
new domain. Public46 informed v3 and hotel informed v4; hotel also contains
three `::ok` labels that the original report calls lenient or artifacts.
Promotion still needs a frozen run on new trajectories with independently
adjudicated labels.
