## Что изменено

1. `SourceStore` сохраняет неизменённые prompt/response, все события, включая
   текстовые KB/tool results, offsets и SHA. Неудачная JSON-структуризация
   не удаляет текстовый источник. Индекс фактов строится из полного контекста.
2. Начальная проекция ограничена; lookup/поиск/пагинация читают полный индекс.
   Цитаты в графе хранятся как ссылки на единый реестр спанов, без копий текста
   у каждого факта. Явные co-recorded связи не называются разрешением/владением.
3. Поиск выполняет один запрос, возвращает результат модели и лишь затем
   получает следующий запрос. BFS/DFS реально обходят индекс с visited/frontier.
   Судья может запросить дополнительные источники после перехода к оценке.
4. Date отличается от datetime; у datetime без зоны нет угадываемой зоны.
   Decimal поддерживает явно записанные группы тысяч. Операнды — точные
   source spans, не свободные числа модели. Арифметика не подтверждает сама
   применимость правила, привязку сущности или единицы.
5. Не закрытые проверки и непрочитанный существенный остаток запрошенной
   страницы приводят к UNKNOWN. Закрытие вопроса требует цитаты и причины;
   семантика причины остаётся модельной, гарантии полного понимания нет.
6. Исправление ссылки разрешено только по уникальному точному совпадению.
   Сырой ответ сохраняется и при ошибке валидации; UNKNOWN не именуется NO_ERROR.
7. Приём входа отделён от окна модели: structural выполняется на принятых
   входах до проверки модельного окна. Новый профиль принимает до2M символов.
8. HTTP transport делает одну попытку. 402/429 и другие постоянные HTTP
   ошибки открывают breaker всего batch; нет автоматического polling/retry.
   SQLite резервирует бюджет до вызова; успешный usage и неизвестные bounds
   учитываются отдельно. Прежний ledger не изменяется.

`scripts/predict.py` и default существующих сервисов не менялись.

### Последовательно выявленные технические ошибки

1. Малый диагностический запрос с `reasoning_effort=none` вернул
   `finish_reason=tool_calls` и пустой текст. Это настоящий вызов функции,
   который текстовый JSON-адаптер ошибочно отклонял. Исправление сохраняет
   native tool frame и возвращает результат с тем же `tool_call_id`.
   Запуск неподтверждённых бизнес-инструментов запрещён allowlist проверяющих
   операций. У Ollama документированы [OpenAI tool calling и reasoning_effort](https://docs.ollama.com/api/openai-compatibility);
   `none` здесь не является гарантией качества или отсутствия reasoning-поля.
2. После этого модель запросила `read_source(h0,start=0,end=200)` для
   60-символьного источника. Наш код отклонял нормальное чтение до EOF.
   Теперь конец ограничивается реальной длиной, возвращается явный флаг
   clipping; недопустимое начало или отрицательные границы по-прежнему
   отклоняются. Ошибка native-операции также получает корректный tool reply.
3. Повтор на закреплённом `e08a37df` прошёл native round trip: модель прочитала
   h0, затем h1, перешла в JUDGE. **Транспорт работает, результат UNKNOWN.**
   Судья предложил ERROR, заполнив лишь grounds из пяти обязательных checks;
   остальные не подтверждены. Пример — авторский механический контроль без
   полноценного каталога инструментов, его нельзя использовать как независимую
   оценку семантической точности. Трасса: `source-search-native-eof-probe/result.json`.
4. V7 даёт судье одну ограниченную возможность прочитать недостающие источники
   и заполнить названные кодом проверки. Это проверено отдельной регрессией
   и реальным дополнительным вызовом: модель перечислила все пять checks,
   но три NOT_APPLICABLE оставила без источников. Итог снова UNKNOWN. Без закрытия существенных
   вопросов итог остаётся UNKNOWN. Изменения после V4 касаются общего протокола,
   не словарей/правил под конкретный домен; V4 gold открыт только для отдельно
   обозначенного исторического отчёта, новый transfer gold в runtime не подаётся.

Этот пример нельзя повысить в эталонный FP: у механического контроля нет
полного каталога полномочий и независимой разметки. Но ошибочные переходы
в объяснении видны непосредственно, независимо от итоговой метки.
