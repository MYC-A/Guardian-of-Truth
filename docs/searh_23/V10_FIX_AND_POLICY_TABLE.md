### B2–B4 выполнены локально

Добавлены pydantic schema, кодовая сегментация исходных parent-пунктов,
динамические enum'ы по каталогам и реальным JSON results, сборка трёх
независимых samples и чистый трёхзначный evaluator. Только 3/3 совпадения
дают DECISIVE, 2/3 — SHADOW; повтор одного rule в одном sample не добавляет
голос. Неподдержанные paths/types и неполные правила отбрасываются.
Статус cache заново проверяется по сохранённым samples: файл не может
самостоятельно повысить 2/3 до DECISIVE.

Evaluator не выдаёт NO_ERROR; отсутствие/неоднозначность поля, несовпадение
сущности, неоднозначное pairing и непрочитанный новый observation не
превращаются в FALSE. Последний matching result без нужного поля не
заменяется более старым значением. TRUE/UNRESOLVED exception suppresses
finding. Код проверяет вызов до target, не приравнивает попытку к success.

REQUIRES — конъюнкция необходимых условий; FORBIDS — конъюнкция запрещённых
условий. Необходимое `A OR B` нельзя без изменения смысла превратить в два
независимых REQUIRES: текущие fixed slots должны оставить такой пункт
непокрытым. UNRESOLVED хотя бы одного необходимого условия подавляет finding.

Подготовлено 12 compiler requests, 4 хэша × 3 samples, GPT-OSS:120b/medium,
без API. Исходные inventories: 73/38/177/40 parent-пунктов,
301/959/101/43 путей, включая реальные arrays/objects. Это не найденные
директивы и не metric полноты.
`user.confirmation_of_trigger` и `ctx.current_datetime` пока не имеют
source-bound witness; conditions с ними не могут получить DECISIVE.
Неявная timezone и свободное semantic scope не были заполнены догадками.
Расширены проверки разных сущностей, массивов, вложенных аргументов,
двух непривязанных текстовых аргументов, типизированных идентификаторов,
OR/AND исключений и timezone. Пользовательский вызов не закрывает обязанность
ассистента. Если последняя запись нужной сущности потеряла поле, старое значение
не переиспользуется; более новая запись другой сущности не стирает нужную.
Измерение моделей и compiler coverage впереди.

Пользователь разрешил считать исправление условия по конкретному правилу,
без выдуманного NO_ERROR всего ответа. Положительный контрактный мутант
тоже будет явно зависеть от корректности скомпилированного правила; совпадение
трёх samples само по себе не превращается в независимый gold исходной политики.

### Расхождения исходного задания (первоначальная остановка)

1. Раздел 0.4 утверждает отсутствие негативных контролей в последних
   transfer-прогонах. В обоих frozen наборах **8 входов: 4 с авторской
   меткой 0 и 4 с меткой 1**, четыре контрастные пары. Каждый рассчитан
   на 16 результатов двух рукавов. Все метки действительно PENDING;
   наличие отрицательных примеров не делает их независимым gold.
2. Раздел 0.2 говорит о контексте около 9k tokens. В 35 direct model
   records фактический provider `prompt_tokens`: минимум **5149**,
   максимум **79598**, среднее **16175.86**. Search дороже в 3.23 раза
   по новым известным токенам — это подтверждается; утверждать одинаково
   короткий контекст для всех случаев нельзя. Самый большой сериализованный
   запрос direct занимает **417040** bytes, хотя raw input меньше 400000.
   Raw threshold и размер полного API запроса нужно учитывать отдельно.
3. A2 требует тест «в FINAL нет ни одного имени из TOOLS» одновременно
   с сохранением оригинальных входов. `calculate` есть и в TOOLS нашего
   verifier, и в исходном каталоге проверяемого агента; текущий target
   `airline__7::t6` сам вызывает `calculate`. Удалить слово из FINAL
   означало бы изменить исходный target/политику. Совместимый тест должен
   проверять отсутствие **добавленных сообщений/операций verifier**, сохраняя
   имена, исходно присутствующие в проверяемом входе. Это уточнение условий
   приёмки было уточнено после команды пользователя продолжить локальную работу.

### Уточнение диагноза восьми FN

Причина «проверяет только истинность утверждений» объясняет часть ответов,
но не установлена как единственная причина всех восьми. Например,
`retail__36::t10` прямо заявляет, что пользователь подтвердил изменение

применимость/выполненность правил, пусть оценка может быть неверной.
В других ответах действительно доминирует «no contradictory or unsupported
claims». По одной формулировке объяснения нельзя доказать общую причину
каждого пропуска. Все восемь оригинальных explanations сохранены в audit.json.

### A3 / runtime: реализовано до измерения качества

`src/guardian_truth/action_audit/` добавляет в **один** direct-запрос атомарные
слоты по каждому native-аргументу, вопросы о ранее известном значении,
перечень доступных/испробованных шагов для отказа или перевода. Сырые prompt
и response сохранены без изменений. Native-перевод аннотируется отдельно
как гипотеза эффекта попытки; он не превращается в выдуманный текстовый акт.

Код проверяет источники, реальные значения, тип поля из каталога и арифметику
через существующий `source_search.calculations`. Assistant rationale не
принимается как независимый источник. Внутреннее `result.role` парсера означает
requestor, поэтому результат инструмента определяется по `kind=result`,
а не по ошибочному ожиданию `role=tool`.

Проверка известного ответа требует точного поля/JSON Pointer, однозначного
значения и сущности из текущего запроса; устаревшее наблюдение не используется.
Неустановленная семантика вопроса явно помечена как model frame, не как
доказанный кодом смысл. Неструктурированный ответ без надёжной field-binding
остаётся UNRESOLVED. Непопробованный шаг сам по себе — только кандидат.
Неполный/невалидный audit **не меняет** независимо валидный голос судьи.

`service/runtime.py` считает таблицу сразу после structural и сохраняет её
shadow-лог даже при structural short-circuit. Unknown policy hash пропускается
без онлайн-компиляции. Новый `guardian-v10.json` оставляет оба слоя в shadow;
решающий режим требует sealed score и выполненных promotion-критериев.
Сравнительные проекции в `v10.variants` используют общий судейский запрос
с audit-слотами: они не выдаются за чистый новый A1+A2 counterfactual.

На совместном наборе новых и существующих source-search тестов: **132 passed**.
Модельное качество A3 пока не измерялось. До финальной заморозки разрешён
только format smoke ≤4 вызовов без подсчёта качества.
