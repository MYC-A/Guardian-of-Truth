# Один управляемый цикл неопределённости

Статус: эксперимент, **выключен по умолчанию**. Это не новая причинная модель мира
и не ослабление строгого claim gate. Исходная точка — V2 `a7500ef`;
обоснование — [аудит baseline](v2_baseline_error_analysis.md).

## Гипотеза и границы

Причина отказа от решения может выбирать полезное следующее действие. Проверяем
это против простого повторного вызова на тех же данных, а не только против одного
вызова: иначе эффект дополнительной генерации ошибочно приписывался бы архитектуре.

Наблюдения V2: 13 уверенных ответов отклонены валидатором, 5 не получены/усечены,
явных модельных UNKNOWN — 0. Поэтому **INVALID_OUTPUT не является смысловым UNKNOWN**.
Уверенные, но неверные выводы при формально корректном ответе этот механизм может
вообще не заметить. Автоматически объявлять их неопределёнными по эталонной метке нельзя.

Минимальные действия:

| Причина | Когда появляется | Действие |
|---|---|---|
| INVALID_OUTPUT | Получен JSON, но строгая оценка отклонена | Повторная проверка согласованности и ссылок на том же контексте |
| MISSING_EVIDENCE | Модель явно оставила claim UNKNOWN и назвала недостающий источник, правило, исключение или значение | Один существующий read/search/graph/entity; затем повторная оценка |
| OTHER | Причина не определена или не входит в проверяемые категории | Сохранить причину, не запускать произвольное действие |

Ошибки API, усечение и неразбираемый JSON остаются отдельными техническими кодами;
мы не выдумываем для них claim/need и не выдаём их за нехватку фактов.
Нехватка условия пока частный случай MISSING_EVIDENCE, а не отдельная подсистема.

## Минимальное состояние

`uncertainty.py` хранит claim/kind/reason/need/known_evidence/attempted_actions и
безопасно нормализованный локальный запрос. В `reading_trace` сохраняются исходное
объяснение модели, claims, результат валидатора и использованные источники, даже
если классификация отклонена. Это диагностические гипотезы, не доказательства.

Во втором адресном запросе передаётся ограниченный снимок предыдущих claims:
прежний verdict, причина, источники и текущее состояние доступности доказательств.
Вытесненный источник нельзя цитировать; связанное текущее состояние становится UNKNOWN.
Прежнее суждение сохраняется для истории. Модель вправе пересмотреть любое суждение,
а итог всё равно должен покрывать все существенные claims и пройти прежнюю проверку.
Автоматического слияния старого score с новым, замораживания и ручных весов нет.

При чтении окно может один раз вытеснить старые фрагменты, но его максимальный размер
не растёт. Записываются найденные ID, реально добавленные и не вместившиеся, вытесненные
источники. `no_new_evidence` не означает «факта не существует». Если новый источник не
доставлен, адресная ветка останавливается без дополнительного смыслового вызова.

Схема: [PlantUML](09_uncertainty_recheck.puml).

## Контролируемое сравнение

`scripts/ablate_uncertainty.py` фиксирует конфигурацию, хэши кода/данных, выбранные ID
и порядок веток **до API**. Поля id/label/explanation не попадают в модельный запрос.
Точные механические нарушения обходятся без модели.

Для остальных строк:

1. `initial`: одна генерация с дополнительным описанием structured unknown.
2. `directed`: тот же первый ответ, затем не более одной адресной попытки при подходящей причине.
3. `repeat`: тот же первый ответ; если причина допускает действие, повторная генерация
   с полностью теми же входными сообщениями, без нового контекста и подсказки причины.

Первый ответ переиспользуется локально, повторно не оплачивается и не учитывается
в HTTP-бюджете. Порядок двух дополнительных веток чередуется. Неподходящие случаи
сохраняют initial без лишнего вызова. Любые неудачи остаются в знаменателе метрик.

Это сравнение **пакета** «причина + действие + память» против обычного повтора.
Оно не изолирует индивидуальный вклад каждого поля. Initial отличается промптом
от исторического V2, поэтому его изменение нельзя целиком приписывать циклу.

Первый ограниченный запуск на 12 строках выбран сортировкой SHA-256 от ID,
без использования меток/найденных ошибок:

```powershell
python scripts/ablate_uncertainty.py --input valid.parquet --output-dir outputs/uncertainty_screen_20b --env-file .env.example --backend groq --model openai/gpt-oss-20b --mode graph --limit 12 --max-evidence-chars 4800 --max-output-tokens 2048 --max-requests 90 --max-input-chars 2000000 --seconds 1800 --retries 3
```

Критерий включения: положительный F1 против initial **и** repeat, разбор новых FP
и корректности причин. Малый изученный valid даже при улучшении не доказывает перенос
на hidden test. При отсутствии эффекта не расширяем таксономию и не усложняем граф.
