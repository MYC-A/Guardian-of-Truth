# Что работает, куда развиваемся и как измеряем пользу

Состояние после этапа 2. Это описание существующего кода и план, а не обещание конкурсного результата.
Главный принцип: развивать переносимые механизмы проверки, а не коллекцию исправлений для `valid.parquet`.
В этой итерации меняются только документы и схемы, не алгоритм детектора.

## 2. Что сейчас действительно работает

| Часть | Что делает | Граница возможностей |
|---|---|---|
| Вход и выход | CSV / Parquet, `prompt` и `response` в детектор, CSV `id,label`, подробный JSONL | Упаковка и исполнение на конкурсной платформе не проверены |
| Разбор | Два формата истории, роли, вызовы, результаты, символьные ссылки на исходник | Это не универсальный разбор произвольного текста или защита от всех неоднозначностей разметки |
| Каталог и схема | Доступность инструмента, обязательные поля, типы, вложенность, перечисления | Только поддержанное описание; динамические инструменты и свободный текст ограничены |
| Обязательства ответа | Отдельные текстовые блоки и вызовы, список нужных проверок | Нет выделения всех атомарных утверждений и доказательства полноты смыслового разбора |
| Граф | Наблюдения, поля, идентификаторы, связи предыдущих версий, сопоставление аргументов | Это структурные связи, не доказанные владение, состояние мира или разрешение действия |
| Поиск источников | По словам и идентификаторам, ограниченный пакет фрагментов | Не смысловой поиск и не RLM; важное основание может не попасть в пакет |
| Смысловой интерфейс | `SemanticAnalyzer`, контекст и проверка формата результата; отключённый модуль по умолчанию | Реальной LLM нет; вывод подключённого модуля остаётся гипотезой и пока не меняет CSV |
| Решение | Нарушение от точных проверок → `1`; иначе `unknown` | В CSV для `unknown` по умолчанию `0`. Это не доказательство правильности; вероятность `null` |
| Испытания | 56 автотестов; сравнение модулей и отчёт по областям на рабочем файле | Нет независимого закрытого набора, обучения, калибровки или оценки статистической устойчивости прироста |

Важная граница: на итоговую метку сейчас влияют только проверки инструмента и схемы аргументов.
Граф, поиск и интерфейс модели уже существуют, но являются подготовкой оснований для следующих модулей.
Инструкции внутри проверяемых диалогов рассматриваются как данные, а не исполняются нашей системой.

23 примера с ошибкой и 23 без ошибки.

| Вариант | Найдено ошибок | Ложные тревоги | F1 |
|---|---:|---:|---:|
| Только доступность инструмента | 5 из 23 | 0 из 23 | 0,357 |
| Только схема аргументов | 1 из 23 | 0 из 23 | 0,083 |
| Обе проверки | 6 из 23 | 0 из 23 | 0,414 |
| Обе проверки + структурный граф | 6 из 23 | 0 из 23 | 0,414 |

Граф дал **0 измеренного прироста F1**. Он построил 5 753 скалярных наблюдения, 78 связей предыдущих версий
и 191 запись сопоставления аргументов. Эти числа описывают объём представления, а не качество решения.
Прибавки отдельных модулей нельзя складывать: они могут находить одни и те же ошибки.

Нулевое число ложных тревог на 23 корректных примерах не гарантирует их отсутствие на новых данных.
`valid.parquet` уже изучен: переименование строк или случайное разделение этого же файла не создаёт независимую проверку.

## 4. Что доделать и какой эффект проверять

Оценки потенциала ниже — инженерные гипотезы по охвату задач, не измеренные проценты успеха.
Каждый блок может дать нулевой или отрицательный прирост после учёта ложных тревог.

| Приоритет и расширение | Что конкретно нужно сделать | Ожидаемый вид пользы | Как доказать пользу / основной риск |
|---|---|---|---|
| **P0. Независимый стенд** | Новые сценарии, группы источников и шаблонов, отдельная настройка и закрытый резерв; сохранять предсказания каждого варианта | Прямого прироста F1 не обещает; позволяет отбрасывать переобученные идеи | Критерии и состав групп фиксировать до итоговой проверки |
| **P1. Общий исполнитель правил без LLM** | Ограниченное представление правила: источник, область, условие, исключение; сравнения, даты, принадлежность, разрешённые переходы; результат `да / нет / неизвестно` | Может повысить полноту на явно описанных ограничениях; потенциально точный, но ограниченный по охвату слой | Не зашивать бизнес-правило из конкретной строки. Неизвестный перевод политики не считать доказанным |
| **P1. Контракты данных и изменение состояния** | Привязка аргумента к роли сущности, явные соответствия полей, подтверждённые результаты изменений, работа с частичным состоянием | Может помочь с чужими идентификаторами, устаревшими данными и несовместимыми действиями | Изменить владельца или порядок событий при сохранении значения; новое значение может быть разрешённой целью операции |
| **P2. Прямая локальная LLM как база сравнения** | Отдельный адаптер, фиксированный запрос, контроль длины, пакетная обработка, ограничения времени, простая политика метки | Наиболее широкий кандидат на увеличение охвата свободного текста; величина неизвестна | Сначала измерить простое решение. Модель может уверенно ошибаться и дать больше ложных тревог |
| **P2. Проверка утверждений с источниками** | Выделение утверждений, смысловое сопоставление, проверка совершённых действий и противоречий; сравнение с прямой LLM | Возможная дополнительная польза от точных источников и меньшего контекста | Извлечение может пропустить утверждение, поиск — основание; сложная система должна обойти простую на тех же данных |
| **P2. Политика итоговой метки** | Разделить механические нарушения и оценки модели; подобрать порог отдельно, измерить калибровку, обработать сбои и неизвестность | Позволяет использовать смысловые оценки; может улучшить баланс полноты и ложных тревог | Порог на 46 изученных строках не является переносимым решением; оценка уверенности не равна доказательству |
| **P3. Дополнительное чтение / RLM** | Запрашивать недостающие основания по необходимости, ограничить число чтений, проверять сохранность источников | Возможная экономия ресурсов или помощь на длинной истории; не обязательный прирост F1 | Сравнить с одним проходом по полному и отобранному контексту. Рекурсия может только увеличить задержку |
| **P3. Проверка отказов через допустимый план** | Выделить цель, найти разрешённые шаги с предусловиями и исключениями эскалации | Узкий потенциальный прирост на необоснованных отказах | Отсутствие найденного плана не доказывает невозможность; нельзя придумывать результаты будущих инструментов |
| **Перед отправкой. Исполнение** | Упаковка, холодный запуск, память, время всего набора, работа без сети и восстановление после ошибки | Сохранение уже достигнутого качества при реальном запуске | Быстрый тест на 46 строках не предсказывает стоимость полной проверки с моделью |

Без LLM полезно сначала сделать P0 и ограниченный P1. Но попытка покрыть произвольные политики тысячами регулярных выражений
не является целью. Неподдержанный смысл должен оставаться неизвестным, а не провоцировать ещё одну заплатку под пример.

## 5. Почему нельзя сейчас обещать «ещё +10%»

Мы не знаем состав скрытых ошибок, качество будущего извлечения и число новых ложных тревог.
Поэтому корректный прогноз сейчас — **вид ожидаемой пользы и эксперимент**, а не численный итог.

Для понимания масштаба, чисто арифметический сценарий, **не прогноз нашего решения**:
при точности 0,90 и полноте 0,30 F1 равен 0,45. Если полнота станет 0,40, а точность действительно сохранится 0,90,
F1 станет примерно 0,554 — рост на 0,104 по шкале F1, или 10,4 процентного пункта.
Сохранение точности здесь является допущением, а не свойством нового модуля.

Для каждого опыта фиксируем:

- `ΔF1` на одних и тех же независимых примерах, а также изменение точности и полноты.
- Сколько новых ошибок найдено, сколько старых находок потеряно и сколько новых ложных тревог появилось.
- Результат по ранее не виденным областям, шаблонам политик, длинам и форматам истории.
- Время, пиковую память, число вызовов модели, сбои и долю неопределённых случаев.
- Интервал неопределённости парного сравнения с пересэмплированием целых независимых групп, а не отдельных производных строк.

Пример порога практической полезности для будущего плана: `ΔF1 ≥ 0,02` при заранее допустимых ложных тревогах
и ресурсах. Это **предлагаемый критерий принятия**, не прогноз и не уже утверждённый порог.
Если интервал различий слишком широк, результат считаем неясным; если качество неизменно, модуль может быть полезен
за счёт заметной экономии времени или памяти. Критерии нужно зафиксировать до просмотра закрытых результатов.

## 6. Как не уйти в подгонку под набор

### Разделять механизм и бизнес-правило

Хорошая общая операция: сравнить дату из подтверждённого источника с текущей датой из входной политики,
учесть указанное исключение и вернуть `неизвестно`, если источник отсутствует.
Плохая заплатка: запомнить дату, имя инструмента, номер строки и правильную метку из конкретного примера.

Операторы могут быть написаны вручную. Условия, значения и область применения должны приходить из текущего входа
через поддержанный формат или явно проверенный перевод. Самостоятельно написанный перевод одной политики —
полезный опыт, но ещё не доказательство работы с произвольными политиками.

### Разделять данные до порождения вариантов

1. Существующий `valid.parquet` оставить регрессионным и диагностическим набором. Не использовать его как закрытый тест.
2. Подготовить новые исходные сценарии разных областей, с разными формулировками правил и форматами истории.
   Нужны и естественные диалоги с отдельной проверкой разметки, и контролируемые синтетические случаи.
3. До генерации вариантов сгруппировать диалоги, общие источники и шаблоны правил. Все близкие копии и производные
   одного шаблона держать вместе. Разделение только по `id` недостаточно.
4. Отделить разработку, настройку порогов и закрытый резерв. Некоторые области и семейства правил оставить только для проверки переноса.
5. Разметку спорных случаев проверять отдельно: изменение должно быть существенной ошибкой по задаче, а не просто необычным стилем.
6. Выбранную версию и настройки заморозить до закрытого прогона. После просмотра ошибок этот резерв уже изучен;
   нельзя многократно исправляться по нему и продолжать называть его независимым.

Размер нового набора выбирать по числу независимых групп, редких типов ошибок и ширине интервалов,
а не только по количеству строк. Тысяча переименований десяти диалогов не равна тысяче независимых наблюдений.
Синтетика из одного генератора тоже может иметь характерные подсказки; её результат нельзя автоматически переносить на естественные диалоги.

### Для каждого правила — проверка противоположного случая

| Меняем в сценарии | Что должно произойти |
|---|---|
| Согласованно переименовываем людей, инструменты и идентификаторы | Решение не меняется, если смысл и доступность сохранены |
| Политика теперь разрешает ранее запрещённое действие | Соответствующее нарушение исчезает |
| Добавляем применимое исключение или нужное подтверждение | Запрет не должен срабатывать автоматически |
| Убираем источник критического факта | Неизвестность вместо выдуманного значения или автоматического запрета |
| Подставляем то же значение для другого владельца | Связь происхождения меняется; нарушение зависит от правила владения |
| Меняем порядок подтверждённых событий | Результат меняется только когда порядок значим для условий |
| Добавляем нерелевантный текст, повторённые слова, прежнее ошибочное утверждение агента | Они не становятся независимыми доказательствами |

Переименование проверяет только одну форму устойчивости. Оно не заменяет новые правила, новые области и новые источники.

## 7. Короткий порядок работы

1. Стенд переноса и описание новых независимых сценариев.
2. Небольшой общий исполнитель условий и явные контракты происхождения; без LLM, без обещания покрытия произвольного текста.
3. Когда подключаем модель — сначала простая прямая проверка как обязательная точка сравнения.
4. По одному добавляем графовый контекст, утверждения, смысл правил и новую политику метки. Измеряем вклад каждого.
5. Только после обнаруженной необходимости пробуем RLM, планирование и несколько проверяющих.

Правило остановки: если расширение помогает только на изученном файле, не переносится или не окупает ресурсную стоимость,
его не нужно включать в итоговую архитектуру. Граф — средство проверки, а не цель, которую надо усложнять любой ценой.
