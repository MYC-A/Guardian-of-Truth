## Что работает

- Разбор двух форматов журнала: стрелки `TOOL_CALL/TOOL_RESPONSE` и отдельные маркеры вызовов/результатов.
- Различение системных правил, пользователя, ассистента и результатов инструментов.
- Каталог инструментов только из системного блока; проверка обязательных полей, вложенных объектов, типов и перечислений.
- Журнал структурированных наблюдений с путями к полям и ссылками на исходный текст. Сведения разных событий не сливаются автоматически.
- Граф наблюдений и аргументов: совпадения полей/значений, сопоставление идентификаторов, связи с предыдущими наблюдениями. Индекс массива не считается идентификатором сущности.
- Отдельный интерфейс `SemanticAnalyzer`; по умолчанию `NoSemanticAnalyzer`, без зависимостей от библиотек моделей. Ошибка подключённого модуля не отменяет точные проверки.
- Клиент Groq / локального совместимого сервера: режимы `direct`, `graph`, `rlm`, ограниченное чтение и общий бюджет HTTP-попыток.
- Исполнитель явных декларативных правил из системного блока: даты, сравнения, принадлежность, исключения и неизвестность. Произвольная политика на естественном языке этим исполнителем не разбирается.
- Планировщик явной модели состояния: ограниченный поиск, проверка каталога и аргументов, различение гарантированных в модели и условных исходов. [Границы применимости](docs/planning.md).
- Контур группового сравнения моделей с отдельной калибровкой и фиксацией конфигурации до теста; подготовлен [резерв RAGTruth](docs/external_validation.md).
- Перечень частей ответа, требующих проверки. Текст пока выделяется блоками, а не атомарными утверждениями.
- Ограниченный по длине поиск фрагментов по словам и идентификаторам.
- CSV с `id,label`, дополнительный JSONL с основаниями, неопределённостью и ссылками на источники.
- Раздельная оценка вклада проверки доступности инструментов и проверки аргументов.
- Сравнение с отключённым графом и подсчёт его структурного покрытия. Это не оценка истинности фактов.

Это частичный детектор. Для неразрешённых примеров CSV использует фиксированную метку `0`,
но в отчёте они остаются `unknown` и `used_fallback=true`. Отсутствие обнаруженной ошибки не означает доказанную корректность.
Вероятности пока не вычисляются (`null`). При явном включении модели её сырой `semantic_score` может определять метку
через отдельную политику порога. Это оценка модели, не доказательство и не откалиброванная вероятность.

## Запуск

Из корня проекта:

```powershell
python -m pip install -e ".[data]"
python -m unittest discover -s tests -v
python scripts/predict.py --input valid.parquet --output outputs/predictions.csv --audit outputs/audit.jsonl
python scripts/evaluate.py --input valid.parquet --output outputs/metrics.json
```

CSV и JSONL обрабатываются без дополнительных библиотек. Дополнение `data` нужно для Parquet.
`evaluate.py` читает метки только для подсчёта качества. Интерфейс `Detector.review` принимает ровно два текста;
`id`, `label` и `explanation` в детектор не передаются.

Ссылки на доказательства — полуоткрытые интервалы символов исходного текста:
`prompt[start:end]` либо `response[start:end]`. Это не байты и не номера токенов.
Проверяемые инструкции и вызовы из файла никогда не исполняются.

## Ограничения первой версии

Есть адаптер смысловой модели, но её качество и прирост пока не измерены на рабочем подключении.
Нет проверенного перевода произвольной политики в правила и полноценного восстановления состояния.
Утверждения и планы отказов проверяются как модельные гипотезы, не как формальные доказательства выполнимости.
`SemanticAnalyzer` получает контекст, разобранную историю, граф и перечень проверок.
Его выводы маркируются предположениями, ссылки проверяются на допустимость; `decision.py` отдельно применяет порог к сырой оценке.
Старый `SemanticChecker` поддержан через адаптер. Пример подключения — в [описании второго этапа](docs/stage2_provenance.md#подключение-будущей-модели).
Структурное совпадение аргумента не доказывает ни разрешение операции, ни актуальность значения в реальном мире.
Граф не извлекает смысл из свободного текста и не сопоставляет автоматически `id`, `payment_id`, `payment_method_id`.
Произвольный формат описания инструментов не поддержан: используется объявленная текстовая схема.
Список считается полным только в поддерживаемом формате без обнаруженных признаков обрыва;
это условие разбора, а не гарантия полноты произвольного входа.
Динамическое добавление инструментов прямо в список во время истории пока не моделируется.
Возвращаемые через посредник инструменты требуют отдельного расширения.

Скрипт соответствует опубликованной сигнатуре запуска; готовность к платформе не проверена.
Точная упаковка Docker и условия исполнения на платформе остаются отдельным этапом.
Веса автоматически не скачиваются. При `--backend none` внешних вызовов нет;
`--backend groq` явно включает передачу проверяемого контекста Groq.
